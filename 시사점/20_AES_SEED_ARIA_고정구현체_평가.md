# AES·SEED·ARIA 고정 구현체 평가

## 평가 범위

본 평가는 `sources.lock.json`에 고정한 OpenSSL 3.5.7, Botan 3.12.0,
Crypto++ 8.9.0 및 Mbed TLS 3.6.7의 정확한 커밋을 대상으로 수행한다. 원본
소스, 빌드 산출물 및 실행 드라이버는 `/tmp` 외부 캐시에만 두며 Git 저장소에
포함하지 않는다. 따라서 본 저장소에는 평가 하니스, 공개 벡터, 잠금 정보 및
집계 기록만 유지한다.

기능 평가는 NIST FIPS 197의 AES-128 단일 블록 벡터 1건, RFC 4269의 SEED
벡터 4건 및 RFC 5794의 ARIA-128·192·256 벡터 3건을 사용한다. 이는 선택한
알려진 정답 시험에 대한 구현 일치성을 확인할 뿐이며, 알고리즘 검증 또는
KCMVP 인증을 의미하지 않는다.

## 실행 결과

독립 감사에서는 임의 외부 실행기를 전달하던 최초 하니스의 소스 연결 증적이
불충분함을 확인하였다. 이에 해당 입력 경로를 제거하고, 하니스가 정확한 고정
checkout에서 라이브러리와 드라이버를 직접 빌드하도록 수정하였다. 최종 실행은
checkout 커밋, 컴파일·링크 명령, 드라이버 SHA-256, 실행 바이너리 SHA-256을
함께 기록한다.

| 구현체 | 고정 커밋 | 선언 지원 범위 | 실행 벡터 | 결과 |
|---|---|---|---:|---|
| OpenSSL 3.5.7 | `8cf17aaeb4599f8af87fefd810b5b5fee90fe69e` | AES·SEED·ARIA | 8 | 8/8 통과 |
| Botan 3.12.0 | `45d6f286c320b2f2efd5373d195ec88c367e3071` | AES·SEED·ARIA | 8 | 8/8 통과 |
| Crypto++ 8.9.0 | `843d74c7c97f9e19a615b8ff3c0ca06599ca501b` | AES·SEED·ARIA | 8 | 8/8 통과 |
| Mbed TLS 3.6.7 | `068ff080b369adfac81509f9b57b2afabaf82dc5` | AES·ARIA | 4 | 4/4 통과 |

총 28건의 구현체별 알려진 정답 시험이 모두 통과하였다. 최종 원시 보고서의
SHA-256은 `d8e29e26957f6eec95722103d2ae05e98ac3b6ba1b1bb5d9b3af0518d4fb7551`이다.
Mbed TLS의 `framework` 하위 모듈은 상위 커밋이 고정한 gitlink
`dde0c4a0e448a0552f18817dcea633bb851fd288`과 일치함을 확인하였다. 정적 파일
집계에는 빌드 생성물을 포함하지 않고 `git ls-files`가 반환하는 추적 소스만
사용한다.

Mbed TLS는 고정 잠금 파일에서 SEED 지원 구현체로 분류하지 않으므로 SEED
벡터를 적용하지 않는다. 이를 실패나 미지원 시험 누락과 혼동하지 않는다.

## 정적 규칙 판정 범위

정적 규칙 결과는 파일별로 세 상태를 유지한다. `violation`은 명시적 모순을
검출한 상태이고, `compliant`는 검사기가 구문을 해석하여 명시적 모순을 찾지
못한 상태이며, `unknown`은 파싱 실패, 간접 상수, 어셈블리, 생성 코드,
래퍼 또는 C++ 템플릿 등의 이유로 판정을 보류한 상태이다. 구현체·규칙 단위
집계는 대상 파일 중 하나라도 `unknown`이면 `unknown`으로 유지한다.

| 구현체 | 알고리즘 규칙 | 준수 파일 | 판정 보류 파일 | 위반 파일 | 집계 |
|---|---|---:|---:|---:|---|
| OpenSSL | AES-001/002/003 각각 | 2 | 47 | 0 | unknown |
| OpenSSL | SEED-001 | 2 | 21 | 0 | unknown |
| OpenSSL | ARIA-001 | 0 | 13 | 0 | unknown |
| Botan | AES-001/002/003 각각 | 0 | 19 | 0 | unknown |
| Botan | SEED-001 | 0 | 6 | 0 | unknown |
| Botan | ARIA-001 | 0 | 4 | 0 | unknown |
| Crypto++ | AES-001/002/003 각각 | 1 | 8 | 0 | unknown |
| Crypto++ | SEED-001 | 0 | 3 | 0 | unknown |
| Crypto++ | ARIA-001 | 0 | 3 | 0 | unknown |
| Mbed TLS | AES-001/002/003 각각 | 1 | 8 | 0 | unknown |
| Mbed TLS | ARIA-001 | 0 | 3 | 0 | unknown |

위 결과에서는 명시적 모순 위반을 검출하지 않았으나, 판정 보류 비율이 높기
때문에 네 구현체가 정적 규칙을 완전히 준수한다고 주장할 수 없다. 오히려 현재
고신뢰 규칙이 C의 직접적 상수 구조에 제한되어 있으며, 최적화된 C와 C++에
대한 일반화 범위가 좁다는 사실을 정량적으로 보여준다.

## 빌드 및 라이선스 경계

- OpenSSL 소스의 라이선스 표시는 Apache-2.0이다.
- Botan 소스의 라이선스 표시는 BSD-2-Clause이다.
- Crypto++는 Boost-1.0과 파일별 퍼블릭 도메인 고지를 함께 확인해야 한다.
- Mbed TLS는 Apache-2.0 또는 GPL-2.0-or-later 선택 조건과 파일별 고지를
  확인해야 한다.

본 프로젝트는 이들 구현체의 소스나 바이너리를 재배포하지 않는다. 향후 특정
파일을 복사하거나 배포 산출물에 연결할 경우에는 해당 파일의 고지와 결합 조건을
별도로 검토해야 한다.

## 재현 및 후속 과제

평가 하니스는 `scripts/evaluate_cipher_implementations.py`에 구현하며, 외부의
임의 실행 드라이버를 받지 않고 잠긴 checkout에서 라이브러리와 실행기를 직접
빌드한다. 단위시험은 임의 실행기 옵션이 존재하지 않는지 확인하고, 일부 파일만 판정 가능한 경우 전체 집계를
`unknown`으로 유지하며, 저장소 내부의 vendor 경로를 거부하는지 검증한다.

후속 개선은 C++ 전용 파서 또는 libclang 기반 판정, 컴파일 데이터베이스를
이용한 매크로 전개, 어셈블리·하드웨어 가속 경로의 명시적 제외 보고 순으로
진행한다. 이 개선 전에는 벡터 통과 결과와 정적 규칙 결과를 하나의 준수 지표로
합산하지 않는다.
