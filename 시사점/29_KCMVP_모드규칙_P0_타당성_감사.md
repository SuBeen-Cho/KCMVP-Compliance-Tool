# KCMVP 모드 규칙 P0 타당성 감사

## 1. 감사 범위와 판정 기준

CFB 피드백 길이, CMAC/GMAC 인증값 길이, CTR 카운터 고갈, 패딩 방법을 현재 활성 규칙과 대조한다. 확정 탐지는 코드에 위반을 직접 입증하는 리터럴이 있고 단위와 적용 도메인을 확정할 수 있는 경우로 한정한다. 일반 표준의 허용 범위와 KCMVP 검증대상 프로파일의 제한을 구분한다.

## 2. 원문 근거

- `암호모듈 구현안내서 Part 1(2024.11)` 부속서 C §C.2는 모듈 내부에 구현한 Zero-padding(덧붙이기 방법 1)을 검증대상 동작모드에서 사용할 수 없다고 설명한다. 모듈 외부의 패딩에는 이 제한이 적용되지 않는다.
- 같은 문서 §C.3은 ARIA·SEED·LEA 기반 CMAC, GCM/GMAC, CCM의 축약 인증값을 112비트 이상으로 설정한 경우에만 검증대상으로 사용할 수 있다고 명시한다. HIGHT CMAC은 64비트 full-length 예외이다.
- `암호알고리즘 구현안내서 Part 2(2024.03)` 제2장은 CFB의 피드백 길이 `s`를 입력으로 다룬다. 이는 범용 KCMVP 규칙으로 CFB-128만을 강제할 수 있는 근거가 아님을 의미한다.

## 3. 규칙별 결론

| 후보 | 결론 | 근거와 오탐 통제 |
|---|---|---|
| GCM/GMAC 인증값 길이 | 활성 규칙 `GCM-002`를 KCMVP 14~16바이트 기준으로 수정한다. | `*_bytes`·`*_bits`로 단위가 명시된 상수 대입을 확정 탐지한다. LEA API에서 바이트 단위로 정의된 `tag_len`/`t_len`도 동일하게 처리하되, 임의의 단위 불명 식별자는 판정하지 않는다. |
| CMAC 인증값 길이 | 규칙 추가 후보로 유지한다. | HIGHT 예외와 비트/바이트 단위를 식별하는 도메인 게이트가 필요하다. 실제 음성·양성 코퍼스 없이 현재 추가하면 오탐률을 정량화할 수 없다. |
| CFB 피드백 길이 | 신규 확정 규칙을 추가하지 않는다. | Part 2가 `s`를 입력으로 허용한다. LEA 참조 API의 CFB-128은 특정 구현 인터페이스이며 전역 KCMVP 명령이 아니다. 현재 `CFB-002`는 논문에서 LEA CFB-128 구현 검사로 적용 범위를 한정해야 한다. |
| CTR 카운터 고갈/wrap | 신규 확정 규칙을 추가하지 않는다. | wrap 도달 가능성은 카운터 필드 크기, 초기값, 처리 블록 수, 상태 재사용을 함께 분석해야 한다. 증가문이나 정수 overflow 표현만으로 위반을 확정하면 오탐이 발생한다. |
| Zero-padding | 즉시 확정 규칙보다 후보 탐색과 L3 확인을 우선한다. | `buffer[i] = 0` 패턴은 잔여 버퍼 초기화·SSP 제로화와 구분되지 않는다. 패딩 함수 경계, 블록 길이 계산, 보안정책서 명세, 모듈 내부/외부 경계를 함께 확인해야 한다. |

## 4. 구현 및 검증 범위

`GCM-002`의 기존 4~16바이트 패턴은 LEA 사용 매뉴얼의 API 수용 하한과 KCMVP 검증 프로파일을 혼동하였다. 이를 KCMVP의 14~16바이트 기준으로 수정한다. 12·17바이트와 96비트는 탐지하고 14·16바이트와 112~128비트는 통과하는 회귀 테스트를 추가한다. LEA API의 `tag_len`/`t_len`은 바이트로 해석하고, 모드 앵커가 없는 일반 MAC 파일에는 적용하지 않는다.

## 5. 후속 개발 순서

1. CMAC에 대해 ARIA·SEED·LEA 양성, HIGHT 예외, 단위 불명 음성 fixture를 먼저 구축한다.
2. Zero-padding은 함수 경계와 길이 계산을 추적하는 AST 분석기를 설계하고, 모듈 내부 패딩일 때만 위반 후보로 생성한다.
3. CTR wrap은 카운터 필드 비트 수와 API별 최대 처리량을 결합하는 범위 분석을 구현한 뒤에만 활성한다.
4. 신규 규칙은 합성 정답 표시가 아닌 실제 구현체 음성 사례를 포함하여 규칙별 precision과 unknown 비율을 독립적으로 보고한다.
