# 8단계: 제3자 블라인드 라벨링

## 연구적 위치

AI 에이전트 간 독립 판정은 사전 오류 탐지와 라벨링 프로토콜 예비 검증에 활용한다. 이를 독립적인 인간 전문가 검증으로 대체하여 주장하지 않는다. 논문의 제3자 검증 주장에는 시스템 결과를 보지 않은 독립 인간 전문가의 판정이 추가로 필요하다.

## 폐쇄형 프로토콜

- 라벨러에게 L3 판정, 재판정, confidence, 정답, 채택·제거 상태를 제공하지 않는다.
- 파일명과 함수명을 중립화했음을 패킷 준비자가 명시한다.
- 판정 단위는 고유 `candidate_id`를 가진 occurrence로 정의한다.
- 동일·유사 소스와 파생 사례는 하나의 `group_id`로 묶고, 라벨러에게 제시하는 그룹 순서를 재현 가능하게 무작위화한다.
- 라벨은 `violation`, `non_violation`, `insufficient_context`, `not_applicable`로 제한한다.
- 각 판정에 요구사항 적용 여부, 0–100 정수 확신도, 구체적 증거, 판정 근거, 소스 행 인용을 기록한다.
- 라벨러 ID, 생성 시각, 라벨러 유형, 모델 공급자·이름·버전을 기록하되 인증 정보는 기록하지 않는다.
- 패킷과 라벨 문서는 정규 SHA-256 식별자로 변조 여부를 검증한다.

`backend/scripts/blind_labeling.py`는 패킷 및 라벨 문서를 오프라인에서 검증하고, 다중 분류 Cohen's κ와 라벨별 one-vs-rest κ를 산출하며, 불일치 사례만 포함한 adjudication queue를 생성한다. 양쪽 라벨러는 서로의 판정과 시스템 출력을 보지 않고 독립적으로 판정해야 한다. 불일치 항목은 제3의 인간 전문가가 별도로 재심한다.

합의도와 성능 신뢰구간은 occurrence를 서로 독립인 표본으로 간주하지 않고 `group_id` 단위로 분할·부트스트랩한다. 동일한 sets 5–7을 반복 실행해 얻은 판정은 새로운 독립 표본으로 계수하지 않는다.
