# 블라인드 코퍼스와 독립 라벨링 절차

## 목적

본 절차는 L1 후보에 포함된 정답 암시 단서를 제거하고, 탐지 발생 건별 독립 판정을 가능하게 하는 데 목적이 있다. 저자 또는 모델이 수행한 판정을 독립 라벨로 간주하지 않으며, 멀티 에이전트 판정은 사람 라벨링 이전의 예비 교차 검토로만 취급한다.

## 구현 범위

`backend/experiments/blind_corpus.py`는 동결된 L1 snapshot을 입력으로 사용하여 공개 라벨링 패킷과 비공개 sidecar를 분리 생성한다. 공개 패킷에는 불투명한 후보 식별자, 중립화된 소스 식별자, 행 번호가 포함된 문맥, 규칙 요구사항 및 근거 출처만 포함한다. 시스템 판정, 빈 판정 필드를 포함한 라벨 필드, 기존 정답, L2·RAG 결과 및 L3 결과는 포함하지 않는다. 생성 결과는 `experiments.labeling.build_packet`의 폐쇄형 스키마로 구성하며 `scripts/blind_labeling.py validate-packet` 검증을 통과해야만 배포한다.

파일 경로는 salt 기반의 결정적 식별자로 치환한다. `violations`, `wrong`, `bad`, `no_zeroize`, `expected`, `answer`, `정답`, `위반` 등 정답을 암시할 수 있는 C 식별자도 결정적으로 치환한다. 문자열 리터럴과 문자 리터럴은 프로그램 의미를 바꿀 수 있으므로 수정하지 않는다. 따라서 해당 리터럴이나 보존된 일반 주석에 금지 단서가 남으면 공개 패킷 생성을 실패 처리한다.

정답 주석은 주석 전체를 제거하되 개행 수를 유지한다. `[V1]`과 같은 변이 표식, 판정·판단 메타데이터 및 규칙 ID가 포함된 제목형 주석도 제거한다. 이에 따라 기존 snapshot의 행 번호와 공개 문맥의 행 번호를 대응할 수 있다. 동일 파일·규칙·행에서 복수 후보가 발생하더라도 각 후보는 동결 후보 전체 식별자에서 파생된 별도 불투명 식별자를 갖는다. 동일 규칙과 동일 중립 문맥을 공유하는 후보에는 동일한 중복 군집 식별자를 부여하며, 특히 세트 5~7의 파생 사례를 독립 표본으로 중복 집계하지 않는다.

## 비공개 자료 관리

비공개 sidecar에는 원래 후보 식별자, 원래 파일 경로, 원래 행 번호 및 과거 파일×규칙 단위 정답을 저장한다. 과거 정답은 발생 건 단위 정답이 아니므로 `legacy_file_rule_label`로 명시하며, 독립적인 발생 건 판정이 필요하다는 제한을 함께 기록한다.

도구는 비공개 sidecar가 Git 저장소 내부에 기록되는 것을 거부한다. sidecar는 권한 `0600`으로 원자적으로 기록한다. 공개 패킷과 sidecar에는 동일한 패킷 SHA-256을 기록하여 사후 결합 시 자료 혼동을 방지한다. 익명화 salt 역시 저장소에 커밋하지 않고 환경변수로만 제공한다.

## 실행 절차

다음 예시는 비공개 자료를 `/tmp`에 기록한다. `--gt-zip`은 세트 1부터 세트 7까지 순서대로 지정한다.

```bash
cd backend
export KCMVP_BLIND_SALT='<32자 이상의 무작위 16진수>'
python scripts/build_blind_label_packet.py \
  --snapshot /tmp/kcmvp-frozen-l1.json \
  --public-output /tmp/kcmvp-blind-public.json \
  --private-output /tmp/kcmvp-blind-private.json \
  --gt-zip '<세트 1 ZIP>' \
  --gt-zip '<세트 2 ZIP>' \
  --gt-zip '<세트 3 ZIP>' \
  --gt-zip '<세트 4 ZIP>' \
  --gt-zip '<세트 5 ZIP>' \
  --gt-zip '<세트 6 ZIP>' \
  --gt-zip '<세트 7 ZIP>'
```

## 라벨링 원칙

두 명 이상의 라벨러는 서로의 결과, 기존 정답, 시스템 결과 및 비공개 sidecar를 보지 않고 동일 공개 패킷을 판정한다. 허용 판정은 `violation`, `not_violation`, `insufficient_evidence`이다. 라벨러는 근거 행과 판정 사유를 함께 기록한다. 최초 판정을 보존한 상태에서 일치도와 불일치 목록을 산출한 뒤, 불일치 건만 별도 합의 절차로 확정한다.

멀티 에이전트는 독립 프롬프트와 격리된 패킷을 사용하여 예비 라벨을 생성할 수 있으나, 동일 모델 계열·동일 규칙 설명·동일 데이터에서 발생하는 상관 오류를 배제할 수 없다. 따라서 해당 결과는 사람에 의한 제3자 교차 검증을 대체하지 않으며, 논문에서는 보조 분석으로 구분하여 보고한다.

식별자 치환 후 공개 소스 경로는 항상 불투명 식별자만 사용한다. 이는 현재 L3 prompt가 파일명에 포함된 `violations` 등의 문자열을 판단 단서로 사용할 수 있다는 감사 결과를 반영한다. 후보 payload의 메시지와 snippet은 공개 패킷에 복사하지 않는다.

## 안전성 제한

ZIP 입력은 절대 경로, 상위 경로 이동, 심볼릭 링크 및 10 MiB를 초과하는 소스 항목을 거부한다. 공개 문맥에 금지 단서가 하나라도 남으면 생성 전체를 실패 처리한다. 문자열 의미를 변경하여 단서를 강제로 제거하지 않으므로, 실패 건은 사람이 해당 문자열의 평가 필요성을 검토한 뒤 코퍼스 포함 여부를 결정해야 한다.

현재 치환기는 C 어휘 수준에서 식별자를 일관되게 변경하나, 전처리 결과·컴파일 결과·L1 후보 대응의 동등성을 자동으로 증명하지 않는다. 실제 공개 코퍼스를 확정하기 전에는 원본과 중립본에 대해 전처리·컴파일 검사와 L1 후보 대응 검사를 별도로 수행하고 그 결과를 해시와 함께 보존해야 한다.
