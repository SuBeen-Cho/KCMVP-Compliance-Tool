# 1단계: 실험 기준 코드 및 재현성

## 확인된 문제

- `HEAD`와 `origin/main`은 `c5597ef`로 같지만 핵심 서비스에 미커밋 변경이 존재한다.
- 기존 `.gitignore`는 평가 스크립트, 라벨 및 결과 전체를 제외하여 Git만으로 실험을 재현할 수 없다.
- Python 의존성은 범위 지정 위주이며 lock 파일이 없다.
- `.env.example`의 Gemini/RAG 기본값이 실제 설정과 달랐다.
- libclang 우선 경로가 LEA delta 및 CMAC parameter 검사를 가려 테스트가 실패했다.
- ARIA 저수준 테스트는 존재하지만 YAML 규칙이 없어 제품 수준 ARIA 지원으로 주장할 수 없다.

## 적용한 변경

- libclang LEA-010에 symbol-graph delta 값 검증을 추가했다.
- CMAC-001이 지역 변수뿐 아니라 함수 매개변수 K1/K2도 인식하도록 했다.
- ARIA-001 저수준 구조 checker를 등록했으나 YAML 규칙은 추가하지 않았다.
- 규칙 inventory와 실행 manifest 생성기를 `backend/experiments/`에 추가했다.
- README 지원 범위를 LEA 중심, 160+ YAML 규칙으로 제한했다.
- `.env.example`을 실제 기본 설정과 일치시켰다.

## 주장 경계

- 현재 YAML 규칙은 161개이며 중복 ID는 없다.
- 8개 운영모드 YAML은 존재하지만 LEA 중심 적용 범위이다.
- ARIA/AES/SEED의 제품 수준 지원은 7단계 평가 전까지 주장하지 않는다.
- dirty worktree에서 생성된 과거 결과는 commit만으로 재현할 수 없다. canonical 결과는 manifest와 함께 새로 생성해야 한다.

## 검증 게이트

- 표적 실패 테스트 5개: 통과.
- 전체 테스트와 독립 재검토 결과는 이 문서에 후속 기록한다.
