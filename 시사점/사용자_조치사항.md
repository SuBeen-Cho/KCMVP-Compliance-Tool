# 사용자 조치사항

이 문서는 자동화로 해결할 수 없거나 사용자 권한·판단이 필요한 항목만 누적한다. 완료된 구현·테스트는 다른 단계 문서에 기록한다.

## 현재 필요한 조치

### 1. Gemini API 자격 증명

- 현재 `backend/.env`의 키는 실제 호출에서 `400 API_KEY_INVALID`를 반환한다.
- Google AI Studio 또는 Google Cloud에서 새 키를 발급하고 Gemini API 활성화, 프로젝트 연결, API 제한을 확인해야 한다.
- 키는 채팅이나 Git에 올리지 않고 로컬 `backend/.env`에만 저장해야 한다.

### 2. 외부 독립 라벨러

- 저자 구축 정답 라벨의 독립 검증을 위해 최소 두 명의 blind annotator가 필요하다.
- annotator는 시스템 판정과 상대방의 라벨을 보지 않은 상태에서 후보를 판정해야 한다.
- 가능하면 KCMVP·암호 구현 검토 경험이 있는 인원을 지정해야 한다.

### 3. 논문 저자 및 공개 범위 확인

- `Author Contributions`에서 모든 역할을 `all authors`로 기술해도 되는지 공동저자 전원의 확인이 필요하다.
- 합성 corpus와 sidecar 정답 라벨의 공개 가능 범위를 결정해야 한다.
- 상용 모듈 자료는 재배포 권한을 확인해야 한다.

### 4. AES·SEED 평가 범위 승인

- 고정 후보는 OpenSSL, Botan, Crypto++, Mbed TLS이다.
- 외부 라이브러리는 KCMVP 인증 모듈이 아니므로 일반 구현체 간 탐지 일반화 평가로만 사용한다.
- KISA SEED 배포물은 재배포 조건이 불명확하여 현재 제외하였다. 사용하려면 별도 라이선스 확인이 필요하다.

## 사용자 조치 없이 계속 진행하는 항목

- 논문 변경 추적본의 학술체·용어 교정
- AST 및 규칙 엔진 회귀 검증
- LLM/RAG no-RAG 및 fail-fast 검증
- 평가 runner, manifest, GT 정제 경로 검증
- AES·SEED source lock 및 fetch/checksum 도구 구현
- 백엔드·프런트엔드 전체 테스트
- 변경 단위별 커밋과 GitHub 업데이트
