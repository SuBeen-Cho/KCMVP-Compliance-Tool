# 블라인드 중립화 동등성 게이트 결과

## 목적

블라인드 코퍼스에서 정답 단서를 제거하는 과정이 소스 코드의 의미와 L1 발생건을 변경하지 않는지 검증한다. 본 검증은 누출 감사와 의미 동등성 감사를 구분한다. 누출 감사는 공개 항목에서 정답 필드, 원본 경로, 원본 식별자 및 판정 단서가 제거되었는지를 확인한다. 의미 동등성 감사는 중립화 전후의 토큰, 전처리 결과, 컴파일 가능 상태 및 L1 발생건을 비교한다.

## 구현한 차단 조건

중립화 과정에서는 모든 C/C++ 주석을 제거하되 공백 한 칸과 기존 개행 수를 보존한다. 따라서 `int/* comment */value`가 `intvalue`로 결합되는 문제를 방지한다. 허용된 식별자 치환을 역변환한 뒤 토큰열이 동일해야 한다. 또한 매크로 문자열화와 토큰 결합, `dlsym`·`GetProcAddress` 문자열, 외부 함수 ABI 및 `__func__` 관찰 가능성을 별도의 의미 변경 위험으로 검사한다.

각 번역 단위에 대하여 Clang 전처리 결과와 구문 컴파일 결과를 원본·중립본으로 나누어 실행한다. 원본은 컴파일되지만 중립본이 컴파일되지 않는 경우를 회귀로 판정한다. 양쪽이 모두 실패한 경우에는 통과로 간주하지 않고 불확정으로 집계한다. 현재 동일한 L1 엔진을 원본과 중립본에 각각 적용한 뒤 `(source_id, rule_id, line)` 다중집합을 비교한다.

동등성 보고서는 폐쇄 스키마와 `report_id` SHA-256으로 보호한다. 패킷 생성기는 보고서 해시, 스냅샷 식별자 및 모든 필수 게이트의 참값을 검증한다. 실패한 보고서를 전달하면 공개·비공개 패킷을 생성하지 않는다. 공개 항목 누출 감사도 실제 항목의 정규 직렬화 해시에 결속하므로 자체 선언값만으로 통과할 수 없다.

## 7세트 실행 결과

동결 스냅샷 `27d8ea63cdf5e5a29ae0e1860b2a7c84d6ab045ced1840dee4050b1848511a29`의 193개 소스와 280개 동결 후보를 사용한다. 현재 L1 엔진을 동일 조건으로 재실행한 결과 원본에서 224건, 중립본에서 210건이 탐지되었다.

| 검사 항목 | 결과 |
|---|---:|
| 소스 토큰 불일치 | 0건 |
| 식별자 의미 위험 | 20건 |
| 전처리 결과 불일치 | 30건 |
| 전처리 양쪽 실패 불확정 | 0건 |
| 컴파일 회귀 | 0건 |
| 컴파일 상태의 다른 전이 | 0건 |
| 컴파일 양쪽 실패 불확정 | 13건 |
| L1 누락 발생건 | 20건 |
| L1 추가 발생건 | 6건 |

식별자 의미 위험 20건은 모두 외부 함수 ABI 변경 가능성에 해당한다. L1 누락은 LEA-030 5건, LEA-043 3건, LEA-014 2건, LEA-015 2건, CTR-LEA-006 2건 및 기타 6건으로 구성된다. L1 추가는 COM-002 3건과 COM-003, CTR-001, CBC-001 각 1건으로 구성된다.

보고서 식별자는 `a324049ff9bbf0ad116c04ba858af5598136de31a392363dd62d4cf0fb53c043`이며, 원시 보고서 파일의 SHA-256은 `081b2c45c685b97a5e36e75c397a55d066868bdeeca73b75eb5e68d1ad4a47c9`이다. 원시 보고서는 `/tmp/kcmvp-blind-equivalence-v2.json`에 보관하였으며 Git에는 포함하지 않는다.

## 해석 및 후속 조치

현행 식별자 치환 방식은 의미 동등성 게이트를 통과하지 못한다. 따라서 이 방식으로 새 블라인드 패킷을 발급하거나 추가 AI 라벨링 결과를 논문 성능평가에 사용해서는 안 된다. 실제 실패 보고서를 패킷 생성기에 입력한 결과 생성이 차단되었으며 출력 파일도 생성되지 않았다.

다음 수정에서는 실행 코드 자체의 식별자를 변경하지 않고, 정답을 암시하는 원본 식별자가 포함된 발생건을 제외하거나 의미 보존이 증명된 로컬 식별자에 한해서만 치환해야 한다. 대안으로 코드 토큰을 변경하지 않은 상태에서 라벨러에게 추상 구문 표현과 중립 설명을 제공하는 방식을 비교한다. 수정 후에는 동일한 193개 소스에 대하여 토큰, 전처리, 컴파일 및 L1 발생건 게이트를 모두 재실행한다.

현재 결과는 안전한 실패이다. 기존 AI 파일럿은 탐색적 절차 검증으로만 유지하며 독립적 정답 데이터 또는 최종 성능 수치로 해석하지 않는다.

## 이중 계층 재설계 및 재검증

초기 실패 이후 분석 계층과 표시 계층을 분리한다. 분석 계층은 모든 주석을 공백과 동일 개행 수로 치환하지만 코드 식별자는 변경하지 않는다. `//` 주석 끝의 역슬래시와 개행이 번역 단계에서 결합되는 경우에는 다음 물리 행까지 주석으로 제거한다. L1은 이 정제 분석 계층에서 새로 생성한다. 표시 계층에서만 경로를 익명화하고 정답 단서 식별자를 별칭으로 바꾼다. 단서 식별자가 하나라도 존재하는 소스는 불완전한 매크로·자료 흐름 분석에 의존하지 않고 전체 표시 문맥을 보수적으로 제외한다. 이 경우 라벨러에게 문맥 불충분 상태를 제공하며 의미 동등성을 주장하지 않는다.

기존 엔진에는 `violations_` 파일명에 따라 회전 연산 정규화 여부를 달리하는 분기가 존재하였다. 이는 벤치마크 정답을 암시하는 이름이 검출 동작을 변경하는 구조이므로 제거한다. 회전 표기 정규화는 모든 파일에 동일하게 적용한다. 수정된 엔진과 7개 원본 ZIP으로 새 정제 L1 스냅샷을 생성한 결과 193개 소스에서 273개 후보가 생성되었다. 스냅샷 식별자는 `928da74cb1b9711cabb93909efa55e652e27369d1b63f4081160c241dd3454eb`이며 파일 SHA-256은 `8685cf586371c1a212277a5ebc6a3b0ede3c1ef775ddbbc5287dc071c87f56eb`이다.

동일한 세트 경계를 보존하여 정제 스냅샷을 재실행한 결과 273개 발생건이 모두 재현되었으며 누락과 추가는 각각 0건이다. 토큰 불일치와 전처리 불일치는 각각 0건이고 컴파일 회귀도 0건이다. 다만 독립 번역 단위로 양쪽 모두 컴파일되지 않아 불확정으로 남은 파일은 13개이다. 표시 별칭 때문에 전체 문맥을 제외하는 소스는 6개이다.

추가로 경로와 정답 단서 식별자를 익명화한 반사실 입력에 L1을 적용한다. 이 검사에서 10개 발생건이 누락되고 4개가 추가되었다. 영향 규칙은 CBC-LEA-005, COM-002, COM-003, CTR-LEA-006, LEA-022, LEA-031 및 LEA-043이다. 따라서 정제 L1의 결정론적 재현성은 확인하였으나 검출기의 경로·식별자 앵커 독립성은 아직 확인하지 못하였다. 엄격 보고서는 안전하게 실패한다.

최신 엄격 보고서의 식별자는 `38b7a0ee6d00115d28c8f96060800a8fcbe2374db2049d4ad7eb2037f64f7909`이며 원시 보고서 SHA-256은 `ce5f9161d598c17b7ab07a363abfa8b249bee1e912d71b2b7423dac5af529c55`이다. 이 보고서는 `/tmp/kcmvp-sanitized-strict-report-v6.json`에 보관한다. 잔여 의존성을 제거하거나 정당한 알고리즘 앵커와 정답 단서를 구분하는 정책을 확정하기 전에는 최종 블라인드 패킷을 발급하지 않는다.

## 사전등록 제외 후 엄격 통과 결과

영향을 받은 7개 규칙을 정답에 맞추어 수정하지 않는다. CBC-LEA-005와 CTR-LEA-006은 모드 관련성 판정에 파일명 또는 내용 명명 앵커를 사용한다. COM-002는 민감정보 식별자 이름에 의존한다. COM-003은 시험 벡터와 키 배열의 구분에 파일명 및 식별자 앵커를 사용한다. LEA-022, LEA-031 및 LEA-043은 LEA 구현 관련성을 파일명 또는 심볼 앵커로 판정한다. 공식 요구사항과 코드 구조만으로 동일한 적용 범위를 확정할 수 있을 때까지 이들 규칙을 블라인드 정량평가에서 사전등록 제외한다.

제외 정책은 엄격 보고서의 폐쇄 스키마와 해시에 포함한다. 정제 L1 전체 273건은 보존하되, 공개 라벨 패킷에서는 제외 규칙에 속한 38건을 제거하여 235건을 발급한다. 이 중 단서 식별자를 포함하여 표시 의미를 보장할 수 없는 58건은 코드를 공개하지 않고 문맥 불충분 표시로 전환한다.

최종 엄격 보고서는 통과한다. 정제 L1 재실행은 273건 대 273건으로 누락과 추가가 없고, 토큰 및 전처리 불일치와 컴파일 회귀도 없다. 완전 익명 반사실 입력에서 발생한 10건 누락과 4건 추가는 모두 사전등록 제외 규칙에 한정되며 제외되지 않은 영향 규칙은 0개이다. 보고서 원시 SHA-256은 `ab41be1aebdf698ff581fe1bf94981365cf446eddbf4cd6d1cd68bcd166fe5a8`이다.

최종 공개 패킷은 235건이며 패킷 식별자는 `51d64f4fb2be731377b63859b2763a65a70f88848e97538a06948cc150a30bed`이다. 공개 패킷 SHA-256은 `5c05039a2c7881b0108f6d493afcf4eca05d815d65742da831a4387a959c59dc`이다. 비공개 사이드카 권한은 `0600`으로 확인한다. 이 결과에서 7개 제외 규칙의 성능을 주장해서는 안 되며, 235건 가운데 표시 문맥을 제공한 발생건과 문맥 불충분 발생건을 구분하여 보고해야 한다.
