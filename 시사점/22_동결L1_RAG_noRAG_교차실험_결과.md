# 동일 L1 후보 기반 RAG/no-RAG 교차 실험 결과

## 실험 계약

본 실험은 clean commit `d83290fc177a1215709f8fad55380bb455c995a7`에서
생성한 하나의 불변 L1 snapshot을 RAG와 no-RAG 조건에 공통으로
적용한다. snapshot은 정제 소스 193개와 L1 후보 280개를 포함하며,
L3 선택기는 모든 조건에서 동일한 161개를 동일 순서로 선택하였다.

- snapshot ID: `27d8ea63cdf5e5a29ae0e1860b2a7c84d6ab045ced1840dee4050b1848511a29`
- snapshot SHA-256: `51441d147fbb2bba4cdc04724775e4d6ee1e7b6e45404f8bc1906dcd78e0a3d0`
- 실행 설계: Pair 1 RAG→no-RAG, Pair 2 no-RAG→RAG, Pair 3 RAG→no-RAG
- pair seed: 42, 43, 44
- 모델: `gemini-2.5-flash-lite`, temperature 0, provider fallback 금지

각 조건은 새 프로세스에서 실행하며, 다른 ablation 플래그를 명시적으로
비활성화한다. API 키, prompt 원문, response 원문은 원장에 저장하지
않으며, 후보·prompt·response 해시와 토큰 수만 저장한다.

## 무결성 검증

독립 감사에서 snapshot, 6개 result, 6개 request ledger의 해시와 내부
run ID·snapshot ID·record count를 모두 재계산하였으며 일치하였다. 모든
실행의 후보 280개와 선택 후보 161개는 순서까지 일치하였다.
산출물에서 API 키 패턴과 로컬 작업공간 절대경로는 발견되지 않았다.

## label-free 조건 결과

| 조건 | 반복 | 선택 | 유지 | 제거 | 미해결 | 요청 기록 |
|---|---:|---:|---:|---:|---:|---:|
| RAG | 3 | 161×3 | 140×3 | 8×3 | 13×3 | 172×3 |
| no-RAG | 3 | 161×3 | 144×3 | 6×3 | 11×3 | 166×3 |

각 조건의 3회 결과는 candidate disposition과 prompt/response hash까지
일치하였다. 따라서 관찰된 순서 효과는 0이지만, 반복 분산 또한
0이므로 이 3회를 독립 확률표본으로 계산하지 않는다.

RAG와 no-RAG의 상태가 다른 후보는 161개 중 12개이다. 상태 전이는
다음과 같다.

| RAG 상태 → no-RAG 상태 | 후보 수 |
|---|---:|
| 유지 → 유지 | 136 |
| 미해결 → 미해결 | 10 |
| 제거 → 제거 | 3 |
| 제거 → 유지 | 5 |
| 유지 → 제거 | 3 |
| 미해결 → 유지 | 3 |
| 유지 → 미해결 | 1 |

즉, RAG는 no-RAG보다 순제거 수가 2개 많지만, 두 조건의 제거
교집은 서로 다르다. RAG 전용 제거는 5개, no-RAG 전용 제거는 3개,
공통 제거는 3개이다. 따라서 단순 제거 수 차이를 품질 향상으로
해석하지 않는다.

## 타당성 한계

1. 입력에서 대괄호형 정답 주석은 제거하였으나 `violations_*.c`,
   `wrong_*`, `no_zeroize` 등의 정답 단서가 파일명과 식별자에 남아 있다.
2. 정답은 저자 구축 `파일×규칙` 단위이며 occurrence 단위 독립 라벨이
   아니다.
3. 161개 선택 후보 중 최초 점수가 있는 고유 후보는 151개이며, 재판정은
   최초 점수 70인 고유 후보 5개에만 적용되었다.
4. confidence는 prompt 계약에 따른 위반 신뢰도 대리점수이며 보정된
   `violation_probability`가 아니다.

따라서 현재 결과로는 RAG가 동일 후보의 판정 구성을 변경한다는 점과
토큰 비용 차이만 보고한다. 정밀도·재현율·F1 향상, RAG의 독립적
정확도 기여 또는 65~74 threshold의 최적성은 주장하지 않는다.

## 후속 게이트

1. 위반을 암시하는 파일명·함수명·주석을 중립적 식별자로 변환한 별도
   blind corpus를 생성한다.
2. occurrence 단위 정답을 시스템 출력을 보지 않은 제3자가 라벨링하고
   일치도와 adjudication 이력을 보존한다.
3. 후보 단위 paired McNemar 검정과 family bootstrap 신뢰구간을 보고한다.
4. threshold는 개발 세트에서만 선택하고 고정한 뒤, 보류 세트에서 단 한
   번 평가한다.
5. 원시 `manifest.json`의 조건 집계 변수 덮어쓰기는 commit `5ba3f56`에서
   수정하였다. 원시 실행 산출물은 변경하지 않고, 본 문서의 조건 합계는
   실행별 원시 값을 독립적으로 재계산한 결과이다.
