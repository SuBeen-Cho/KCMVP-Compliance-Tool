# 동결 L1 사후 라벨 결합과 threshold calibration 가능성 감사

## 결론

3회의 RAG/no-RAG 교차 실험 종료 후 저자 구축 정답을 후처리로 결합할 수 있음을 확인한다. 다만 현재 점수는 보정된 `violation_probability`가 아니며, 재판정 점수도 일부 후보에만 존재한다. 따라서 현재 자료를 `calibrate_threshold.py`에 입력하는 것은 스키마를 인위적으로 만족시키는 행위이며 과학적으로 타당하지 않다. 보정 실행을 중단하고 사후 결합 범위와 차단 사유를 기록한다.

이 결론은 제3자 라벨에 대한 검증이 아니다. 원본 ZIP 내의 저자 작성 정답 주석을 사후에 파싱한 결과이므로, 논문에서는 반드시 “저자 구축 정답”으로 표기한다.

## 감사 대상과 무결성

- 동결 L1 snapshot: Git 외부 실험 산출물 `kcmvp-frozen-l1-d83290f.json`
- snapshot SHA-256: `51441d147fbb2bba4cdc04724775e4d6ee1e7b6e45404f8bc1906dcd78e0a3d0`
- snapshot ID: `27d8ea63cdf5e5a29ae0e1860b2a7c84d6ab045ced1840dee4050b1848511a29`
- 교차 실험 manifest: Git 외부 실험 산출물 `kcmvp-paired-d83290f/manifest.json`
- manifest SHA-256: `91f5932d77ad73bb45e5bbba1f36b1126bb103104993639608adbe7fea4362cd`
- 조건별 실행: RAG 3회, no-RAG 3회로 총 6회를 감사한다.

manifest에 기록된 snapshot 파일 해시와 실제 파일 해시가 일치한다. 각 result 파일의 SHA-256도 manifest의 실행별 `result_sha256`와 일치한다. 원시 snapshot, result, ledger, ZIP은 수정하지 않았다.

## 정답 사후 결합 방법

1. L3 실험은 정답 주석이 제거된 snapshot만 입력으로 사용한다.
2. 실험이 종료된 후에만 원본 7개 ZIP에서 `[\uC704\uBC18: RULE-ID]` 주석을 파싱한다.
3. candidate ID의 `set-N/source_id/rule_id`를 이용해 정답과 결합한다. `src/`는 기존 평가기의 stable source identity 규칙에 따라 정규화한다.
4. 조건과 반복은 occurrence로 유지하되, 같은 candidate family는 개발/held-out 분할에서 같은 그룹으로 유지한다.

이 순서는 정답이 L3 요청에 유입되는 정보 누출을 방지한다. 다만 정답은 후보 행이 아닌 `파일×규칙` 단위로 중복 제거되어 있다. 한 파일에서 동일 규칙이 여러 행을 탐지하면 모든 후보를 양성으로 부여하게 된다. 단일 조건에서 동일 `파일×규칙`에 둘 이상의 후보가 존재하는 그룹은 23개이다. 따라서 현재 결합은 occurrence-level 정답이라고 간주하지 않으며, 일차 탐색 분석에만 사용한다.

## 결합 가능 범위

| 항목 | 결과 |
|---|---:|
| snapshot L1 후보 | 280 |
| 총 L3 판단 레코드 | 894 |
| 판단 점수가 있는 고유 candidate ID | 151 |
| 사후 결합된 양성 행 | 663 |
| 사후 결합된 음성 행 | 231 |
| 재판정이 적용된 행 | 27 |
| 재판정이 적용된 고유 candidate ID | 5 |
| candidate×condition 기준 재판정 결과 | 9 |

RAG은 반복당 148개, no-RAG은 반복당 150개의 판단 레코드를 생성한다. 3회 반복에서 조건별 `l3_decision_records` 해시는 각각 동일하다. 즉, 반복 행은 독립표본이 아니며 표본 수를 894개로 간주하여 불확실성을 축소하지 않는다. 조건별 고유 후보 또는 후보 family를 통계 단위로 사용해야 한다.

## 점수 및 재판정 coverage

- 894개 판단 레코드의 `score_provenance`는 모두 `prompt_contract_confidence_proxy_not_calibrated_probability`이다.
- 최초 점수는 0, 10, 30, 70, 75, 80, 85, 90, 95, 100에만 분포한다.
- 재판정 27개는 모두 최초 점수가 70이다.
- 재판정 점수는 20, 75, 85, 90, 95에만 분포한다.
- 다른 최초 점수를 포함하는 대안 window에는 대응하는 재판정 출력이 없다.

따라서 65~74 window에 대한 후처리 성능은 기술적으로 계산할 수 있지만, 이 window를 다른 window와 공정하게 비교하여 선택할 수는 없다. 또한 점수 의미가 위반 확률이 아니므로 Brier score와 ECE를 산출하지 않는다.

## 보정 실행 차단 사유

1. **점수 의미 불일치**: 현재 confidence는 보정된 위반 확률이 아니다. 엄격한 calibration schema의 `violation_probability`로 이름만 변경하면 안 된다.
2. **재판정 결측**: 현재 window 밖 후보의 counterfactual 재판정 출력이 없어 window sweep이 불가능하다.
3. **정답 해상도**: 저자 정답이 `파일×규칙` 단위이므로 복수 행 후보의 occurrence-level 정답을 구분하지 못한다.
4. **독립성 부족**: 정답은 저자가 구축했으며, 조건별 3회 출력도 완전히 동일하여 독립 반복으로 불확실성을 추정할 수 없다.
5. **선택 coverage**: 280개 L1 후보 전체가 아닌 151개 고유 후보에만 최초 점수가 있다. 선택되지 않은 후보를 임의 점수로 채우지 않는다.

## 타당한 후속 실험

1. L3 프롬프트가 verdict 자신감이 아닌 일관된 `violation_probability` 정의를 출력하도록 계약을 개정한다.
2. calibration에 사용할 사전 정의 window grid의 합집합에 포함되는 모든 후보에 대해 재판정을 수행하거나, 최초 판정과 독립적인 재판정 점수를 전체 후보에 대해 저장한다.
3. 정답을 line/occurrence 단위로 재라벨링하고, 가능하면 제3자 교차 검증과 일치도를 보고한다.
4. 동일 candidate family를 하나의 그룹으로 묶어 개발/held-out 누출을 방지한다.
5. 개발 세트에서만 threshold/window를 선택하고, 고정된 정책을 held-out 세트에서 단 한 번 평가한다.
6. 후보 family 단위 bootstrap으로 불확실성 구간을 산출하되, 완전히 동일한 반복 행을 독립표본으로 세지 않는다.

## 논문 반영 가이드

현재 단계에서는 “65~74를 보정했다” 또는 “최적 threshold를 확인했다”라고 기술하지 않는다. 대신 “현재 65~74 구간은 heuristic이며, 저자 구축 정답의 해상도와 점수 의미 및 counterfactual 재판정 coverage의 제약으로 인해 현재 자료에서 후처리 보정을 수행하지 않았다”고 기술한다.
