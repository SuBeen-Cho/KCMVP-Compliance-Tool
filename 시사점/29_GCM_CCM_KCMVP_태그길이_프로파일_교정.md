# GCM·CCM KCMVP 인증값 길이 프로파일 교정

## 1. 검토 목적

활성 룰셋의 `GCM-002`와 `CCM-003`이 일반 국제표준의 허용 범위와 KCMVP 검증대상 프로파일을 혼동하는지 검토한다. 기존 합성 정답 데이터에 맞추지 않고 공식 원문을 우선하여 교정한다.

## 2. 원문 확인

국가보안기술연구소가 2024년 3월 발간한 『암호알고리즘 구현안내서 Part 2』의 해당 쪽을 PDF 원문에서 직접 확인한다.

- p.27은 GCM 암호화 입력의 인증값 길이 `Tlen`을 112~128비트로 명시한다.
- p.29은 GCM 복호화 입력 인증값 `T`의 길이를 112~128비트로 명시한다.
- p.33은 CCM formatting에서 인증값 바이트 길이 `t`를 별도 파라미터로 정의한다.
- p.34은 CCM 암호화의 인증값 바이트 길이 `Tlen`을 14 또는 16바이트로 제한한다.
- p.35는 CCM 복호화 입력으로 `Tlen`을 정의하며, p.36은 복호화에서도 14 또는 16바이트 제한을 명시한다.

따라서 기존 `GCM-002`의 4~16바이트 허용과 `CCM-003`의 4/6/8/10/12/14/16바이트 허용은 KCMVP 프로파일을 대표하지 못한다. 해당 범위는 일반 표준·API 호환성 범위와 분리하여 관리해야 한다.

## 3. 구현 내용

1. `GCM-002`의 KCMVP 정상 범위를 비트 단위 112~128, 바이트 단위 14~16으로 교정한다.
2. `CCM-003`의 KCMVP 정상 집합을 112/128비트 또는 14/16바이트로 교정한다.
3. `compliance_profile`, `value_unit_policy`, `generic_standard_profile` 메타데이터를 추가하여 판정 단위와 프로파일을 명시한다.
4. `*_bits`는 비트, `*_bytes`는 바이트로 판독하며, LEA C API의 `tag_len`/`t_len`은 바이트로 판독하는 선형 의미 스캐너를 구현한다.
5. 용도와 단위가 확정되지 않은 일반 숫자 상수는 검출하지 않아 오탐을 제어한다.
6. L3 프롬프트와 RAG 매핑을 동일한 KCMVP 프로파일로 교정한다.

## 4. 검증 결과

- 바이트·비트 경계값, 일반 표준에서만 허용되는 축약 태그, 단위 미명시 LEA API, 무관 숫자 상수를 포함한 전용 회귀 시험 30건이 모두 통과한다.
- 룰 엔진·provenance 관련 시험을 포함한 선별 시험 76건이 모두 통과한다.
- 정상 구현 fixture는 C11 구문 검사를 통과하며, `GCM-002`와 `CCM-003`에서 위반 후보를 생성하지 않는다.
- YAML 룰 메타데이터와 JSON 매핑의 파싱이 정상적으로 완료된다.

## 5. 해석 한계와 추가 개발 방향

현재 스캐너는 숫자 리터럴 대입을 우선 판정한다. 매크로, enum, 함수 인자, 구조체 필드, 외부 설정 값을 통해 태그 길이가 전달되는 경우에는 추가적인 상수 전파와 호출 그래프 분석이 필요하다. 다음 단계에서는 해당 경로를 보수적 `unresolved`로 분리하고, 단위가 입증된 경우에만 정적 확정 판정을 생성해야 한다.
