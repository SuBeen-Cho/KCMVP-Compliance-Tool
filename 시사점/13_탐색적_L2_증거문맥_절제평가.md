# 탐색적 L2 증거 문맥 절제 평가

## 판정

2026년 8월 11일의 matched-input 단일 실행 절제 평가는 L2의 독립적 성능 향상을 입증하지 못한다. RAG 조건은 no-RAG 조건보다 저자 정답 라벨에 없는 추가 탐지가 3건 적었으나 정답 라벨과 일치하는 탐지도 2건 적었으며, F1 차이는 0.000186에 불과하다. 반복 및 실행 순서 교차를 수행한 paired inference가 아니므로 해당 결과는 탐색적 관찰로만 사용하며 논문의 확정 성능표에는 반영하지 않는다.

## 실행 조건

- 저장소 커밋: `91cf6c4682d05a99f56710c97ba422ed0e22ce87`
- 실행 상태: clean worktree, 실행 전후 코드·입력·환경·모델 identity 일치
- 데이터: 저자가 구축하고 라벨링한 LEA 코드 세트 7개, 정답 라벨 128건
- 입력 정제: 분석 트리에서 정답 주석을 물리적으로 제거한다.
- 모델: 기존 설정인 `gemini-2.5-flash-lite`를 사용한다.
- RAG 조건: Chroma 벡터 검색이 아니라 direct mapping과 TF-IDF fallback을 사용한다.
- 원시 결과: Git 외부에 보관하고, 공개 요약에는 SHA-256만 기록한다.

## 집계 단위 주의

L3 제거 이벤트와 최종 성능 지표의 단위가 서로 다르다. 제거 이벤트는 개별 탐지 occurrence를 세지만 TP·FP_extra·FN은 `파일::규칙` 고유 후보를 센다. RAG 실행은 제거 이벤트 9건이며 이 가운데 최종 집합에서 소멸한 `파일::규칙` 후보는 8건이다. 해당 후보는 저자 라벨에 없는 추가 탐지 5건과 라벨 일치 탐지 3건으로 구성된다. no-RAG 실행은 제거 이벤트 6건이며 이 가운데 최종 집합에서 소멸한 후보는 3건이다. 해당 후보는 저자 라벨에 없는 추가 탐지 2건과 라벨 일치 탐지 1건으로 구성된다. 따라서 제거 이벤트 수를 FN 증가량으로 직접 해석하지 않는다.

## 해석 한계

- 조건별로 한 번만 순차 실행했으므로 반복 paired 실험이 아니다.
- 실행 순서를 무작위화하거나 AB/BA로 교차하지 않았다.
- 원격 모델은 temperature 0 및 seed 42에서도 완전한 결정성을 보장하지 않는다.
- RAG 조건의 호출 및 토큰 수가 더 많지만 실행시간은 더 짧으므로 시간 차이는 API 지연 변동으로 해석한다.
- 본 비교는 L2를 독립 분류기로 평가하지 않는다. L3 프롬프트에 검색 증거 문맥을 추가하는 조건부 효과만 비교한다.
- 정답 라벨은 독립 제3자 검증을 거치지 않았다.

## 다음 검증 게이트

1. L1 후보를 한 번 생성하여 고유 후보 ID·순서와 입력 조각을 동결한다.
2. 두 조건에 동일한 동결 후보를 공급하고 후보별 프롬프트 및 증거 문맥 해시를 저장한다.
3. 고유 후보 단위와 occurrence 단위 지표를 분리하여 기록한다.
4. 조건별 초기 반복 목표를 10회 이상으로 설정하고 실행 순서를 무작위화하거나 교차하며, 이후 관측 분산과 사전등록한 검정력 기준에 따라 반복 수를 확대한다.
5. 세트 단위 paired bootstrap 신뢰구간과 정답 후보에 대한 exact McNemar 검정을 수행한다.
6. 독립 라벨링이 완료된 후에만 논문 성능 주장으로 승격한다.
