# 3단계: 수치·산정 방식 교정

## 확인 결과

- 과거 원고의 `7 / 14.5 KLOC = 0.58`은 산술적으로 틀리다. 올바른 값은 약 `0.48`이다.
- 압축 파일을 다시 센 결과, C 파일만의 물리 LOC는 11,983줄(약 12.0 KLOC), C와 헤더를 합치면 14,511줄(약 14.5 KLOC)이었다.
- 따라서 `0.58`은 7건을 C-only 12.0 KLOC로 나눌 때에만 근사적으로 성립한다. 파일 수와 LOC 범위를 섞으면 안 된다.
- legacy JSON의 현 값은 9건/12.0 KLOC=0.75로 과거 원고의 7건과도 일치하지 않는다.

## 조치

- 현재 원고에서는 독립 라벨이 없는 blind candidate 빈도를 성능 지표로 사용하지 않는다.
- 128/128, precision 77.6%, F1 87.4%, 9/46=19.6%의 산술 자체는 맞지만, immutable manifest가 없는 `legacy_unverified` 결과로 명시한다.
- 새 canonical 실행 전에는 현재 161개 규칙 snapshot과 legacy 성능을 같은 버전의 결과처럼 결합하지 않는다.

## 검증 기준

- 모든 비율은 분자·분모·분석 대상 파일 확장자·LOC 정의를 함께 기록한다.
- 논문 표는 code, document, traceability의 실행 단위를 분리한다.
