# LEA 53개 규칙 규범근거 전수감사

## 감사 정책

활성 LEA 규칙 53개를 LEA 규격서, 검증시스템, 소스코드 사용 매뉴얼, 설계 논문과 대조한다. TTA LEA 규격서는 `normative_standard`, KISA 검증시스템은 `normative_test_interface`, 소스 매뉴얼은 `reference_implementation_manual`, 설계 논문은 `research_reference`로 분리한다. 숫자·수학식·배열 배치·인덱싱 주장 전체를 규범 원문이 직접 함의하는 경우만 verified로 승격한다.

## 유지 결과

- 29개는 규격서에 관련 수식이 있으나 현재 detector가 동치 표현, wrapper, 상수 전파, project boundary를 충분히 다루지 못하므로 `review_required_detector_scope`로 유지한다.
- 7개는 논문 최적화, 일반 암호모듈 요구, 부채널 안전성 추론을 LEA 알고리즘 규범과 분리하기 위해 유지한다.
- 8개는 검증 하네스·참조값·MCT/MMT/KAT 산출물 적용성을 occurrence 단위로 확인해야 하므로 유지한다.

`backend/mapping/lea_rule_claim_audit.json`은 상기 네 그룹에 53개 활성 ID가 중복 없이 정확히 한 번씩 들어가는지 테스한다. 규격 원문이 있다는 사실과 현재 L1 detector의 정확성을 분리하기 위함이다.

## 독립 완전성 공격감사

승격된 8개를 다시 원문 unit 단위로 검토한 결과 규칙 주장의 과승격이나 설계 논문·참조 매뉴얼의 혼입은 없다. 다만 LEA-001/002/003은 표 행만 제공해 `Nb/Nk/Nr`의 의미가 bundle 내에서 소실되었고, LEA-021/022는 입력·출력·반복 범위 문맥이 빠져 있었으며, LEA-023은 절 제목과 수식 중간 unit이 누락됐다. 이를 각각 p.11 b3~b10, p.14 b24~b35, p.15 b41~b55, p.17 b18~b28의 자립형 묶음으로 보강했다. LEA-005와 LEA-011도 모든 unit에 page/block locator를 명시했다.

중복 사용은 p.11 규격 표를 블록 길이, 키 길이, 라운드 수 열에 각각 적용한 LEA-001/002/003에만 존재하며 최대 재사용은 3회이다. 이는 동일 표의 서로 다른 열을 근거로 사용하는 합리적 재사용이다. 이 8개의 authority는 모두 `normative_standard` 및 `LEA_DATASHEET_KO`로 고정되며, 일반 L1 detector는 여전히 동치 표현·wrapper·상수 전파로 인한 불확실성을 가지므로 결정적 L3 우회 대상으로 확대하지 않는다. 규격서의 `effective_date` 미기재도 현재 인용 검증기에서 보수적 판정 제거를 차단한다.

최종 registry는 활성 166개 중 verified 50개, `review_required` 109개, unmapped 7개를 유지한다. 추가된 완전성·authority·재사용 회귀를 포함한 focused test 26건과 전체 backend test 541건(540 passed, 1 skipped)이 통과한다.
