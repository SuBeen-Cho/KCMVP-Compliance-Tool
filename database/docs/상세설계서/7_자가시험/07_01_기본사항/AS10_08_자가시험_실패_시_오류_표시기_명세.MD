# [AS10.08] 자가시험 실패 시, 표시기를 통한 오류 표시 명세

## 1. 보안요구사항 개요
자가시험이 실패할 경우, 실패한 시험의 종류와 원인을 사용자가 명확히 식별할 수 있도록 오류 상태와 이를 알리는 오류 표시기(Status Indicator) 간의 매핑 관계를 명세해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE10.08.01**: 각 자가시험에 따른 오류 상태 명세와 오류 표시기 명세

## 3. 작성 예시 (Examples)

### 3.1. 오류 상태 및 표시기 정의
"KISACrypto V1.0은 소프트웨어 암호모듈로서 논리적인 상태 코드(Return Value)를 통해 오류 표시기 기능을 수행한다. 자가시험 실패 시 반환되는 상태 코드는 설계서 및 시험서에 명세된 오류 코드와 1:1로 일치한다."

| 자가시험 종류 | 실패 조건 | 오류 표시기 (상태 코드) |
| :--- | :--- | :--- |
| **동작 전 무결성 시험** | 바이너리 무결성 훼손 | `KISA_PreSelfTest_Integrity_Fail` |
| **블록암호 KAT** | LEA/SEED 알고리즘 오류 | `KISA_PreSelfTest_BlockCipher_Fail` |
| **키쌍 일치 시험** | RSA/DH 키쌍 생성 오류 | `KISA_CondTest_PairKey_Fail` |
| **건전성 시험** | 엔트로피 수집 기준 미달 | `KISA_CondTest_DRBG_Health_Fail` |

### 3.2. 표시기 출력 메커니즘
- **반환값 활용**: 각 자가시험 API는 연산 종료 시 `int` 형태의 상태 값을 호출자(Application)에게 반환함.
- **로그 및 표시**: 응용 프로그램은 반환된 상태 코드를 확인하여 사용자 인터페이스(UI)나 시스템 로그를 통해 자가시험의 실패 여부와 구체적인 오류 종류를 표시함.

## 4. 구조도 및 시각 자료 (Visuals)
> **알림**: 본 항목은 오류 코드와 상태 표시 간의 정합성에 집중함.
> **논리 흐름**: [자가시험 실패] → [해당 오류 코드 식별] → [상태 표시기(Return Code) 세팅] → [모듈 인터페이스를 통해 외부로 출력] → [사용자/운영자 인지]

## 5. 해설 및 증빙 가이드 (Guide)
- **AS10.07과의 연동**: 본 항목은 자가시험 실패 시의 처리 절차를 다루는 AS10.07과 통합하여 기술할 수 있음. 핵심은 설계서에 명세된 오류 코드와 실제 모듈이 반환하는 값이 일치함을 증빙하는 것임.
- **표시기의 형태**: 소프트웨어 모듈은 하드웨어 LED와 같은 물리적 표시기가 없으므로, API의 반환값이나 전역 상태 변수(Global State Variable)가 표시기 역할을 수행함을 논리적으로 설명해야 함.
- **일치 여부 검증**: 실제 자가시험 실패 상황을 시뮬레이션했을 때, 모듈로부터 반환되는 상태 코드가 설계서의 정의와 일치하는지 암호모듈 시험서(ATE)를 통해 최종 확인이 필요함.
