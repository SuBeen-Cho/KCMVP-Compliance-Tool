# [AS10.09] 오류 상태 시, 암호연산 및 제어/데이터 출력 금지

## 1. 보안요구사항 개요
암호모듈이 오류 상태(심각한 오류 또는 단순한 오류)에 진입한 경우, 인가되지 않은 암호연산 수행을 방지하고 제어 및 데이터 출력 인터페이스를 통한 정보 유출을 차단하기 위한 메커니즘을 명세해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE10.09.01**: 오류 상태 시, 암호연산, 제어 출력 및 데이터 출력 인터페이스를 통한 출력 금지 방법 명세

## 3. 작성 예시 (Examples)

### 3.1. 오류 상태의 분류 및 관리
"KISACrypto V1.0은 발생 원인 및 심각도에 따라 오류 상태를 다음과 같이 구분하여 관리한다."

- **단순한 오류 (Simple Error)**: 사용자 입력 오류나 서비스 사용 실수로 발생하며, 상태 코드 출력 후 정상 동작 모드로 자동 복귀함.
- **심각한 오류 (Serious Error)**: 자가시험(무결성, KAT 등) 실패 시 발생하며, 모듈의 재시작 또는 재설치 전까지는 암호 서비스를 제공할 수 없는 고정된 오류 상태를 유지함.

### 3.2. 데이터 및 제어 출력 차단 메커니즘
- **상태 체크 로직**: 모든 암호 서비스 API(예: `KISA_LEA_Encrypt`)는 실행 최우선 단계에서 모듈의 전역 상태 변수(`g_module_state`)를 체크함.
- **출력 금지 절차**: 
    1. 전역 상태가 `STATE_ERROR`인 경우, 실제 암호 연산 로직으로 진입하지 않고 즉시 종료함.
    2. 데이터 출력 인터페이스(Buffer)로 어떠한 중간값이나 결과값도 기록하지 않음.
    3. 오직 사전에 정의된 **오류 코드(Status Indicator)**만을 반환함.
- **연산 중 오류 발생 시**: 암호 서비스 수행 중 예기치 못한 오류 발생 시, 즉시 내부 임시 데이터를 **제로화(Zeroization)**한 후 연산을 중단하고 오류 코드를 출력함.

## 4. 구조도 및 시각 자료 (Visuals)
> **알림**: 본 항목은 전역 상태 제어 및 API 진입 통제 로직에 집중함.
> **논리 흐름**: [API 호출] → [전역 상태(STATE) 확인] → {정상: 연산 수행 / 오류: 즉시 반환} → [데이터 출력 차단] → [오류 코드 반환]

## 5. 해설 및 증빙 가이드 (Guide)
- **인터페이스 섹션과의 연계**: 본 항목은 AS03(인터페이스) 섹션의 데이터/제어 출력 차단 요건과 밀밀하게 연결되므로, 두 섹션의 설명이 상호 모순되지 않도록 정합성을 유지해야 함.
- **가용성보다 보안성**: KCMVP 심사에서는 '심각한 오류' 발생 시 모듈이 스스로를 봉쇄(Lock-down)하는지를 중요하게 봄. 따라서 단순히 오류를 알리는 것을 넘어, 실제 연산 코드가 실행되지 않음을 소스코드 레벨(예: API 진입점의 `if`문)에서 증빙하는 것이 효과적임.
- **LEA 및 PQC 알고리즘 적용**: 수빈님이 구현 중인 LEA나 양자 내성 암호(PQC) 모듈에서도 각 알고리즘 API 시작 부분에 이 상태 체크 로직이 포함되어 있음을 설계서에 명시할 것.
