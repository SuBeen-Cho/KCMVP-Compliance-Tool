# [AS10.10] 자가시험 오류 시, 암호 서비스 제한 명세

## 1. 보안요구사항 개요
동작 전 자가시험 또는 조건부 자가시험에서 오류가 발생했을 때, 해당 오류가 해결(재구동 또는 재설치)되기 전까지 암호모듈이 어떠한 암호 서비스도 제공하지 않도록 제한하는 구체적인 방법을 명세해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE10.10.01**: 자가시험 오류가 해결되기 전, 암호 서비스를 제한하는 방법 명세

## 3. 작성 예시 (Examples)

### 3.1. 상태 변수를 활용한 서비스 통제 메커니즘
"KISACrypto V1.0은 암호모듈의 현재 상태를 저장하고 관리하기 위한 전역 내부 변수(`g_module_status`)를 유지한다. 이 변수는 오직 자가시험 결과 또는 서비스 연산 결과에 의해서만 변경된다."

- **상태 전이**: 자가시험(동작 전 무결성 시험, 알고리즘 KAT 등) 실패 시, 내부 상태 변수를 즉시 '심각한 오류(STATE_CRITICAL_ERROR)' 상태로 변경한다.
- **서비스 제한**: 
    - 모든 암호 서비스 API 시작점에서 내부 상태 변수를 확인한다.
    - 현재 상태가 '심각한 오류'인 경우, 요청된 함수와 관련된 기능을 포함하여 모듈 내 모든 기능을 사용할 수 없도록 차단한다.
    - 호출자에게는 사전에 정의된 오류 코드만을 반환하고 실제 연산 로직으로의 진입을 원천 봉쇄한다.

### 3.2. 오류 상태 해제 조건
- **영구적 제한**: 소프트웨어 라이브러리 특성상 메모리 상의 오류 상태는 휘발성이나, 심각한 오류로 판단된 경우 단순 API 재호출로는 정상 상태로 복구되지 않는다.
- **해제 방법**: 사용자는 암호모듈이 탑재된 응용 프로그램을 완전히 종료 후 **재구동(Reboot)**하거나, 바이너리 손상이 의심되는 경우 **재설치(Reinstall)**를 수행해야 한다. 재구동 후 다시 수행되는 동작 전 자가시험을 모두 통과하여 상태 변수가 '정상(STATE_NORMAL)'으로 설정된 경우에만 서비스를 재개한다.

## 4. 구조도 및 시각 자료 (Visuals)
> **알림**: 본 항목은 유한상태모델(FSM)과 연계된 상태 기반 제어 로직에 집중함.
> **논리 흐름**: [자가시험 실패] → [전역 변수 갱신(Serious Error)] → [서비스 요청 인입] → [상태 변수 체크] → [진입 거부/오류 반환] → [재구동/재설치] → [자가시험 재수행] → [정상 복구]

## 5. 해설 및 증빙 가이드 (Guide)
- **AS10.09와의 차별점**: AS10.09가 데이터가 밖으로 나가지 않게 '잠그는 것'에 집중한다면, AS10.10은 '정상 상태가 아니면 아예 일을 시작하지 않는' 관리 로직을 증빙하는 것이 핵심임.
- **내부 변수 보호**: 상태를 저장하는 전역 변수가 외부 응용 프로그램에 의해 임의로 수정될 수 없도록 캡슐화되어 있음을 강조할 것.
- **PQC/대칭키 알고리즘 통합**: 구현 중인 **LEA, HAETAE, SMAUG-T** 알고리즘의 모든 진입점(Entry Point)에 이 상태 확인 로직이 공통적으로 적용되어 있음을 설계서에 명시하여 보안 일관성을 증명할 것.
- **FSM(유한상태모델) 연계**: 나중에 작성할 유한상태모델 섹션에서 'Error State'에서 'Normal State'로 가는 전이 조건이 오직 'Power On(재구동)'임을 이 항목과 일치시켜야 함.
