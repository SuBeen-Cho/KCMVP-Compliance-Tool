# [AS10.11] 자가시험 실패 시 오류상태 미출력에 대한 명세

## 1. 보안요구사항 개요
자가시험 실패 시 암호모듈이 별도의 명시적인 오류 상태를 출력하지 않는 경우, 해당 모듈이 오류 상태에 진입했음을 결정할 수 있는 명백한 절차와 암호 서비스 수행 불가함을 입증하는 근거를 개발문서에 명세해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE10.11.01**: 자가시험 실패 시 오류상태 미출력에 대한 암호모듈이 오류 상태에 진입했는지를 결정할 수 있는 명백한 절차를 명세

## 3. 작성 예시 (Examples)

### 3.1. 암시적 오류 상태 판단 절차
"KISACrypto V1.0은 자가시험 실패 시 사용자에게 별도의 'Error State' 문자열이나 메시지를 화면에 출력하지 않는다. 대신, 내부 상태를 오류 상태로 고정하여 이후의 모든 암호 서비스 요청에 대해 서비스 수행 불가함을 반환값으로 알린다."

- **판단 절차**: 
    1. 모듈 초기화 후 임의의 암호 서비스 API(예: `KISA_LEA_Encrypt`)를 호출한다.
    2. API가 정상 결과가 아닌 특정 실패 코드(예: `KISA_ERR_NOT_INITIALIZED` 또는 `0`)를 일관되게 반환하는지 확인한다.
    3. 동일한 API를 재호출해도 동일한 실패 코드가 반환된다면, 모듈이 자가시험 실패로 인한 암시적 오류 상태에 진입한 것으로 결정한다.

### 3.2. 소스코드 상의 서비스 제한 근거
"자가시험 실패 시 전역 상태 변수(`g_self_test_passed`)가 `FALSE`로 설정되며, 모든 서비스 진입점에서는 이 값을 체크하여 로직을 중단한다."

```c
// 암호 서비스 진입점 예시 (LEA 알고리즘)
int KISA_LEA_Encrypt(unsigned char* ct, const unsigned char* pt, void* key)
{
    // 자가시험 통과 여부를 체크하여 오류 상태 진입 여부 결정
    if (g_self_test_passed != TRUE) {
        // 어떠한 암호 연산도 수행하지 않고 즉시 종료
        return KISA_ERR_STATE_INVALID; 
    }
    
    // 정상 상태일 경우에만 실제 LEA 연산 로직 수행
    ...
}
```

## 4. 구조도 및 시각 자료 (Visuals)
> **알림**: 본 항목은 명시적 출력 대신 서비스 가용성 차단을 통한 오류 인지 로직에 집중함.
> **논리 흐름**: [자가시험 수행] → [실패 시 내부 FLAG만 'Fail' 세팅] → [서비스 요청] → [내부 FLAG 체크] → [응답 없음/에러 코드 반환] → [운영자가 오류 상태임을 확정]

## 5. 해설 및 증빙 가이드 (Guide)
- **출력 부재의 정당성**: 보안상의 이유로 상세한 오류 정보를 노출하지 않는 경우, 이를 대체하여 운영자가 상황을 파악할 수 있는 우회적 판단 경로(반환값 확인 등)가 설계서에 기술되어야 함.
- **소스코드 매핑**: 실제 소스코드에서 자가시험 결과가 저장되는 변수와, 이 변수가 각 알고리즘(LEA, HAETAE 등) API의 조건문에서 어떻게 사용되는지 매핑하여 제시해야 함.
- **일관성 유지**: AS10.09(출력 금지) 및 AS10.10(서비스 제한)과 논리적으로 일치해야 하며, 재구동 전까지는 이 암시적 오류 상태가 절대로 해제되지 않음을 명시할 것.
- **PQC 알고리즘 고려**: 구현 중인 **HAETAE**나 **SMAUG-T**와 같은 복잡한 알고리즘은 KAT 시험 시간이 상대적으로 길 수 있는데, 이 과정에서 발생한 실패가 이후 모든 연산 차단으로 이어지는지 판단 절차를 명확히 할 것.
