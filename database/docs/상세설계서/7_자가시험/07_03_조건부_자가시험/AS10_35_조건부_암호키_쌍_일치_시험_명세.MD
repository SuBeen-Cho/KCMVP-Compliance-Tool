# [AS10.35] 조건부 암호키 쌍 일치 시험 명세

## 1. 보안요구사항 개요
암호모듈이 공개키, 개인키 쌍을 내부에서 생성하는 경우, KS X ISO/IEC 19790의 부속서 C~E 명세에 따라 생성된 키 쌍이 수학적으로 일치하고 유효한지 확인하기 위한 조건부 자가시험을 수행하고 그 과정을 명세해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE10.35.01~03**: 조건부 암호키 쌍 일치시험에 대한 상세 명세 및 이행 여부 증빙

## 3. 작성 예시 (Examples)

### 3.1. 대상 알고리즘 및 시험 정책
"KISACrypto V1.0은 공개키 암호(RSAES), 전자서명(RSA-PSS), 키 합의(DH) 알고리즘에 대해 키 쌍 생성 기능을 제공하며, 키 생성 직후 다음과 같은 일치 시험을 강제로 수행한다."

- **시험 시점**: `KISA_Crypto_genKeyPair()` 함수 내부에서 키 생성이 완료된 직후, 사용자에게 키를 반환하기 전에 수행함.
- **시험 방법**: 생성된 공개키와 개인키를 사용하여 암호화/복호화 또는 서명/검증 연산을 1회 수행하여 원본 데이터와의 일치 여부를 확인함.

### 3.2. 알고리즘별 상세 시험 방법
| 알고리즘 유형 | 상세 시험 절차 (PCT) |
| :--- | :--- |
| **암호화 (RSAES)** | 임의의 테스트 데이터를 공개키로 암호화한 후, 생성된 개인키로 복호화하여 원본 데이터와 일치하는지 비교함. |
| **전자서명 (RSA-PSS)** | 임의의 테스트 데이터에 대해 생성된 개인키로 서명을 생성하고, 이를 공개키로 검증하여 성공 여부를 확인함. |
| **키 합의 (DH)** | 생성된 키 쌍을 기반으로 임시 키 교환 과정을 모사하여 최종 도출된 공유 비밀값이 올바른지 수학적으로 검증함. |

## 4. 구조도 및 시각 자료 (Visuals)
> **알림**: 본 항목은 키 생성과 검증 로직의 원자적(Atomic) 실행에 집중함.
> **논리 흐름**: [키 쌍 생성 API 호출] → [난수 기반 키 생성] → [즉시 PCT 함수 호출] → [성공 시 키 반환 / 실패 시 키 즉시 제로화 및 오류 코드 반환]

## 5. 해설 및 증빙 가이드 (Guide)
- **부속서 준수**: 본 시험은 KS X ISO/IEC 19790 표준의 부속서 C(공개키 암호), D(키 확립), E(전자서명)에서 요구하는 알고리즘별 일치성 시험 요건을 충족해야 함.
- **AS10.25와의 관계**: 본 항목은 조건부 자가시험의 전체 목록을 다루는 AS10.25와 밀접하게 연관됨. AS10.25에서 시험 목록을 제시했다면, AS10.35에서는 그 절차의 수학적 정당성과 표준 준수 여부를 더 깊이 있게 서술함.
- **보안성 확보**: 일치 시험에 사용된 임시 테스트 데이터 및 중간 연산 결과물은 시험 종료 즉시 **제로화(Zeroization)**하여 메모리에 잔류하지 않도록 설계해야 함.
- **PQC 알고리즘 확장**: 수빈님이 연구 중인 **HAETAE(양자내성 전자서명)** 알고리즘 역시 새로운 키 쌍을 생성할 때 이 PCT 로직이 반드시 포함되어야 하며, 해당 과정이 설계서 상에 명확히 기술되어야 함.
