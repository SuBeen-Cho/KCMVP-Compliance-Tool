# [AS02.24] 검증대상 동작모드에서 서비스에 대한 표시기 제공 필요

## 1. 보안요구사항 개요
암호모듈은 제공하는 각 암호 서비스별로 성공과 실패 여부를 확인할 수 있는 표시기(Status Indicator)를 제공해야 하며, 운영자가 모듈의 현재 동작모드와 상태를 확인할 수 있는 수단을 마련해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE02.24.01**: 개발문서에 서비스에 대한 표시기 명세 필요

## 3. 작성 예시 (Examples)

### 3.1. 서비스 표시기 개요
"KISACrypto V1.0 암호모듈은 제공하는 각 암호 서비스별로 성공과 실패 여부를 확인할 수 있는 표시기를 제공한다. 소프트웨어 암호모듈의 특성상 각 함수 또는 API의 반환값(Return Value)을 통해 상태를 출력하며, 상세 정의는 다음과 같다."

### 3.2. [표] 주요 서비스별 표시기(상태 출력) 명세

| 함수 명칭 | 입력/제어 | 상태 출력 (표시기) | 설명 |
| :--- | :--- | :--- | :--- |
| **int KISA_Crypto_initialize(void)** | API 호출 | - KISA_SUCCESS (0x0001): 성공<br>- KISA_CRYPTO_ERROR_SELFTEST_FAILED (0x0002): 자가시험 실패<br>- KISA_CRYPTO_ERROR_STATE_IN_ERROR (0x0003): 오류 상태 | 모듈 초기화 및 동작 전 자가시험 수행. 성공 시 검증대상 동작모드로 자동 천이됨. |
| **int KISA_Crypto_getState(void)** | API 호출 | - KISA_CM_LOAD (0x10001)<br>- KISA_CM_PRE_SELFTEST (0x10002)<br>- KISA_CM_COND_SELFTEST (0x10003)<br>- KISA_CM_NORMAL_EXECUTION (0x10004)<br>- KISA_CM_SIMPLE_ERROR (0x10005)<br>- KISA_CM_HARD_ERROR (0x10006)<br>- KISA_CM_EXIT (0x10007) | 암호모듈의 현재 형태상태와 동작모드에 대한 표시기를 반환하여 운영자가 상태를 확인할 수 있게 함. |

## 4. 구조도 및 시각 자료 (Visuals)
> **알림**: 본 항목은 별도의 아키텍처 다이어그램을 포함하지 않음. 
> **논리 흐름**: [서비스/함수 호출] → [내부 로직 수행] → [성공/실패/오류 상태 판별] → [정의된 상태 코드(0x...) 반환] → [운영자 상태 확인]

## 5. 해설 및 증빙 가이드 (Guide)
- **반환값 정의**: 소프트웨어 암호모듈은 함수 호출 시 반환되는 상태값(상태정보)이 곧 표시기 역할을 함. 따라서 각 서비스별 성공/실패 에러 코드를 상세설계서에 빠짐없이 정의해야 함.
- **모드 확인 서비스**: 운영자가 언제든 모듈의 현재 동작모드를 확인할 수 있도록 `getState`와 같은 별도의 상태 확인 함수를 반드시 제공해야 함.
- **오류 상태 처리**: 자가시험 실패 등 모듈에 이상이 생겼을 경우, 이를 명확히 식별할 수 있는 고유 에러 코드(Hard Error 등)를 반환하여 후속 조치가 가능하도록 설계해야 함.
- **일관성**: 여기서 정의한 상태 코드는 실제 소스코드의 헤더파일(`kisa_kcmvp_main.h` 등)에 정의된 매크로 상수값과 반드시 일치해야 함.
