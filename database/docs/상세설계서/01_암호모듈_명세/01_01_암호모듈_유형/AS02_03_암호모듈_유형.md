# [AS02.03] 암호모듈 유형의 선택 및 근거 제시

## 1. 보안요구사항 개요
암호모듈의 물리적/논리적 형태를 정의하고, 해당 유형을 선택한 타당한 근거 및 모든 구성요소를 상세설계서에 명시해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE02.03.01**: 모듈 유형과 유형 선택의 근거를 제시한 개발문서 제출
- **VE02.03.02**: 암호모듈의 모든 구성요소를 식별하는 개발문서 제출

## 3. 작성 예시 (Examples)

### 3.1. 서술형 예시
"KISACrypto(암호모듈명)는 검증대상 암호알고리즘과 키 생성을 포함하는 알고리즘 함수와 프로세스로 구현한 소프트웨어 조합의 집합으로 “.dll” 및 “.so” 형태로 구성된 소프트웨어 모듈이다. 본 암호모듈은 KS X ISO/IEC 19790:2015 암호모듈 보안요구사항의 보안수준 1을 준수하여 개발되었으며, 비검증대상 암호 알고리즘을 포함하지 않는다."

### 3.2. 표 형식 예시
| 항목 | 상세 내용 |
| :--- | :--- |
| **암호모듈명** | KISACrypto |
| **버전** | V1.0 |
| **제조사** | KISA (한국인터넷진흥원) |
| **보안수준** | 보안수준1 |
| **암호모듈유형** | 소프트웨어 암호모듈(동적라이브러리) |
| **구성요소** | 단일 파일로 구성 <br> - KISACrypto32.dll, KISACrypto64.dll(윈도우 환경) <br> - libKISACrypto64.so(리눅스 환경) 등 |
| **암호서비스** | 블록암호, 해시함수, 메시지인증코드, 난수발생기, 공개키암호, 전자서명, 키설정 등 |
| **운영환경** | **윈도우 환경**: Windows 10 32/64비트 <br> **리눅스 환경**: Ubuntu 24.04 64비트 |

## 4. 구조도 및 시각 자료 (Visuals)
> **알림**: 본 항목은 별도의 아키텍처 다이어그램을 포함하지 않음. 
> **논리 흐름**: [운영환경 로드] → [동적 라이브러리(DLL/SO) 식별] → [암호 서비스 호출 인터페이스 정의]

## 5. 해설 및 증빙 가이드 (Guide)
- 암호모듈 유형의 선택과 근거를 제시해야 하며, 위의 예시와 유사한 형태로 증빙 가능함.
- 구성요소는 단일 파일 형태뿐만 아니라, 암호모듈 파일과 무결성 검증 파일이 분리된 형태, .dll(.so, .dylib, .ko 등으로 구현 가능)이 여러 개의 파일로 구성된 형태 등 다양한 형태로 존재할 수 있음에 유의할 것.
