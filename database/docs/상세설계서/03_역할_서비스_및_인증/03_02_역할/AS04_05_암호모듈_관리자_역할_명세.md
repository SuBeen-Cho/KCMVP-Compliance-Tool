# [AS04.05] 암호모듈 관리자 역할에 대한 명세

## 1. 보안요구사항 개요
암호모듈의 관리 및 운영 전반을 담당하는 '암호 관리자' 역할을 정의하고, 해당 역할이 수행할 수 있는 관리적 서비스(설치, 초기화, 자가시험, 파기 등)의 범위를 명시해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE04.05.01**: 암호모듈 관리자와 연관된 서비스 명세

## 3. 작성 예시 (Examples)

### 3.1. [표] 인가된 역할별 서비스 권한 명세
| 구분 | 인가된 역할 및 수행 서비스 |
| :--- | :--- |
| **일반 사용자** | - 암호모듈에서 제공하는 보안 서비스 수행 (암/복호화, 해시 등) |
| **암호 관리자** | - 암호모듈 설치, 초기화, 자가시험 수행, 종료, 삭제 <br> - 암호모듈에서 제공하는 보안 서비스 수행 |

### 3.2. 서술형 예시
"KISACrypto V1.0은 암호 관리자와 일반 사용자 역할을 지원하며 논리적으로 구분된다. 일반 사용자는 암호모듈이 제공하는 일반 보안 서비스를 사용할 수 있으며, 관리자는 이에 더해 암호모듈의 설치, 초기화, 자가시험 수행, 종료 등의 관리적인 서비스까지 모두 사용 가능하다."

## 4. 구조도 및 시각 자료 (Visuals)
> **알림**: 본 항목은 별도의 아키텍처 다이어그램을 포함하지 않음. 
> **논리 흐름**: [관리자/사용자 역할 식별] → [서비스 호출 시 권한 대조] → [관리 서비스(초기화/파기 등) 접근 허용] → [운영 프로세스 수행]

## 5. 해설 및 증빙 가이드 (Guide)
- **관리자 역할 필수 포함**: 암호모듈 설계 시 기본적으로 암호관리자에 대한 역할이 포함되어야 함을 유의할 것.
- **권한의 포괄성**: 암호 관리자는 일반 사용자가 사용할 수 있는 모든 보안 서비스에 추가적으로 설치, 초기화, 중요보안매개변수(CSP) 관리, 종료, 삭제 등의 특수 권한을 가짐을 명시적으로 구분해야 함.
- **논리적 구분**: 소프트웨어 모듈의 경우, 물리적인 구분이 어렵기 때문에 API 호출 인터페이스나 내부 상태 제어 로직을 통해 역할을 명시적으로 구분하여 증빙해야 함.
