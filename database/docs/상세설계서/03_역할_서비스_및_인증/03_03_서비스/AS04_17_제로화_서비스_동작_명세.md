# [AS04.17] 검증대상 동작모드에서 제공하는 제로화 서비스에 대한 동작 명세

## 1. 보안요구사항 개요
검증대상 동작모드에서 사용되는 모든 중요보안매개변수(CSP)에 대하여, 사용 완료 후 메모리 상에서 안전하게 파기하는 제로화(Zeroization) 서비스의 동작 과정을 명세해야 함.

## 2. 상세 요구사항 (Requirements)
*해당 항목은 별도의 VE 식별자 없이 제로화 동작에 대한 구체적인 증빙을 요구함.*

## 3. 작성 예시 (Examples)

### 3.1. 제로화 서비스 개요
"KISACrypto V1.0은 사용이 완료된 중요보안매개변수에 대해 사용 후, 메모리 상에서 안전하게 삭제할 수 있는 제로화 API인 `KISA_Crypto_Zeroize()`를 제공한다. 해당 함수는 인자로 전달된 메모리 영역을 0으로 덮어쓰기 하여 잔류 정보를 파기한다."

### 3.2. 블록암호 키 제로화 수행 결과 예시
"아래는 128-bit 블록 암호키에 대해 제로화 API를 호출하였을 때, 메모리 상의 기존 값이 '0'으로 초기화되는 과정을 보인 로그이다."

## 5. 해설 및 증빙 가이드 (Guide)
- **제로화의 확실성**: 단순히 메모리 할당을 해제(Free)하는 것만으로는 데이터가 남을 수 있으므로, 반드시 물리적인 덮어쓰기(Overwrite) 과정이 포함되어 있음을 소스코드와 로그로 증명해야 함.
- **시험서와의 정합성**: AS04.17에서 제시하는 제로화 시험 데이터는 실제 **'암호모듈 시험서'**의 테스트 케이스와 동일한 입출력 형식을 유지해야 함.
- **대상 파라미터**: 비밀키뿐만 아니라 IV(초기화 벡터), 중간 연산 값, 개인키 등 모듈 내에서 정의된 모든 CSP가 제로화 대상에 포함되어 있는지 확인이 필요함.
- **자동 제로화**: 특정 서비스 종료 시 자동으로 호출되는 내부 제로화 로직이 있다면, 그 호출 시점과 처리 과정을 상세설계서에 명기할 것.
