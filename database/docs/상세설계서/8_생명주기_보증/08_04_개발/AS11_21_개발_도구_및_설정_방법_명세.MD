# [AS11.21] 개발 도구(컴파일러) 및 설정 방법 명세

## 1. 보안요구사항 개요
소프트웨어 암호모듈 구성 요소에 대하여 암호모듈을 개발하기 위해 사용한 개발 도구(컴파일러, 빌드 도구 등)의 상세 사양과 보안 설정 방법(컴파일 옵션 등)을 운영 환경별로 상세히 명세해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE11.21.01**: 소프트웨어 암호모듈 구성 요소에 대하여 암호모듈을 개발하기 위해 사용한 개발 도구 명세

## 3. 작성 예시 (Examples)

### 3.1. 운영 환경별 개발 도구 설정 명세
"본 암호모듈은 각 운영 환경에서 동일한 보안 수준을 유지하도록 다음과 같은 개발 도구와 빌드 옵션을 사용하여 생성되었다."

| 운영 환경 | 개발 도구 (컴파일러/링커) | 빌드 도구 및 방법 | 주요 컴파일/링크 옵션 |
| :--- | :--- | :--- | :--- |
| **Windows 10** | Microsoft Visual C++ Compiler (Visual Studio 2019, v142) | MSBuild / Release 빌드 | `/O2` (속도 최적화), `/GS` (버퍼 오버런 체크), `/NXCOMPAT` (DEP 적용) |
| **Linux (Ubuntu)** | GCC (v9.3.0) / GNU Linker (ld) | GNU Make / Makefile 호출 | `-O3` (최적화), `-fstack-protector-all` (스택 보호), `-fPIC` (위치 독립 코드) |

### 3.2. 빌드 절차 및 설정 방법
1. **환경 설정**: 각 운영 환경에 맞는 컴파일러 경로 및 환경 변수를 설정함.
2. **옵션 적용**: 보안 요구사항에 정의된 최적화 및 보안 강화 옵션(Stack Guard 등)이 빌드 스크립트에 누락 없이 반영되었는지 확인함.
3. **최종 빌드**: `make` 명령 또는 IDE의 `Rebuild All` 기능을 통해 최종 배포용 라이브러리를 생성함.

## 4. 구조도 및 시각 자료 (Visuals)
> **설계 핵심**: 본 항목은 개발 도구의 설정값이 암호모듈의 바이너리 보안 특성(스택 보호, DEP 등)에 직접적인 영향을 미침을 증빙하는 것이 관건임.

## 5. 해설 및 증빙 가이드 (Guide)
- **보안 옵션의 필수성**: KCMVP 심사에서는 단순히 컴파일러 버전뿐만 아니라, 메모리 오염 공격을 방어하기 위한 보안 컴파일 옵션(예: `/GS`, `-fstack-protector`)이 실제로 적용되었는지를 매우 중요하게 확인하므로 이를 명확히 기재해야 함.
- **AS11.15와의 차별점**: AS11.15가 전반적인 '인프라' 환경에 집중한다면, AS11.21은 실제 소스코드를 바이너리로 변환하는 '도구와 그 설정값'에 더 집중하여 기술함.
- **재현성 증빙**: 동일한 도구와 옵션을 사용하여 빌드했을 때 항상 같은 해시값을 가진 결과물이 나옴을 보장해야 하며, 임베디드 환경의 경우 링커 스크립트(.ld) 내의 섹션 배치 설정 등도 개발 도구 명세에 포함하는 것이 권장됨.
