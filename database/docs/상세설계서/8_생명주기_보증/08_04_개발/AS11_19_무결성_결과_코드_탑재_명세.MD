# [AS11.19] 무결성 결과 코드 탑재 명세

## 1. 보안요구사항 개요
암호모듈 개발 단계에서 소프트웨어의 무결성을 검증하기 위한 인증 기법 메커니즘을 적용하고, 계산된 결과 코드(무결성 검증값)를 모듈 내에 안전하게 탑재하는 방법과 절차를 명세해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE11.19.01**: 개발 단계에서 무결성 및 인증 기법 메커니즘의 결과 코드 명세

## 3. 작성 예시 (Examples)

### 3.1. 무결성 검증값 생성 도구 및 알고리즘
"암호모듈의 무결성 검증값 생성을 위해 별도로 개발된 전용 프로그램인 **'IntegrityGenSoftware'**를 사용하며, 신뢰성 확보를 위해 다음과 같은 방식을 적용한다."

* **적용 알고리즘**: 암호모듈 내부 소스코드에 구현된 것과 동일한 **HMAC(SHA-256)** 알고리즘을 사용함.
* **검증 키 생성**: 검증대상 암호알고리즘으로 승인된 **난수발생기(RNG)**를 통해 무결성 검증키를 생성하여 보안성을 확보함.
* **형상 관리**: 무결성 검증값 생성 프로그램 역시 암호모듈과 동일하게 형상관리 시스템의 적용을 받아 버전 및 이력이 관리됨.

### 3.2. 결과 코드 탑재 방법
* **결합 위치**: 'IntegrityGenSoftware'를 통해 생성된 최종 무결성 검증값(HMAC 결과값)을 암호모듈 바이너리 파일의 **최하단(Footer 영역)**에 물리적으로 결합함.
* **검증 프로세스**: 모듈 초기화 시, 탑재된 결과 코드를 읽어와 실시간으로 계산한 값과 비교함으로써 모듈의 변조 여부를 최종 판단함.

## 4. 구조도 및 시각 자료 (Visuals)
> **설계 핵심**: 본 항목은 빌드 후 공정(Post-build process)에서 무결성 값이 생성되고 결합되는 흐름을 증빙하는 것이 관건임.
> **논리 흐름**: [모듈 빌드 완료] → [IntegrityGenSoftware 실행] → [HMAC-SHA-256 계산] → [바이너리 하단에 값 추가] → [배포용 암호모듈 완성]


## 5. 해설 및 증빙 가이드 (Guide)
* **알고리즘의 정합성**: 생성 프로그램에 구현된 HMAC 로직이 실제 암호모듈의 소스코드와 동일함을 소스코드 비교나 함수 호출 구조를 통해 증빙해야 함.
* **키 관리의 안전성**: 무결성 검증에 사용된 키가 어떻게 안전하게 생성되고 보관되는지(예: 별도의 보안 저장소 또는 소스 내 은닉 등)에 대한 추가 명세가 필요할 수 있음.
* **결합 위치의 명확성**: 바이너리 파일 내에서 검증값이 저장되는 정확한 오프셋(Offset)이나 영역을 설계서에 명시하여, 무결성 시험 단계에서 해당 값을 올바르게 추출할 수 있음을 보여주어야 함.
* **KCMVP 대응**: 심사 시에는 실제 'IntegrityGenSoftware'를 실행하여 결과 코드가 생성되고 결합되는 과정을 시연해야 할 수 있으므로, 관련 매뉴얼과 빌드 스크립트를 함께 정리해 두는 것이 권장됨.
