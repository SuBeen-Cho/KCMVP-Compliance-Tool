# [AS11.03] 형상관리 시스템의 사용 명세

## 1. 보안요구사항 개요
암호모듈 개발에 사용되는 개발문서, 소스코드, 구성요소 등에 대하여 형상관리 시스템(CMS)을 적용하고, 이에 대한 상세 명세와 적절한 접근 제어 정책을 제시해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE11.03.01**: 개발문서, 모듈구성요소, 모듈에 관리 적용된 형상관리시스템 명세

## 3. 작성 예시 (Examples)

### 3.1. 형상관리 시스템 환경 및 도구
"KISACrypto V1.0 암호모듈은 개발 전 과정의 보안성과 추적성을 보장하기 위해 **Git(또는 SVN)** 기반의 형상관리 시스템을 사용한다."

* **시스템 명칭**: GitLab Enterprise Edition (또는 사내 구축형 SVN 서버)
* **관리 서버**: 개발망 내 독립된 형상관리 서버 (외부망 차단)
* **접근 제어**: 2단계 인증(2FA) 및 역할 기반 접근 제어(RBAC) 적용

### 3.2. 형상관리 대상 목록
"다음과 같은 암호모듈 관련 핵심 자산을 형상관리 시스템의 관리 항목으로 지정하여 버전 관리 및 이력 추적을 수행한다."

| 관리 항목 | 세부 내용 |
| :--- | :--- |
| **개발 문서** | 요구사항 정의서, 기본/상세 설계서, 시험 계획서 및 결과서 |
| **소스 코드** | 암호 알고리즘 소스코드, 헤더 파일, 빌드 스크립트(Makefile) |
| **구성 요소** | 외부 라이브러리(필요 시), 테스트 벡터 데이터 세트 |
| **보안 자산** | 무결성 검증용 마스터 키, 인증서 생성 스크립트 |
| **테스트 프로그램** | 자가시험 및 알고리즘 검증용 테스트 도구 소스 |

## 4. 구조도 및 시각 자료 (Visuals)
> **설계 핵심**: 형상 변경(Commit/Push)은 사전에 인가된 개발자만 가능하며, 모든 변경 이력은 타임스탬프와 작업자 정보가 포함되어 기록됨.

## 5. 해설 및 증빙 가이드 (Guide)
* **접근 제어의 구체성**: 단순히 "시스템을 사용한다"는 기술보다는, "누가, 어떤 권한으로, 어떻게 접근하는지"에 대한 정책(예: 개발자 읽기/쓰기, 관리자 전체 권한 등)을 명시하는 것이 중요함.
* **형상관리문서 인용**: 상세한 관리 절차(Branch 전략, Merge Request 프로세스 등)는 별도로 작성된 '형상관리 지침서'의 내용을 인용하여 증빙의 전문성을 높일 것.
* **무결성 검증키 관리**: 특히 KCMVP 심사에서는 무결성 검증에 사용되는 키나 파라미터가 형상관리 내에서 어떻게 안전하게 분리되어 관리되는지 눈여겨보므로 이에 대한 언급을 포함할 것.
