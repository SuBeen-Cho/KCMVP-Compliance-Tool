# [AS11.32] 안전한 설치, 초기화 및 시동 명세

## 1. 보안요구사항 개요
암호모듈이 배포되어 운영 환경에 안전하게 설치되고, 무결성이 보장된 상태에서 초기화 및 시동될 수 있도록 구체적인 절차를 명세해야 함. 또한 사용이 종료된 모듈을 안전하게 소거하는 방법도 포함해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE11.32.01**: 안전한 설치, 초기화 및 시동을 위한 절차 명세

## 3. 작성 예시 (Examples)

### 3.1. 단계별 안전 운영 절차
"KISACrypto V1.0 암호모듈은 배포부터 소거까지 다음과 같은 엄격한 절차를 준수하여 운영한다."

| 구분 (주체) | 절차 및 상세 내용 |
| :--- | :--- |
| **설치 전 검증**<br>(암호모듈 관리자) | 1. **보안 USB**를 통해 암호모듈 배포 및 전달.<br>2. 인수자는 암호모듈 파일에 대한 파일명과 시험기관 홈페이지에 등재된 해시값을 비교하여 검증필 여부 확인. (File: KISACrypto V1.0, Ver: 1.0) |
| **설치**<br>(인수자) | 1. 인수자는 암호모듈 파일(`KISACrypto32.dll`, `KISACrypto64.dll`, `libKISACrypto64.so`)을 지정된 설치 경로로 이동.<br>2. 별도의 설치 프로그램 없이 일반 동적/공유 라이브러리 링크 방식으로 설치 완료. |
| **초기화 및 시동**<br>(인수자) | 1. 테스트 프로그램을 이용하여 자가시험 성공 여부 확인.<br>2. 시험 실패 시 개발팀장 및 보안관리자에게 즉시 보고.<br>3. 서비스 API 호출 후 모듈 명칭 및 버전 확인 API를 통해 정보 정합성 최종 확인. |
| **소거**<br>(개발자, 인수자) | 1. 사용이 완전히 완료되어 삭제하는 경우, 특정 경로에 저장된 라이브러리 파일 및 관련 보안 자산을 물리적으로 삭제. |

## 4. 구조도 및 시각 자료 (Visuals)
> **설계 핵심**: 배포 경로의 신뢰성(보안 USB)과 설치 후 상태 검증(자가시험 및 API 확인)이 연쇄적으로 이루어져야 함.
> **논리 흐름**: [보안 배포] → [해시값 검증] → [경로 설치] → [자가시험 수행] → [API 가동] → [운영 종료 후 소거]

## 5. 해설 및 증빙 가이드 (Guide)
- **배포의 안전성**: 암호모듈은 사전에 할당된 운영자에게만 보안 USB 등 안전한 경로를 통해 전달되어야 하며, 불특정 다수에게 공개된 경로로 배포되어서는 안 됨.
- **검증필 확인**: 인수자가 직접 시험기관(KISA 등) 홈페이지의 공고 내용과 대조하는 절차를 명시하여, 배포 중 변조 가능성을 원천 차단함.
- **스크립트 활용**: 수빈님이 개발 중인 KCMVP 사전 검증 프레임워크에서는 설치 오류를 방지하기 위해 자동화된 **설치 및 환경 설정 스크립트**를 제공하고, 이를 통해 VE11.32.01 요건을 더 강력하게 증빙할 수 있음.
- **운영 가이드 연계**: 본 항목의 절차는 12장에서 작성할 '관리자/운영자 안내서'의 내용과 완벽히 일치해야 함.
