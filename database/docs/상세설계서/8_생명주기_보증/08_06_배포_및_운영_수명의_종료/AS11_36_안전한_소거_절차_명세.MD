# [AS11.36] 안전한 소거 절차 명세

## 1. 보안요구사항 개요
암호모듈의 사용이 완전히 종료된 후, 잔존하는 암호 자산 및 모듈 파일을 물리적·논리적으로 복구가 불가능하도록 안전하게 제거하는 절차를 명세해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE11.36.01**: 안전한 소거 절차를 명세

## 3. 작성 예시 (Examples)

### 3.1. 플랫폼별 안전 소거 방법
"KISACrypto V1.0 암호모듈은 동적 라이브러리 형태로 존재하므로, 사용 종료 시 해당 라이브러리 파일을 삭제하고 저장 영역을 덮어쓰기 함으로써 소거를 수행한다."

- **Windows 환경**: 
    - 암호모듈 파일(`KISACrypto32.dll`, `KISACrypto64.dll`)을 삭제함.
    - `cipher` 명령어를 사용하여 삭제된 파일 영역을 덮어쓰기 함으로써 복구 가능성을 차단함.
    - 예시: `cipher /w:C:\KISACrypto`
- **Linux 환경**: 
    - `shred` 명령어를 사용하여 파일을 여러 번 덮어쓴 후 삭제함.
    - 기본 3회 덮어쓰기 후 마지막에 0으로 채우는(Zeroing) 과정을 수행함.
    - 예시: `shred -u -n 3 -z libKISACrypto64.so`
- **기타 저장 매체**: USB, CD 등으로 배포된 자료의 경우 저장 장치를 물리적으로 파쇄하거나 로우 레벨 포맷(Low-level Format)을 수행함.

### 3.2. 소거 절차의 자동화
"운영자의 편의와 정확한 소거를 위해, 상기 소거 명령어를 포함한 별도의 스크립트 형태의 소거 명령 집합을 제공할 수 있다."

## 4. 구조도 및 시각 자료 (Visuals)
> **설계 핵심**: 단순 삭제(Delete)가 아닌 재기록(Overwrite)을 통한 완전 파기에 집중함.
> **논리 흐름**: [운영 종료 결정] → [라이브러리 언로드] → [플랫폼별 소거 도구 실행(cipher/shred)] → [영역 덮어쓰기 완료] → [소거 확인]

## 5. 해설 및 증빙 가이드 (Guide)
- **절차의 구체성**: 단순히 "파일을 지운다"고 기술하지 말고, OS에서 제공하는 보안 소거 도구(cipher, shred 등)의 옵션값과 실행 예시를 상세히 기재해야 함.
- **배포 매체별 대응**: 소프트웨어 바이너리뿐만 아니라 배포 시 사용된 매체(USB 등)에 대한 처리 방안도 누락 없이 포함해야 함.
- **LEA 및 PQC 프로젝트 적용**: 수빈님이 개발 중인 **LEA** 최적화 모듈이나 **HAETAE** 라이브러리가 탑재된 서버 및 임베디드 기기에서, 해당 라이브러리 영역만 타겟팅하여 안전하게 소거할 수 있는 스크립트를 안내서(12장)와 연계하여 작성할 것.
