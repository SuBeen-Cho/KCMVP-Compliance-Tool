# [AS06.07] 보안정책문서에 운영환경 설정 사항 명세

## 1. 보안요구사항 개요
암호모듈이 구동되는 구체적인 운영환경 정보와 모듈의 안전한 동작을 위해 필요한 설정 및 규제 사항을 보안정책서(SP)에 명세하여, 사용자가 이를 참고하여 올바르게 환경을 구성할 수 있도록 해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE06.07.01**: 운영환경 설정과 규제 사항에 대해 보안정책문서(SP)에 명세 필요

## 3. 작성 예시 (Examples)

### 3.1. 보안정책서(SP) 반영 예시
"KISACrypto V1.0 암호모듈은 범용적인 운영체제인 Windows 10과 Ubuntu 24.04에서 동작한다. 본 모듈은 운영체제가 제공하는 프로세스 및 메모리 보호 기능을 활용하므로, 암호모듈 인스턴스와 CSP가 타 프로세스에 의해 간섭받지 않는다."

### 3.2. 운영환경 규제 및 권고사항
"암호모듈을 안전하게 운영하기 위해 다음과 같은 환경 설정을 권고한다."
1. **계정 생성**: 운영체제 내에 암호모듈 전용 관리자(Crypto Officer)와 사용자(User) 계정을 개별 생성해야 함.
2. **인증 절차**: 각 운영체제가 제공하는 표준 인증 메커니즘을 통과한 사용자만이 암호모듈에 접근할 수 있도록 권한을 제한함.
3. **독립성 유지**: 암호모듈 인스턴스 보호를 위한 특별한 추가 설정은 필요하지 않으나, OS의 최신 보안 업데이트를 유지할 것을 권장함.

## 4. 구조도 및 시각 자료 (Visuals)
> **알림**: 본 항목은 문서화 요건에 집중함.
> **논리 흐름**: [운영환경 식별] → [OS 보안 기능 매핑] → [관리자/사용자 계정 정책 수립] → [보안정책서(SP)에 상세 명세] → [운영자 가이드로 활용]


## 5. 해설 및 증빙 가이드 (Guide)
- **정보의 일관성**: 본 조항에서 명세하는 운영환경 정보는 상세설계서(AS06.03) 및 사용자 안내서(AG)에 기재된 내용과 완벽히 일치해야 함.
- **사용자 참고용**: 단순히 "안전하다"는 서술에 그치지 않고, 사용자가 실제 시스템을 구축할 때 참고할 수 있도록 구체적인 OS 버전, 비트 정보, 필요한 권한 설정 등을 포함하는 것이 핵심임.
- **규제 사항 포함**: 암호모듈을 사용하기 위해 지켜야 할 최소한의 보안 수칙(예: 계정 분리, 비밀번호 정책 등)을 규제 사항으로서 보안정책서에 명확히 기술해야 함.
