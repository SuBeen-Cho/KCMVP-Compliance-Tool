# [AS05.09] 운영자의 요구에 따른 무결성 시험 수행 명세

## 1. 보안요구사항 개요
암호모듈 초기화 시 수행되는 자동 자가시험과 별개로, 운영자가 필요할 때 인터페이스를 통해 온디맨드(On-demand) 방식으로 무결성 시험을 수행할 수 있는 메커니즘을 제공해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE05.09.01**: 운영자의 요구에 따라 인터페이스를 통해 무결성 시험을 수행할 수 있는 근거 제시

## 3. 작성 예시 (Examples)

### 3.1. 온디맨드 무결성 시험 API 개요
"KISACrypto V1.0 암호모듈은 운영자의 요구에 따라 즉시 무결성 시험을 수행할 수 있도록 `KISA_Crypto_integritytest()` API를 제공한다. 본 모듈은 소프트웨어(SW) 라이브러리 유형이므로 SFMI(Software or Firmware Module Interface) 규격에 따라 제어 입력 인터페이스를 통해 해당 기능을 호출할 수 있다."

### 3.2. 인터페이스 및 보안 통제
- **호출 방식**: 응용 프로그램에서 제어 입력 인터페이스인 `KISA_Crypto_integritytest()`를 직접 호출함.
- **데이터 격리**: 무결성 시험에 필요한 데이터 입력, 출력, 상태 정보는 암호모듈 인터페이스 보안요구사항(AS03 섹션)에서 정의한 전용 경로를 통해서만 전달되며, 명세된 경로 이외의 인터페이스는 사용하지 않음.
- **결과 반환**: 시험 수행 후 성공 또는 실패 여부를 즉시 반환하며, 실패 시 모듈은 오류 상태로 전환됨.

## 4. 구조도 및 시각 자료 (Visuals)
> **알림**: 본 항목은 API 호출을 통한 논리적 흐름에 집중함.
> **논리 흐름**: [운영자/응용 프로그램 요청] → [KISA_Crypto_integritytest 호출] → [무결성 검증 로직 진입] → [전용 인터페이스를 통한 정보 전달] → [결과값 반환]


## 5. 해설 및 증빙 가이드 (Guide)
- **독립적 수행 보장**: 동작 전 자가시험(Pre-operational Self-test)과는 별도로, 운영자가 실시간으로 무결성을 확인할 수 있는 API가 소스코드 상에 구현되어 있음을 증빙해야 함.
- **인터페이스 단일화**: AS05.10 요건과 연계하여, 무결성 시험과 관련된 모든 정보(키 복원, 결과값 출력 등)가 AS03에서 명세한 공식 인터페이스를 통해서만 전달됨을 강조할 것.
- **API 형태의 유연성**: 무결성 시험만을 수행하는 전용 API 형태이거나, 무결성 시험을 포함한 전체 자가시험을 아우르는 API 형태 모두 인정되므로 모듈 설계 방식에 맞춰 명세하면 됨.
