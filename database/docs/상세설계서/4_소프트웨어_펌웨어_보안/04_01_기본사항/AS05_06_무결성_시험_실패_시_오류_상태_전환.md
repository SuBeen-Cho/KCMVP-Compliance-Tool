# [AS05.06] 무결성 시험 실패 시 오류 상태 전환 명세

## 1. 보안요구사항 개요
암호모듈 초기화 중 수행되는 소프트웨어/펌웨어 무결성 시험이 실패할 경우, 모듈은 즉시 모든 서비스를 차단하고 '심각한 오류(Critical Error)' 상태로 전환되어야 함을 명세함.

## 2. 상세 요구사항 (Requirements)
- **VE05.06.01**: 암호모듈에 적용된 소프트웨어/펌웨어 무결성 시험에 대한 명세

## 3. 작성 예시 (Examples)

### 3.1. 무결성 시험 메커니즘 개요
"KISACrypto V1.0은 RSA-PSS 3072-bit 전자서명을 이용하여 무결성 검증을 수행한다. 초기화 과정 중 무결성 검증이 실패하면 모듈은 심각한 오류 상태로 자동 천이되며, 이후 모든 서비스 호출이 거부된다. 이 상태는 모듈의 재시작 또는 재설치를 통해서만 해제될 수 있다."

### 3.2. 무결성 시험 수행 수도코드 (Pseudocode)
"아래는 `KISA_integrity.c`에 구현된 `_Integrity_test()` 함수의 논리 흐름이다. 주석을 통해 각 단계별 보안 조치를 명시한다."

```c
int _Integrity_test(void) {
    int rv = 0;
    
    // A.1 라이브러리 경로 획득
    // 암호모듈 인스턴스로부터 실행 파일의 물리적 경로를 얻음
    _GetModuleFileName(modulename, MODULE_NAME_LEN);

    // A.2 버퍼에 암호모듈 파일 내용 로드
    // 경로를 이용하여 모듈 파트(M)와 서명값(T)을 각각 메모리에 로드
    _Load_library(module_buf, sig_buf, modulename);

    // A.3 무결성 검증을 위한 내부 함수 호출
    // 서명 검증을 위해 _LibraryVerify() 호출
    rv = _LibraryVerify(sig_buf, SIGN_LEN, module_buf, len);
    
    if (rv != 0) { 
        // A.4 실패 시, 오류 코드를 반환하여 암호모듈을 심각한 오류 상태로 천이
        rv = -1;
        goto end;
    }

    // A.5 제로화
    // 검증 성공/실패 여부와 관계없이 사용된 임시 경로 정보 등 제로화
    Crypto_Zeroize(modulename, MODULE_NAME_LEN);
    ...
}

int _LibraryVerify(const u8 *signature, const u32 signatureLength, const u8 *message, const u32 messageLength) {
    int rv = 0;
    
    // B.1 모듈 내부에 저장된 공개키 로드
    // 분산 저장된 서명검증키(V)를 복원 및 로드
    rv = PublicKey_Decode(pubKey, empty_o, sizeof(empty_o));
    
    if (rv != 0) {
        goto error;
    }

    // B.2 전자서명 기반으로 무결성 검증 수행
    // RSA-PSS-SHA384 알고리즘을 사용하여 서명(T) 검증
    rv = PKCS1_Verify(signature, signatureLength, PKCS1_MSGID_MESSAGE,
                      message, messageLength, PKCS1_SIGNID_RSA_PSS_SHA384, pubKey, &signParam);
    
    if (rv != 0) {
        goto error;
    }

error:
    // B.3 제로화 수행 (사용된 임시 변수 및 공개키 객체에 대해 모두 제로화 필요)
    RSA_PublicKey_Free(pubKey);
    pubKey = NULL;
    
    return rv;
}
```

## 4. 구조도 및 시각 자료 (Visuals)
> **알림**: 본 항목은 수도코드를 통한 논리 명세에 집중함.
> **논리 흐름**: [파일 경로 획득] → [모듈/서명 로드] → [검증키 복원] → [RSA-PSS 검증] → [실패 시 즉각 -1 반환] → [상태 머신에서 Critical Error 고정] → [임시 데이터 제로화]


## 5. 해설 및 증빙 가이드 (Guide)
- **상태 천이의 명확성**: 수도코드에서 검증 실패 시(`rv != 0`) 반환되는 에러 코드가 상위 호출 함수(`KISA_Crypto_initialize`)에서 어떻게 '심각한 오류 상태' 플래그로 설정되는지 논리적 연결 고리를 제시해야 함.
- **AS05.07/08 연동**: 본 조항의 수도코드는 무결성 검증 기술(AS05.07)과 중간 데이터 제로화(AS05.08) 요건을 동시에 증빙하는 자료로 활용될 수 있으므로, 관련 주석을 상세히 유지할 것.
- **Fail-Safe 보장**: 검증 과정 중 메모리에 로드된 공개키나 모듈 버퍼 등이 에러 발생 시에도 누락 없이 제로화(`B.3` 과정)되는지 확인이 필요함.
