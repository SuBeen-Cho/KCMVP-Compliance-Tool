# [AS05.04] 안전한 배포, 운영 및 설치 전 변조 방지

## 1. 보안요구사항 개요
암호모듈의 배포, 운영 및 설치 과정에서 인가되지 않은 변경이 발생하지 않도록 안전한 메커니즘을 마련해야 하며, 배포된 소프트웨어/펌웨어가 설계된 대로 안전하게 설치되었음을 증명해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE05.04.01**: 암호모듈의 소프트웨어와 펌웨어 명세 및 안전한 배포, 운영, 설치 전 변경되지 않는 근거 제시

## 3. 작성 예시 (Examples)

### 3.1. 형상관리 및 배포 항목
"KISACrypto V1.0은 개발 완료 후 Git 기반의 자동화된 형상관리 시스템을 통해 관리되며, 배포 시 다음의 항목들을 포함한다."
1. **문서**: 기본 및 상세설계서, 형상관리문서, 시험서
2. **소스코드**: `*.c`, `*.h` 파일 (필요 시)
3. **최종 결과물**: 무결성 검증이 가능한 형태로 빌드된 바이너리 파일
4. **무결성 검증키**: 배포된 모듈의 위변조 확인용 키
5. **테스트 프로그램**: 암호모듈 정상 동작 확인용 검증 프로그램

### 3.2. 안전한 설치 절차 명세
"사용자(도입기관)는 배포된 암호모듈을 다음의 5단계 절차를 통해 안전하게 설치한다."
1. **해시값 비교**: 시험기관 홈페이지 등에 공시된 검증필 암호모듈의 해시값과 배포받은 파일의 해시값을 비교함.
2. **일치 여부 확인**: 두 값이 정확히 일치할 경우에만 설치 프로세스를 진행함.
3. **파일 복사**: 제공된 `dll` 또는 `so` 파일을 응용 프로그램이 참조하는 라이브러리 경로에 복사함.
4. **테스트 도구 설치**: 함께 배포된 Makefile을 이용하여 검증용 테스트 프로그램을 빌드 및 설치함.
5. **무결성 및 동작 확인**: 테스트 프로그램을 실행하여 동작 전 자가시험이 성공적으로 수행되는지 최종 확인함.

## 4. 구조도 및 시각 자료 (Visuals)
> **알림**: 본 항목은 별도의 아키텍처 다이어그램을 포함하지 않음. 
> **논리 흐름**: [Git 형상관리] → [배포 패키징] → [공식 해시값 공시] → [사용자 해시 검증] → [라이브러리 설치] → [자가시험 및 검증 완료]


## 5. 해설 및 증빙 가이드 (Guide)
- **생명주기 보증 연동**: 본 항목은 형상관리문서와 밀접하게 연관되므로, 배포되는 바이너리의 버전 정보가 형상관리 기록과 일치함을 증빙해야 함.
- **해시 검증의 강제성**: 설치 안내서(AG)에 해시값 비교 단계를 필수 과정으로 명시하여, 운영자가 설치 전 변조 여부를 반드시 확인하도록 유도해야 함.
- **배포 채널 보안**: 가능한 경우 보안이 유지되는 공식 채널이나 서명된 패키지 형태로 배포하여 배포 과정에서의 위협을 최소화할 것.
