# [AS05.05] 암호모듈 자체 또는 다른 검증필 암호모듈을 이용한 무결성 검증

## 1. 보안요구사항 개요
암호모듈의 모든 소프트웨어/펌웨어 구성 요소에 대해 자체적으로 또는 다른 검증필 암호모듈을 이용하여 무결성 검증을 수행해야 함. 검증에 사용되는 기법(인증 코드, 서명 등)과 검증키의 위치, 저장 방법 등을 상세히 명세해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE05.05.01**: 모든 소프트웨어/펌웨어 구성 요소에 대해 무결성 검증을 수행하는 근거와 방법 명세, 무결성 검증키의 위치 명세
- **VE05.05.02**: 모든 소프트웨어/펌웨어 구성 요소에 대해 단일 인증 코드나 서명에 대한 명세 또는 복수 인증 코드나 서명에 대한 명세
- **VE05.05.03**: 무결성 검증에 사용된 암호키의 저장 위치를 명세

## 3. 작성 예시

### 3.1. 작성예시 1: HMAC-SHA256 기반 무결성 검증
"KISACrypto V1.0 암호모듈은 자체적으로 HMAC-SHA256을 이용하여 소프트웨어 구성요소에 대한 무결성 검증을 수행한다. 사용되는 무결성검증키 K의 크기는 256비트이며, 메모리 덤프 등을 통한 키 노출을 방지하기 위해 암호모듈 내부에 분산 저장된다."

- **검증값 생성 (빌드 시)**: 자체 소프트웨어(`IntegrityGenSoftware.exe`)를 이용하여 모듈(M)의 HMAC-SHA256 값인 32바이트 무결성검증값(T)을 생성하고, 이를 모듈의 끝에 연접하여 최종 바이너리를 생성함.
- **검증 절차 (실행 시)**: 
    1. `KISA_Crypto_initialize()` 호출 시 `_Preself_test()` 내의 `_Integrity_test()` 실행.
    2. 분산 저장된 HMAC 키 K를 복원.
    3. 바이너리에서 모듈 파트 M과 연접된 검증값 T를 각각 로드.
    4. M과 K를 입력으로 하여 새로운 T'를 계산.
    5. T'와 T를 비교하여 일치 여부 확인.
    6. 검증 과정에서 생성된 중간 데이터(복원된 키, 복사된 버퍼 등)를 모두 제로화한 후 결과 반환.

### 3.2. 작성예시 2: RSA-PSS(3072-bit) 기반 무결성 검증
"KISACrypto V1.0 암호모듈은 자체적으로 RSA-PSS(3072-bit)를 이용하여 무결성 검증을 수행한다. 서명 생성 시에는 서명키 S가 사용되며, 검증 시에는 암호모듈 내부에 분산 저장된 서명검증키 V를 사용한다."

- **검증값 생성 (빌드 시)**: 서명키 S를 내장한 생성 도구를 통해 모듈 파트 M에 대한 384바이트 무결성검증값(서명 T)을 생성하여 모듈 끝에 연접함.
- **검증 절차 (실행 시)**:
    1. 초기화 과정에서 `_HASH_selftest()` 및 `_RSAPSS_selftest()`를 통해 알고리즘 정상 동작 확인(KAT).
    2. `_Integrity_test()` 함수를 통해 분산 저장된 검증키 V와 관련 파라미터 로드.
    3. 바이너리에서 M과 T를 로드하여 `Verify(V, M, T)` 함수 수행.
    4. 성공/실패 결과값을 반환하고 사용된 중간 데이터(V, M, T 등)를 모두 제로화함.

## 4. 구조도 및 시각 자료

### 4.1. [도식] 무결성 검증값 생성 및 최종 모듈 구성
- **입력**: 모듈파트 M + 무결성 검증키 (HMAC K 또는 RSA-PSS V)
- **도구**: `IntegrityGenSoftware.exe` (내부에 K 또는 S 보유)
- **출력**: 모듈파트 M 끝에 무결성 검증값 T가 연접된 최종 암호모듈 바이너리

### 4.2. [흐름도] 암호모듈 초기화 중 무결성 검증 과정
1. `KISA_Crypto_initialize()` 진입
2. `_Preself_test()` 호출
3. (필요 시) `_HASH_selftest()`, `_RSAPSS_selftest()` 등 알고리즘 KAT 수행
4. `_Integrity_test()` 호출: 키 복원 → 검증값 재계산 → 비교 → **중간 데이터 제로화** → 결과 반환

## 5. 해설 및 증빙 가이드
- **KAT 간소화**: GVI 지침에 따라 무결성 검증 기술 자체가 검증대상 알고리즘을 사용하고 저장된 검증값을 Known Answer로 사용하는 형식이므로, 무결성 시험은 그 자체로 KAT로 간주될 수 있음. 따라서 무결성 시험 이전에 해당 알고리즘에 대한 별도의 KAT를 선행하지 않아도 요건을 충족함.
- **분산 저장**: 키 노출 방지를 위해 무결성 검증키를 소스코드나 바이너리 내에 조각내어 분산 저장하는 로직을 명세하고, 이를 복원하는 과정을 상세히 기술해야 함.
- **제로화 필수**: 검증 과정에서 메모리에 로드되거나 복원된 키, 중간 연산 데이터 등은 검증 종료 즉시 제로화하여 잔류하지 않도록 설계해야 함.
