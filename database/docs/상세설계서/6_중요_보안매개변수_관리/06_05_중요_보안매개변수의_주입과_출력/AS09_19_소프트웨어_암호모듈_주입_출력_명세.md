# [AS09.19] 소프트웨어 암호모듈에 대한 주입/출력 명세

## 1. 보안요구사항 개요
소프트웨어 암호모듈이 중요보안매개변수(CSP)나 공개보안매개변수(PSP)를 주입받거나 출력할 때, 평문 또는 암호화된 형태의 구체적인 주입/출력 방법을 명세해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE09.19.01**: 소프트웨어 암호모듈의 경우, 평문 또는 암호화된 형태의 주입/출력 방법 명세

## 3. 작성 예시 (Examples)

### 3.1. 라이브러리형 암호모듈의 주입/출력 방식
"KISACrypto V1.0 암호모듈은 소프트웨어 라이브러리 형태의 암호모듈이다. 본 모듈은 응용 프로그램(Application)으로부터 암호 서비스 호출 시, API의 파라미터를 통해 CSP 및 PSP를 평문(Plaintext) 형식으로 입력받는다."

- **입력 방식**: 응용 프로그램이 모듈의 API(예: `KISA_LEA_Encrypt`)를 호출할 때, 메모리 상의 평문 키 데이터를 포인터 파라미터로 전달함.
- **출력 방식**: 연산 결과로 생성된 출력 데이터(예: 암호문, MAC 값 등)를 응용 프로그램이 지정한 메모리 버퍼에 평문 형식으로 기록하여 반환함.

## 4. 구조도 및 시각 자료 (Visuals)
> **알림**: 본 항목은 논리적 인터페이스 간의 데이터 이동에 집중함.
> **논리 흐름**: [응용 프로그램 메모리] → [API 파라미터(평문 CSP/PSP)] → [암호모듈 경계 진입] → [내부 연산 수행] → [결과값 반환]

## 5. 해설 및 증빙 가이드 (Guide)
- **보안수준별 요건**: 보안수준 1과 2의 소프트웨어 암호모듈은 운영체제(OS)의 가상 메모리 보호 기능을 통해 프로세스 독립성이 보장되는 경우(KS X ISO/IEC 19790 7.6.3 준수), 평문 형태의 주입 및 출력이 허용됨.
- **모듈 형태에 따른 적용**: 
    - **라이브러리형**: 응용 프로그램 프로세스 내에서 직접 데이터를 주고받으므로 평문 주입 방식을 주로 명세함.
    - **하이브리드/제품형**: 소프트웨어와 하드웨어 구성요소 간, 혹은 파일 시스템 저장 시 SSP가 이동할 수 있으므로 암호화된 주입/출력 메커니즘이 추가로 필요할 수 있음.
- **LEA 알고리즘 적용**: 수빈님이 구현 중인 LEA 알고리즘의 경우, 키(Key)와 평문(Plaintext)을 API 인자로 받을 때 평문 상태로 유입됨을 명시하고, 해당 데이터가 모듈 내부로 들어온 즉시 AS09.01~05에서 정의한 보호 정책을 따름을 기술할 것.
