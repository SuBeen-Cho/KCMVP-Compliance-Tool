# [AS09.29] 중요 보안매개변수(SSP)의 제로화 명세

## 1. 보안요구사항 개요
암호모듈 내부의 보호되지 않는 SSP가 사용 완료되거나 예외 상황이 발생했을 때, 이를 복구하거나 재사용할 수 없도록 물리적으로 제로화(Zeroization)하는 방법과 절차를 명세해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE09.29.01**: 제로화된 SSP가 어떻게 복구되거나 재사용될 수 없는지 명세

## 3. 작성 예시 (Examples)

### 3.1. 제로화 기본 원리 및 API (`KISA_Crypto_Zeroize`)
"본 모듈은 SSP가 저장된 메모리 공간을 해당 크기만큼 '0'으로 덧쓰는 방식을 사용한다. 특히 컴파일러 최적화로 인해 제로화 루틴이 생략되는 것을 방지하기 위해 `volatile` 키워드를 사용하여 최적화 예외 처리를 수행한다."

```c
void KISA_Crypto_Zeroize(void * ptr, int size)
{
    volatile unsigned char* p = ptr;
    while(size--)
    {
        *p++ = 0;
    }
}
```

### 3.2. 절차적 제로화 (Procedural Zeroization)
"API 내부에서 생성된 중간 데이터, 복사된 SSP 등을 API 반환 직전 혹은 오류 발생 시 즉시 파기하는 방법이다."

| 서비스 | SSP 유형 | 절차적 제로화 대상 |
| :--- | :--- | :--- |
| **블록 암호** | 라운드 키 및 임시 데이터 | `encryptFinal`, `decryptFinal` 내 사용 완료된 라운드 키 및 복사본 |
| **HMAC** | keyed ipad/opad 등 | `hmacFinal` 내 HMAC 키와 XOR된 ipad, opad 정보 |
| **HMAC_DRBG** | 엔트로피 및 내부 상태 | `drbgInit`, `drbgReseed` 시 사용된 잡음원 정보 및 임시 데이터 |
| **공개키/서명** | 난수 및 중간 연산값 | `genKeyPair`, `publicEncrypt`, `sign` 등에서 사용된 임시 난수 및 시드 |
| **키 설정(DH)** | 파라미터 및 중간값 | `genParameter`, `genKeyPair` 내 파라미터 생성을 위한 임시 데이터 |

### 3.3. 운영적 제로화 (Operational Zeroization)
"Long-term으로 사용되는 SSP(공개키, 개인키 등)에 대해 응용 프로그램에서 사용이 완료된 후 명시적으로 호출하여 파기하는 API를 제공한다."

1. **RSAES/RSA-PSS**: `KISA_Crypto_RSA_publicKey_Zeroize()`, `_privateKey_Zeroize()`
2. **ECDSA**: `KISA_Crypto_EC_publicKey_Zeroize()`, `_privateKey_Zeroize()`
3. **Diffie-Hellman**: `KISA_Crypto_DH_param_Zeroize()`, `_publicKey_Zeroize()`, `_privateKey_Zeroize()`
4. **일반 난수**: `KISA_Crypto_Zeroize()`

## 5. 해설 및 증빙 가이드 (Guide)
- **최적화 방지 증빙**: 심사 시 `volatile` 키워드 사용 여부와 실제 어셈블리 코드에서 제로화 루틴이 살아있는지 확인하므로, 소스코드의 해당 위치를 명확히 제시해야 함.
- **오류 발생 시 처리**: 정상 종료 시뿐만 아니라, `if(rv != 0)`와 같은 에러 핸들링 구문(goto error 등)에서도 제로화 함수가 반드시 호출되도록 설계되어야 함.
- **LEA 알고리즘 적용**: 수빈님이 진행 중인 LEA 알고리즘 프로젝트의 경우, 라운드 키가 생성되는 `LEA_KeySchedule` 이후 연산이 끝나는 시점에 해당 라운드 키 메모리를 `KISA_Crypto_Zeroize`로 지우는 로직을 포함시키고 이를 표에 추가할 것.
- **소스코드 위치 명세**: 해설에 언급된 대로 제로화가 적용된 소스코드의 파일명과 라인 넘버를 함께 제공하면 증빙의 명확성이 크게 향상됨.
