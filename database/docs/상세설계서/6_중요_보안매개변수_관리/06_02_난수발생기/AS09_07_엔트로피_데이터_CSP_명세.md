# [AS09.07] 암호 경계 외부 엔트로피 입력 데이터의 CSP 명세

## 1. 보안요구사항 개요
암호 경계 외부(운영체제 등)로부터 수집된 엔트로피 잡음원과 이를 이용하여 생성된 모든 내부 상태 및 출력 난수열을 중요보안매개변수(CSP)로 간주하여 보안 요구사항에 따라 엄격히 관리해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE09.07.01**: 암호 경계 외부에서 수집된 엔트로피로부터 생성된 데이터에 대해 CSP로 명세 필요

## 3. 작성 예시 (Examples)

### 3.1. 엔트로피 수집 및 CSP 관리 로직
"KISACrypto V1.0은 윈도우 및 리눅스와 같이 신뢰된 범용 운영체제에서 동작하는 소프트웨어 라이브러리형 암호모듈이다. 본 모듈은 난수발생기에 사용되는 잡음원을 수집하기 위해 운영체제가 제공하는 시스템 API를 이용한다."

- **초기화 단계**: 시스템 API를 통해 수집된 잡음원은 난수발생기의 시드(Seed)로 사용되어 내부 상태를 구성한다. 이때 수집된 원본 잡음원은 CSP로 간주되며, 내부 상태 구성이 완료된 직후 즉시 메모리에서 제로화된다.
- **난수 생성 단계**: 난수발생기의 내부 상태를 통해 생성 및 출력된 난수열 역시 CSP로 간주되어 암호모듈 내부에서 처리된다. 해당 난수열은 사용이 완료된 후 즉시 제로화 과정을 거친다.
- **종료 단계**: 난수발생기의 사용이 최종적으로 완료되면, 잡음원으로부터 구성되었던 난수발생기의 모든 내부 상태 정보를 메모리에서 제로화하여 파기한다.

## 5. 해설 및 증빙 가이드 (Guide)
- **비결정론적 데이터 보호**: 엔트로피 잡음원은 난수발생기의 내부 상태를 결정짓는 핵심적인 비결정론적 데이터이므로, 유출될 경우 난수 예측이 가능해짐. 따라서 사용 직후의 제로화 절차를 반드시 설계서에 명시해야 함.
- **출력값의 CSP 지정**: 생성된 난수열이 단순히 데이터로 취급되는 것이 아니라, 비밀키 생성의 원천이 되는 CSP임을 명확히 기술해야 함.
- **시스템 API 명시**: 윈도우의 `CryptGenRandom`이나 리눅스의 `/dev/urandom` 등 엔트로피를 가져오는 구체적인 시스템 함수를 함께 언급하면 증빙의 구체성이 높아짐.
