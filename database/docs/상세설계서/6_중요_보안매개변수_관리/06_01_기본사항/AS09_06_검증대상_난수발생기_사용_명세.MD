# [AS09.06] 검증대상 난수발생기 사용 명세

## 1. 보안요구사항 개요
암호모듈 내에서 사용되는 모든 핵심 보안 매개변수(SSP) 생성 시, 검증대상 알고리즘으로 승인된 난수발생기(DRBG)를 사용해야 하며, 이에 대한 목록, 사용법 및 실제 소스코드 상의 적용 증빙을 명세해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE09.06.01**: 난수발생기의 목록과 사용법 및 난수 생성과 설정 시 검증대상 난수발생기를 사용했다는 증빙 명세
- **VE09.06.02**: SSP 생성 및 설정 시 검증대상 난수발생기 사용 여부 확인

## 3. 작성 예시 (Examples)

### 3.1. 검증대상 난수발생기(DRBG) 개요
"KISACrypto V1.0은 TTAK.KO-12.0332 표준을 준수하는 HMAC_DRBG(HMAC-SHA256)를 제공한다. 본 난수발생기는 예측 내성(Prediction Resistance) 기능을 지원하며, 초기화(`drbgInit`), 갱신(`drbgReseed`), 생성(`drbgGenerate`), 소멸(`drbgClose`)의 생명주기를 가진다."

### 3.2. [표] SSP 생성 및 설정 시 난수발생기 적용 증빙
| 서비스 | 용도 | 관련 API | 소스코드 정보 (파일명 및 관련 코드) |
| :--- | :--- | :--- | :--- |
| **블록암호 (LEA/SEED)** | 비밀키, IV 생성 | `KISA_Crypto_drbgGenerate()` | `KISA_drbg.c` -> `hmac_drbgGenerate()` |
| **공개키 암호 (RSAES)** | 키쌍 생성, 암호화 | `KISA_Crypto_genKeyPair()` | `KISA_rsa.c` -> `BN_gen_prime()` -> `hmac_drbgGenerate()` |
| **전자서명 (RSA-PSS)** | 키쌍, 서명(Salt) 생성 | `KISA_Crypto_sign()` | `KISA_rsa.c` -> `BN_gen_salt()` -> `hmac_drbgGenerate()` |
| **키 설정 (DH)** | 파라미터, 키쌍 생성 | `KISA_Crypto_DH_genKeyPair()` | `KISA_dh.c` -> `BN_gen_prime()` -> `hmac_drbgGenerate()` |

## 4. 구조도 및 시각 자료 (Visuals)
> **설계 핵심**: 엔트로피와 논스(Nonce)를 입력받아 내부 상태를 구성하고, `Generate` 함수 호출 시마다 내부 상태를 갱신하여 출력 난수의 예측 불가능성을 보장함. 사용 완료 후 `Close` 함수를 통해 내부 상태(V, Key)를 메모리에서 제로화함.

## 5. 해설 및 증빙 가이드 (Guide)
- **표준 적합성**: 본 항목은 AS09.05와 연계되어 증빙 가능하며, 난수발생기의 설계가 표준(NIST SP 800-90A 또는 TTAK 표준)에 의거했음을 소스코드 수준에서 증명해야 함.
- **코드 매핑의 구체성**: 단순히 API 이름만 적는 것이 아니라, 위 표와 같이 실제 소스파일명(`KISA_rsa.c`)과 내부 호출 함수(`BN_gen_prime`)를 명시하여 난수발생기가 SSP 생성의 '소스'로 사용됨을 명확히 증빙해야 함.
- **예측 내성(PR) 활용**: 예측 내성이 활성화된 경우, 난수를 생성하기 전 항상 리시드(Reseed) 과정을 수행하여 엔트로피를 보강하는 로직이 구현되어 있는지 확인이 필요함.
- **LEA 알고리즘 연동**: 수빈님이 진행 중인 LEA 대칭키 알고리즘 프로젝트에서도 키 생성 시 반드시 본 설계서에 정의된 `KISA_Crypto_drbgGenerate()`를 호출하도록 소스코드를 구성해야 심사를 통과할 수 있음.
