# [LEA.015] 암호문 최종 대입

## 1. 보안요구사항 개요
LEA 암호화 알고리즘 1의 마지막 단계로, Nr번 라운드 함수 수행 후 최종 상태값 X_Nr을 암호문 바이트 배열 C에 대입하며, 워드 배열에서 바이트 배열로의 변환 규약(리틀엔디언)을 적용한다.

## 2. 상세 요구사항 (Requirements)
- **LEA-037**: 암호화 라운드 함수를 Nr번 반복 수행한 후, 최종 상태값 X\_Nr = (X\_Nr[0], X\_Nr[1], X\_Nr[2], X\_Nr[3])을 128비트 암호문 C(바이트 배열)로 변환하여 대입해야 한다. 변환은 `C ← X_Nr` 형태이며, 리틀엔디언 바이트 순서를 따른다.

## 3. 작성 예시 (Examples)
### 3.1. 의사코드 예시

```
// 알고리즘 1 — 암호화 (마지막 단계)
// (Step 1~4가 완료된 후)

Step 5: C ← X_Nr
  // 워드 배열 → 바이트 배열 변환 (리틀엔디언)
  // c[0..3]   = X_Nr[0] 의 바이트 분해
  // c[4..7]   = X_Nr[1] 의 바이트 분해
  // c[8..11]  = X_Nr[2] 의 바이트 분해
  // c[12..15] = X_Nr[3] 의 바이트 분해
```

### 3.2. C 코드 예시

```c
void lea_encrypt(const uint8_t P[16], const uint32_t RK[][6], int Nr, uint8_t C[16]) {
    uint32_t X[4];

    memcpy(X, P, 16);                     // Step 1: X_0 ← P

    for (int i = 0; i < Nr; i++) {         // Step 2~4: 라운드 반복
        lea_round_enc(X, RK[i]);
    }

    memcpy(C, X, 16);                     // Step 5: C ← X_Nr
}
```

### 3.3. 표 형식 예시 — 워드-바이트 매핑

| 워드 | 출력 바이트 인덱스 | 리틀엔디언 분해 |
| :--- | :--- | :--- |
| X\_Nr[0] | c[0], c[1], c[2], c[3] | LSB → c[0], MSB → c[3] |
| X\_Nr[1] | c[4], c[5], c[6], c[7] | LSB → c[4], MSB → c[7] |
| X\_Nr[2] | c[8], c[9], c[10], c[11] | LSB → c[8], MSB → c[11] |
| X\_Nr[3] | c[12], c[13], c[14], c[15] | LSB → c[12], MSB → c[15] |

### 4.2. 변환 과정 설명
최종 상태값 X\_Nr의 4개 32비트 워드는 순서대로 16바이트 암호문 배열 C에 매핑된다. 리틀엔디언 플랫폼에서는 `memcpy(C, X, 16)` 한 줄로 변환이 완료된다.

## 5. 해설 및 증빙 가이드 (Guide)
- **초기화 단계(X₀ ← P)와의 대칭성**: 초기화에서 바이트→워드 변환을 수행했으므로, 최종 단계에서는 역방향(워드→바이트) 변환을 수행한다. 두 과정의 엔디언 규칙이 일치해야 한다.
- **라운드 수 검증**: Nr은 키 길이에 따라 24(128비트), 28(192비트), 32(256비트)이다. Nr이 잘못 설정되면 최종 상태값이 틀어진다.
- **출력 버퍼 크기**: 암호문 C는 반드시 128비트(16바이트) 이상의 버퍼여야 한다. 블록 크기보다 작은 버퍼는 버퍼 오버플로우를 초래한다.
- **KAT 검증과의 관계**: 이 단계의 출력값이 KAT(기지 답안 검사) RESPONSE 파일의 CT 값과 일치하는지 대조하여 구현 정확성을 확인한다.
- **참고 규격**: LEA 표준 규격서 §5.2.1 알고리즘 1.
