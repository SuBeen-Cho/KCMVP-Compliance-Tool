# [LEA.005] 비트 색인 규약

## 1. 보안요구사항 개요
LEA에서 워드 내 비트 색인은 31(MSB)에서 0(LSB)으로 매핑되며, 바이트 배열·워드 배열·워드 내 비트 간의 관계가 표준 규격서 <표 4-3>에 정의된 규약을 정확히 따라야 한다.

## 2. 상세 요구사항 (Requirements)
- **LEA-006**: 워드 내 비트 색인은 최상위 비트(MSB)를 31, 최하위 비트(LSB)를 0으로 매핑해야 한다. 바이트 배열 인덱스, 워드 배열 인덱스, 워드 내 비트 색인의 3단계 관계가 표준 규격서 <표 4-3>의 정의를 준수해야 한다.

## 3. 작성 예시 (Examples)
### 3.1. 표 형식 예시 (비트 색인 매핑 - <표 4-3> 참조)

| 바이트 배열 인덱스 | 3 | 2 | 1 | 0 |
| :--- | :---: | :---: | :---: | :---: |
| **워드 배열 인덱스** | 0 | 0 | 0 | 0 |
| **워드 내 비트 색인** | 31 ... 24 | 23 ... 16 | 15 ... 8 | 7 ... 0 |
| **비트 역할** | MSB 영역 | - | - | LSB 영역 |

### 3.2. 상세 매핑 예시

| 바이트 A[i] | 바이트 내 비트 (MSB→LSB) | 워드 B[0] 내 비트 위치 |
| :---: | :---: | :---: |
| A[0] | bit7 ... bit0 | bit7 ... bit0 |
| A[1] | bit7 ... bit0 | bit15 ... bit8 |
| A[2] | bit7 ... bit0 | bit23 ... bit16 |
| A[3] | bit7 ... bit0 | bit31 ... bit24 |

### 3.3. 서술형 예시
"LEA 워드의 비트 색인은 MSB=31, LSB=0으로 정의한다. 바이트 배열 A[0]의 비트들은 워드 B[0]의 bit0~bit7에 대응하고, A[3]의 비트들은 bit24~bit31에 대응한다. 이는 리틀 엔디안 바이트 순서와 일관된 비트 색인 규약이다."

## 4. 구조도 및 시각 자료 (Visuals)

```
워드 B[0] (32비트):
┌──────────┬──────────┬──────────┬──────────┐
│ bit31-24 │ bit23-16 │ bit15-8  │ bit7-0   │
│  A[3]    │  A[2]    │  A[1]    │  A[0]    │
│  (MSB)   │          │          │  (LSB)   │
└──────────┴──────────┴──────────┴──────────┘
```

비트 번호가 증가할수록 상위 바이트에 대응하며, 이 구조는 회전 연산(ROL/ROR) 시 비트 이동 방향의 기준이 된다.

## 5. 해설 및 증빙 가이드 (Guide)
- **비트 순서 혼동 주의**: 일부 문서에서 MSB=0으로 표기하는 경우가 있으나, LEA 표준은 MSB=31을 사용한다. 구현 및 설계서에서 비트 순서가 혼동되지 않도록 주의한다.
- **회전 연산과의 관계**: ROL(왼쪽 회전)은 비트 색인이 증가하는 방향으로 이동하는 연산이다. 비트 색인 규약이 올바르지 않으면 회전 방향이 반대로 구현될 수 있다.
- **증빙 시 주안점**: 테스트 벡터에서 각 바이트의 비트 위치가 표준과 일치하는지 확인하고, 특히 회전 연산 결과가 예상값과 동일한지 검증한다.
- **참고 규격**: LEA 표준 규격서 <표 4-3>.
