# [AS04.43] 리셋, 재부팅, 전원 재인가 후 운영자 인증 방법 명세

## 1. 보안요구사항 개요
암호모듈의 전원이 종료되거나 리셋, 재부팅되는 경우, 이전에 유지되던 운영자의 인증 상태가 완전히 소멸되어야 함을 명세해야 함. 재시작 후에는 반드시 새로운 인증 절차를 거쳐야만 모듈에 접근할 수 있어야 함.

## 2. 상세 요구사항 (Requirements)
- **VE04.43.01**: 암호모듈의 전원 종료 시, 이전 인증을 소멸하는 방법 명세

## 3. 작성 예시 (Examples)

### 3.1. 서술형 예시 (소프트웨어 라이브러리형)
"KISACrypto V1.0은 보안수준 1 소프트웨어 라이브러리 형태의 암호모듈이기 때문에 자체적인 인증메커니즘을 포함하지 않는다. 즉, 암호모듈은 자체적인 인증방법을 제공하지 않으며 운영체제가 제공하는 인증에 의존하기 때문에 운영체제 인증이 초기화되기 이전에 본 모듈에 접근하는 것은 불가능하다. 본 암호 모듈은 수행되는 서비스에 따라 논리적으로 분리되며, 그 역할에 따라 암묵적으로 인증된다. 이때 운영체제의 인증에 실패한 암호 관리자는 본 암호모듈의 서비스를 수행할 수 없다. 본 암호모듈이 동작하는 범용 운영환경(윈도우, 리눅스)에서는 사용자가 로그오프를 하거나 운영체제 종료 시 이전에 인증된 정보를 적절히 제거하는 기능이 탑재되어 있다."

## 4. 구조도 및 시각 자료 (Visuals)
> **알림**: 본 항목은 별도의 아키텍처 다이어그램을 포함하지 않음. 
> **논리 흐름**: [전원 종료/리셋] → [메모리 내 인증 세션 파기] → [운영체제 인증 정보 초기화] → [재부팅 후 신규 인증 요구] → [인증 성공 시 서비스 접근 허용]

## 5. 해설 및 증빙 가이드 (Guide)
- **운영환경 의존성**: 라이브러리 형태의 암호모듈은 운영환경(OS)의 인증에 의존하므로, OS 차원의 로그오프나 종료 시 인증 정보가 제거되는 메커니즘을 근거로 제시할 수 있음.
- **인증 정보 제로화**: 제품형 암호모듈이나 자체 인증을 사용하는 경우, 모듈 종료 시 메모리 상에서 관리되던 사용자의 인증 정보(비밀번호, 토큰 등)를 적절히 제로화(Zeroization)하는 절차를 상세히 기술해야 함.
- **재인증 강제**: 리셋 또는 전원 재인가 이후 별도의 절차 없이 이전 인증 상태가 유지되지 않음을 논리적으로 입증하여 비인가자의 접근 가능성을 원천 차단해야 함.
