# [AS04.44] 암호모듈 내의 인증데이터에 대한 보호

## 1. 보안요구사항 개요
암호모듈 내부에서 관리되는 모든 인증 데이터(비밀번호, 생체 정보, 토큰 등)가 비인가자에게 노출되거나 수정, 대체되지 않도록 보호하는 방법을 명세해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE04.44.01**: 암호모듈 내의 모든 인증 데이터를 보호하는 방법을 명세

## 3. 작성 예시 (Examples)

### 3.1. 서술형 예시 (소프트웨어 라이브러리형 - 보안수준 1)
"KISACrypto V1.0은 보안수준 1 소프트웨어 라이브러리 형태의 암호모듈이기 때문에 자체적인 인증메커니즘을 포함하지 않는다. 따라서, 내부적으로 사용자의 인증 데이터를 저장하는 메모리를 포함하지 않는다."

## 4. 구조도 및 시각 자료 (Visuals)
> **알림**: 본 항목은 별도의 아키텍처 다이어그램을 포함하지 않음. 
> **논리 흐름**: [인증 요청] → [운영환경(OS) 인증 메커니즘 활용] → [모듈 내 별도 인증 데이터 저장소 부재 확인] → [인증 데이터 유출 가능성 원천 차단]


## 5. 해설 및 증빙 가이드 (Guide)
- **라이브러리형 대응**: 보안수준 1의 라이브러리형 모듈은 운영환경의 인증에 의존하므로, 예시와 같이 "자체 저장 공간이 없음"을 명시하여 데이터 보호 요건을 간접적으로 충족할 수 있음.
- **제품형/고수준 모듈**: 자체 인증 기능을 가진 경우, 인증 데이터를 검증대상 암호알고리즘으로 암호화하여 저장하거나, 무결성 검증 과정을 통해 변조 여부를 확인하는 메커니즘을 상세히 명세해야 함.
- **보호 범위**: 인증 데이터에 대한 노출(Confidentiality), 수정(Integrity), 대체(Substitution)로부터 안전하도록 설계되었음을 증명하는 것이 핵심임.
