# [AS04.13] 버전 출력 서비스 명세

## 1. 보안요구사항 개요
암호모듈의 명칭과 버전 정보를 출력하는 서비스를 정의하고, 해당 정보가 한국인터넷진흥원(KISA)의 검증 목록에 기재된 정보와 어떻게 연관되는지 상세설계서, 보안정책서, 안내서 등에 명확히 명세해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE04.13.01~02**: 암호모듈 명칭과 버전 정보를 출력하는 서비스 명세
- **VE04.13.03**: 개발 문서, 보안정책서, 안내서에 암호모듈의 이름과 버전 정보가 검증 목록과 어떻게 연관되는지 명세

## 3. 작성 예시 (Examples)

### 3.1. 서술형 예시
"KISACrypto V1.0은 `KISA_Crypto_getVersion()` API를 통해 아래와 같이 암호모듈의 명칭과 버전 정보를 출력하는 서비스를 제공한다. 해당 서비스는 별도의 인가 없이 관리자와 사용자 모두 호출 가능하다."

### 3.2. 버전 출력 결과 예시 (Output)
```text
KCMVP_Initialize()
KISACrypto V1.0
Developed by KISA
```

## 4. 구조도 및 시각 자료 (Visuals)
> **알림**: 본 항목은 별도의 아키텍처 다이어그램을 포함하지 않음. 
> **논리 흐름**: [운영자/사용자의 버전 확인 요청] → [KISA_Crypto_getVersion() API 호출] → [모듈 내부의 고정된 명칭 및 버전 정보 추출] → [사용자 인터페이스로 결과값 반환]

## 5. 해설 및 증빙 가이드 (Guide)
- **검증 목록과의 일치성**: API를 통해 출력되는 명칭과 버전 번호는 반드시 KISA 검증 대상 목록에 등록된 공식 명칭 및 버전과 토씨 하나 틀리지 않고 일치해야 함.
- **문서 간 일관성**: 본 조항에서 요구하는 버전 출력 서비스의 수행 방법과 결과는 상세설계서뿐만 아니라 **보안정책서(SP)**와 **사용자 안내서(AG)**에도 동일하게 포함되어야 함을 유의할 것.
- **연관성 명세**: 출력되는 정보가 검증 받은 제품임을 식별할 수 있는 유일한 식별자임을 설명하고, 형상 관리 문서와의 연관 관계를 함께 제시하는 것이 권장됨.
