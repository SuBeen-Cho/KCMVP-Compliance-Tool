# [AS04.02] 동시 운영자의 지원 여부 및 방법 명세

## 1. 보안요구사항 개요
암호모듈이 여러 명의 운영자가 동시에 접속하여 서비스를 사용하는 '동시 운영자' 기능을 지원하는지 여부를 명시하고, 지원할 경우 각 운영자의 역할과 서비스를 분리하여 유지하는 방법을 상세히 명세해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE04.02.01**: 동시 운영자 지원 여부, 지원 시 각 동시 운영자에 대한 역할과 서비스를 구분하여 유지하는 방법 명세

## 3. 작성 예시 (Examples)

### 3.1. 서술형 예시 (소프트웨어 라이브러리형)
"KISACrypto V1.0은 소프트웨어 라이브러리 형태의 암호모듈로서 여러 응용 프로그램에게 범용적인 암호 서비스를 제공하는 것을 목표로 한다. 본 모듈은 보안수준 1에 해당하여 자체적인 인증 메커니즘을 탑재하지 않고 운영환경(OS)에서 제공하는 보호 메커니즘을 활용한다. 따라서, 암호모듈 자체적으로는 동시 운영자 기능을 지원하지 않으며 내부적으로 운영자 정보를 관리하지 않는다. 다만, 호출하는 암호 서비스에 따라 암호 관리자 역할과 사용자 역할을 논리적으로 분리하여 지원한다."

## 4. 구조도 및 시각 자료 (Visuals)
> **알림**: 본 항목은 별도의 아키텍처 다이어그램을 포함하지 않음. 
> **논리 흐름**: [운영환경(OS) 로그인] → [응용 프로그램 실행] → [암호모듈 로드] → [API 호출 기반 역할 분리] → [단일 세션 서비스 제공]


## 5. 해설 및 증빙 가이드 (Guide)
- **라이브러리형의 특성**: 범용 SW 라이브러리는 보통 운영자 정보를 직접 유지하기 어렵기 때문에, 예시와 같이 "동시 운영자 지원이 어렵다"고 명시하는 것이 일반적임.
- **역할 분리 강조**: 동시 운영은 지원하지 않더라도, 관리자(Crypto Officer)와 사용자(User) 역할이 API 호출에 따라 어떻게 논리적으로 구분되는지는 반드시 언급해야 함.
- **제품형 모듈의 경우**: 만약 자체 인증 메커니즘을 가진 제품형 모듈이라면, 세션 관리나 토큰 등을 통해 동시 운영자를 어떻게 식별하고 관리하는지 상세히 기술해야 함.
