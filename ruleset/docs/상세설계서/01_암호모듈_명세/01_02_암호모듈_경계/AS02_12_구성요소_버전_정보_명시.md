# [AS02.12] 구성요소에 대한 버전 정보 명시

## 1. 보안요구사항 개요
암호모듈의 각 구성요소(실행 파일, 라이브러리 등)에 대한 구체적인 버전 정보를 명세하여 검증 대상의 정체성을 명확히 해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE02.12.01**: 구성요소에 대한 버전 정보

## 3. 작성 예시 (Examples)

### 3.1. [표] 암호모듈의 구성요소 버전 정보 예시
| 구분 | 운영환경 | 구성 형태 | 비고 |
| :--- | :--- | :--- | :--- |
| **SW** | Windows 10 32-bit | KISACrypto32.dll | KISACrypto V1.0 <br> (무결성검증 데이터는 암호모듈에 포함됨) |
| **SW** | Windows 10 64-bit | KISACrypto64.dll | KISACrypto V1.0 <br> (무결성검증 데이터는 암호모듈에 포함됨) |
| **SW** | Ubuntu 24.04 64-bit | libKISACrypto64.so | KISACrypto V1.0 <br> (무결성검증 데이터는 암호모듈에 포함됨) |

> **논리 흐름**: [운영환경 식별] → [플랫폼별 구성 형태 매칭] → [형상 관리 버전(V1.0) 부여] → [무결성 검증 데이터 포함 관계 정의]

## 5. 해설 및 증빙 가이드 (Guide)
- **버전 명세**: 암호모듈 전체의 버전뿐만 아니라, 각 운영환경별로 배포되는 개별 파일(dll, so 등)의 버전 정보를 상세설계서에 명확히 기술해야 함.
- **무결성 데이터 확인**: 비고란에 기재된 것과 같이, 무결성 검증 값이 모듈 내부에 포함되어 있는지 또는 별도의 파일로 존재하는지를 반드시 명시해야 심사 시 혼선을 방지할 수 있음.
- **일관성**: AS02.11에서 정의한 모듈 명칭과 버전 정보가 모든 제출 문서에서 일관되게 사용되는지 확인이 필요함.
