# [AS02.11] 적절한 명칭의 사용 필요

## 1. 보안요구사항 개요
암호모듈의 명칭은 개발 주체와 용도를 명확히 식별할 수 있도록 부여되어야 하며, 실제 암호경계 내 구성 요소의 범위를 오해하게 만드는 광범위한 명칭을 사용해서는 안 됨.

## 2. 상세 요구사항 (Requirements)
- **VE02.11.01**: 적절한 명칭 사용의 근거 제시

## 3. 작성 예시 (Examples)

### 3.1. 서술형 예시
"KISACrypto V1.0 암호모듈은 검증대상 암호알고리즘만을 탑재한 범용 소프트웨어 라이브러리형 암호모듈이다. 한국인터넷진흥원(KISA)에서 개발하여, 개발 기관 명과 암호 기능의 목적을 모두 포함하여 'KISACrypto'라고 명명한다."

## 4. 구조도 및 시각 자료 (Visuals)
> **알림**: 본 항목은 별도의 아키텍처 다이어그램을 포함하지 않음. 
> **논리 흐름**: [개발주체/용도 식별] → [명칭 후보 생성] → [경계 범위 일치 여부 검토] → [최종 명칭 확정]

## 5. 해설 및 증빙 가이드 (Guide)
- **식별성 확보**: 암호모듈 명칭 부여 시 개발업체명과 제품의 용도(Crypto, Cipher, Hash 등)를 확인 할 수 있는 키워드를 포함하는 것이 권장됨.
- **명칭의 범위 제한**: 암호경계 내부에 있는 구성 요소의 실제 조합보다 더 큰 범위의 제품이나 시스템 전체를 의미하는 명칭(예: 전사 보안 시스템, 통합 네트워크 등)을 사용하지 않도록 주의해야 함.
- **버전 관리**: 명칭과 함께 버전 번호를 명시하여 검증 대상 모듈을 명확히 특정해야 함.
