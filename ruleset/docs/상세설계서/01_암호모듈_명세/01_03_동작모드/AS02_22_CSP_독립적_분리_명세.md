# [AS02.22] 동작모드간, 서비스 간 CSP에 대한 독립적 분리 필요

## 1. 보안요구사항 개요
암호모듈 내의 서로 다른 동작모드(검증대상/비검증대상) 및 서비스 간에 사용되는 핵심보안매개변수(CSP)가 논리적/물리적으로 독립적으로 분리되어야 하며, 모드 전환 시 기존 CSP가 유출되거나 오용되지 않도록 관리되어야 함.

## 2. 상세 요구사항 (Requirements)
- **VE02.22.01**: 동작모드/서비스 별 사용되는 CSP 명세 필요
- **VE02.22.02**: 동작모드/서비스 간 CSP가 분리되는 방법 명세 필요

## 3. 작성 예시 (Examples)

### 3.1. 서술형 예시
"KISACrypto V1.0은 검증대상 동작모드만을 지원하며, 검증대상 동작모드에서 지원하는 검증대상 암호알고리즘 및 관련 CSP 목록은 AS02.20에서 제시하였다. 본 모듈은 단일 동작모드 체계로 운영되므로 모드 간 CSP 간섭이 발생하지 않으며, 각 암호 서비스 호출 시 메모리 할당 및 해제 과정을 통해 서비스 간 CSP 독립성을 보장한다."

## 4. 구조도 및 시각 자료 (Visuals)
> **알림**: 본 항목은 별도의 아키텍처 다이어그램을 포함하지 않음. 
> **논리 흐름**: [동작모드 확인] → [서비스별 사용 CSP 식별] → [메모리 영역 분리 할당] → [모드/서비스 종료 시 CSP 제로화] → [독립적 분리 상태 유지]

## 5. 해설 및 증빙 가이드 (Guide)
- **모드 전환 시 보호**: 만약 검증대상 동작모드와 비검증대상 동작모드를 모두 지원하는 경우, 모드 간 천이 시 기존 모드에서 사용하던 CSP를 독립적으로 분리하거나 파기하는 방법을 상세히 명세해야 함.
- **제로화(Zeroization)**: 모드 전환 시 가장 대표적인 분리 방법은 '제로화'임. 기존 메모리 영역을 0으로 덮어쓰는 등의 구체적인 제로화 메커니즘을 상세설계서에 기술할 것.
- **서비스 간 격리**: 동일 모드 내에서도 서로 다른 암호 서비스(예: AES 연산 vs RSA 연산) 간에 CSP가 혼용되지 않도록 프로세스나 메모리 차원에서의 격리 방안을 제시해야 함.
- **일관성 체크**: 본 항목에서 명세하는 CSP 목록은 반드시 AS02.20(알고리즘 명세)에서 정의한 목록과 일치해야 함.
