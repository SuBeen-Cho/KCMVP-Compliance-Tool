# [AS09.04] 패스워드 해시값, 난수발생기 상태 정보 및 키 생성 중간값의 CSP 관리

## 1. 보안요구사항 개요
패스워드의 해시값, 난수발생기의 내부 상태 정보, 엔트로피, 시드값 및 키 생성 과정에서 발생하는 중간값들을 중요보안매개변수(CSP)로 간주하고, 이를 안전하게 관리 및 파기하는 메커니즘을 명세해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE09.04.01**: 패스워드의 해시값, 난수발생기의 상태 정보 및 키 생성 중간값에 대해 CSP로서 안전하게 관리하는 지에 대한 명세

## 3. 작성 예시 (Examples)

### 3.1. CSP 식별 및 처리 원칙
"KISACrypto V1.0 암호모듈은 다음의 정보들을 CSP로 인식하여 관리하며, 사용 완료 후 즉각적인 제로화를 통해 인가되지 않은 접근 및 유출을 방지한다."

- **대상 항목**: 엔트로피(Entropy), 시드(Seed) 값, 난수발생기 내부 상태, 키 생성 중 발생하는 임시 중간값 등.
- **단계별 제로화 절차**:
    1. **난수발생기 초기화**: 수집된 잡음원(Entropy)으로부터 난수발생기 내부 상태를 생성한 직후, 원본 잡음원 데이터를 메모리에서 즉시 제로화함.
    2. **서비스 종료 시**: 난수발생기의 사용이 완료되거나 키 생성 연산이 끝난 후, 메모리에 남아 있는 내부 상태 및 모든 중간값을 전용 제로화 API를 통해 파기함.

## 4. 구조도 및 시각 자료 (Visuals)
> **알림**: 본 항목은 데이터의 논리적 관리 범주에 집중함.
> **논리 흐름**: [원시 데이터 수집] → [CSP 인식 및 메모리 할당] → [연산 수행] → [중간 결과값 생성] → [사용 완료 즉시 제로화 수행] → [자원 반환]

## 5. 해설 및 증빙 가이드 (Guide)
- **누락 주의 CSP**: 패스워드 해시값이나 난수발생기의 내부 상태 정보는 설계 시 CSP 정의에서 누락되기 쉬운 항목이므로, 관리 대상 목록에 명시적으로 포함되어야 함.
- **동적 데이터의 처리**: 알고리즘 동작 중 일시적으로 생성되는 난수값들도 보안 맥락에 따라 CSP로 관리될 필요가 있으며, 해당 데이터들의 생명주기(생성~소멸)가 설계서에 반영되어야 함.
- **제로화의 적시성**: '사용이 끝난 직후'라는 시점을 코드 레벨에서 명확히 정의하고, 지체 없이 제로화 함수가 호출됨을 증빙하는 것이 심사의 핵심임.
