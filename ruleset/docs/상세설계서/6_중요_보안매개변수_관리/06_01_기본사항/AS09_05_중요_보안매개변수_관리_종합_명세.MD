# [AS09.05] KS X ISO/IEC 19790:2015 A.2.9에 대한 명세

## 1. 보안요구사항 개요
중요보안매개변수(CSP) 및 공개보안매개변수(PSP)의 전체 생명주기(생성, 설정, 주입, 출력, 저장, 제로화)에 대한 설계 및 관리 방법을 KS X ISO/IEC 19790 표준에 의거하여 상세히 명세해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE09.05.01**: KS X ISO/IEC 19790:2015의 A.2.9에 명세된 요구사항을 충족하는 설계서 제공

## 3. 작성 예시 (Examples)

### 3.1. 난수발생기(DRBG) 설계 및 API 명세
"KISACrypto V1.0은 HMAC_DRBG(HMAC-SHA-256)를 탑재하여 예측 내성(PR)을 지원한다. 시드값은 논스, 잡음원, 개별화 문자열을 조합하여 생성하며, 리시드(Reseed) 카운터를 통해 내부 상태를 주기적으로 갱신한다."

| API 명 | 주요 설명 |
| :--- | :--- |
| **KISA_Crypto_drbgInit()** | 논스, 잡음원 등을 입력받아 시드값 생성 및 내부 상태 초기화 |
| **KISA_Crypto_drbgReseed()** | 추가 잡음원을 수집하여 DRBG의 내부 상태를 강제 갱신 |
| **KISA_Crypto_drbgGenerate()** | 요청된 길이의 난수 비트열 생성 및 내부 상태 자동 갱신 |
| **KISA_Crypto_drbgClose()** | 사용된 메모리 및 내부 상태값을 제로화 후 종료 |
| **KISA_Crypto_drbgRand()** | 초기화-생성-제로화를 한 번에 수행하는 일회성 API |

### 3.2. 엔트로피 및 SSP 생성 방법
- **최소 엔트로피 명세**: TTAK.KO-12.0306/R1 표준에 따라 잡음원을 수집하며, 반복 횟수 테스트(RCT)와 적응성 비율 테스트(APT)를 통해 실시간 건전성을 검증함.
- **SSP 생성 알고리즘**: 모든 핵심보안매개변수(SSP)는 HMAC_DRBG를 기반으로 생성되며, SEED(키/IV), HMAC(키), RSA(키쌍), DH(파라미터/키쌍) 등의 생성 시 해당 난수 생성 API를 이용함.

### 3.3. SSP 합의 및 전송 (Diffie-Hellman)
"DH 알고리즘(2048/3072-bit)을 이용하여 안전한 키 합의 기능을 제공한다. `KISA_Crypto_DH_genParameter()`, `genKeyPair()`, `computeSharedSecret()` API를 통해 파라미터 생성부터 공통 비밀키 계산까지의 과정을 지원한다."

### 3.4. SSP 주입, 저장 및 제로화 방법
- **주입 및 출력**: 암호모듈 경계를 기준으로 내/외부로 직접 유입되거나 유출되는 SSP는 존재하지 않음.
- **저장**: 전원이 인가되지 않은 상태에서 SSP가 암호경계 내에 영구 저장되는 경우는 없음.
- **제로화 방법**:
    - **절차적 제로화**: API 내부에서 임시 변수에 복사된 데이터나 도출된 중간값을 반환 전 즉시 메모리에서 덮어쓰기('0' 또는 무의미한 난수)하여 파기함.
    - **운영적 제로화**: `drbgClose()`와 같이 사용자가 명시적으로 호출하여 관련 자원을 해제하고 제로화하는 전용 API를 제공함.

## 4. 구조도 및 시각 자료 (Visuals)
> **알림**: 본 항목은 난수발생 및 SSP 관리의 전체 논리 흐름에 집중함.
> **논리 흐름**: [엔트로피 수집] → [DRBG 초기화/시딩] → [난수/SSP 생성] → [키 합의(DH)] → [사용 중 메모리 보호] → [사용 완료 후 즉시 제로화(절차적/운영적)]


## 5. 해설 및 증빙 가이드 (Guide)
- **표준 준수**: 난수발생기(TTAK.KO-12.0332) 및 엔트로피 검증 표준을 명확히 인용하여 설계의 타당성을 입증해야 함.
- **중복 명세 허용**: 본 항목은 SSP 명세, 제로화 등 다른 조항의 내용을 포함하므로, 상세설계서 작성 시 상호 참조(Cross-reference)를 통해 일관성을 유지하는 것이 효율적임.
- **제로화 시점**: 특히 '반환 전 제로화'와 '명시적 종료 시 제로화' 두 가지 방식이 소스코드 상에서 어떻게 구분되어 구현되었는지 구체적인 사례(수도코드 등)를 제시할 것.
