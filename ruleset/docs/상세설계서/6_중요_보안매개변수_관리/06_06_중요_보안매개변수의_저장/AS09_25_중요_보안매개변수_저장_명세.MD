# [AS09.25] 암호모듈 내부에 저장되는 모든 SSP에 대한 저장 명세

## 1. 보안요구사항 개요
암호모듈 내부에 영구적 또는 임시로 저장되는 모든 중요보안매개변수(SSP)에 대하여, 각 키가 올바른 개체(사용자, 프로세스 등)와 연계되어 있음을 보장하는 메커니즘과 절차를 명세해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE09.25.01**: 모든 키가 올바른 개체와 연계됨을 확인할 수 있는 메커니즘과 절차에 대한 서술

## 3. 작성 예시 (Examples)

### 3.1. 라이브러리형 암호모듈의 저장 정책
"KISACrypto V1.0 암호모듈은 소프트웨어 라이브러리 형태의 암호모듈로서, 암호연산 수행을 위해 입력받은 키를 모듈 내부에 영구적으로 저장하는 관리 기능을 지원하지 않는다."

- **휘발성 관리**: 모든 SSP는 API 호출 시 응용 프로그램으로부터 전달받아 RAM 상의 임시 버퍼에서만 유지되며, 연산이 종료되거나 API가 반환되기 직전에 제로화 절차를 거쳐 완전히 소멸됨.
- **개체 연계성**: 키 저장 기능을 제공하지 않으므로, 별도의 개체 연계 메커니즘은 응용 프로그램 단계에서 관리하도록 설계됨.

## 4. 구조도 및 시각 자료 (Visuals)
> **설계 핵심**: 본 모듈은 '비저장(Stateless)' 원칙을 준수함. 키 데이터는 암호 경계를 통과하여 메모리에 머무는 동안에만 유효하며, 비휘발성 저장장치(HDD/SSD)에 기록되는 과정이 존재하지 않음을 증빙함.

## 5. 해설 및 증빙 가이드 (Guide)
- **기능 부재의 명시**: 소프트웨어 암호모듈의 경우 별도의 키 저장소(Key Store)를 운영하지 않는 경우가 많음. 이 경우 작성 예시와 같이 기능을 지원하지 않음을 명시하여 해당 요건을 충족할 수 있음.
- **응용 프로그램의 역할**: 만약 응용 프로그램에서 키 저장 기능이 필수적으로 요구되는 경우, 암호모듈 외부에서 별도의 보안 저장 인터페이스를 설계하거나, 암호모듈이 키를 암호화하여 반환(Key Wrapping)하는 기능을 추가하여 설계해야 함.
- **LEA 알고리즘 적용 시**: 수빈님이 구현하는 LEA 모듈 역시 라이브러리 호출 시에만 키를 사용하고 즉시 파기하는 구조라면, 본 항목의 '저장 기능 미지원' 논리를 그대로 활용하여 문서를 구성할 것.
