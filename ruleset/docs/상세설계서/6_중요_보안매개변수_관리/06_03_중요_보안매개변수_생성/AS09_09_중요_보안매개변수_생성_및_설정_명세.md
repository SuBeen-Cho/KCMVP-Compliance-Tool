# [AS09.09] 중요 보안매개변수(SSP) 생성 및 설정 방법 명세

## 1. 보안요구사항 개요
검증대상 난수발생기를 이용하여 모듈 내에서 직접 SSP를 생성하거나, 주입된 다른 SSP로부터 새로운 SSP를 유도하는 경우, KS X ISO/IEC 19790 부속서 D에서 정의한 생성 방법을 준수해야 함을 명세함.

## 2. 상세 요구사항 (Requirements)
- **VE09.09.01**: 모듈에서 SSP를 생성하거나 유도하는 경우, 부속서 D의 목록에 제시된 생성 방법을 준수함을 명세
- **VE09.09.02**: SSP 생성 및 설정 시 상세 사용법 명세

## 3. 작성 예시 (Examples)

### 3.1. 난수발생기를 이용한 직접 생성
"KISACrypto V1.0은 검증대상 난수발생기인 HMAC_DRBG를 사용하여 암호키, 난수, 공개키 암호/전자서명의 소수(Prime) 등을 생성한다. 생성 시 별도의 가공 없이 난수발생기 출력을 직접 사용함으로써 데이터의 엔트로피를 보존한다."

### 3.2. 키 설정(Key Establishment) 표준 준수
"본 모듈은 안전한 키 공유를 위해 다음과 같은 국제 표준 메커니즘을 준수하여 구현되었다."
- **키 전송 (Key Transport)**: RSAES 기반의 키 전송 방법은 `ISO/IEC 11770-2`의 "G.3 RSA key transfer" 규격을 준수함.
- **키 합의 (Key Agreement)**: DH 기반의 키 합의 방법은 `ISO/IEC 11770-3`의 "D.6 Diffie-Hellman key agreement" 규격을 준수함.

## 4. 구조도 및 시각 자료 (Visuals)
> **알림**: 본 항목은 표준 준수 논리에 집중함.
> **논리 흐름**: [검증대상 DRBG 기동] → [난수 비트열 생성] → [표준 기반 키 생성/합의 알고리즘 입력] → [ISO/IEC 11770 규격에 따른 키 교환] → [최종 SSP 확정]


## 5. 해설 및 증빙 가이드 (Guide)
- **표준 메커니즘의 적절성**: 현재 KCMVP에서는 KAS(키 합의 기법)나 KTS(키 전송 기법)가 별도로 지정되어 있지 않으나, `ISO/IEC 11770` 시리즈를 준수하는 경우 검증대상 동작모드에서 사용 가능함.
- **프리미티브의 제한**: 키 설정 과정에서 사용되는 원천 알고리즘(RSAES, DH, ECDH 등)은 반드시 검증대상 암호알고리즘 목록에 포함된 것이어야 함.
- **생성 방법의 구체성**: 난수발생기를 통해 SSP를 생성하는 구체적인 호출 순서와 파라미터 설정값은 앞선 '난수발생기 사용 예시'와 일치하도록 작성해야 함.
- **LEA 알고리즘 적용**: 수빈님이 연구 중인 LEA 비밀키 생성 시에도 본 항목에서 정의한 HMAC_DRBG 직접 출력 사용 원칙을 적용함을 명시할 것.
