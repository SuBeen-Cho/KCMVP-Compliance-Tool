# [AS10.53] 주기적 자가시험 명세

## 1. 보안요구사항 개요
암호모듈이 구동 중인 상태에서 운영자의 요청 또는 사전에 정의된 조건에 따라 모듈의 안전성을 재검증하기 위한 주기적 자가시험(Periodic Self-test)의 수행 항목과 방법론을 명세해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE10.53.01**: 주기적 자가시험(동작 전 자가시험, 조건부 알고리즘 시험 등)에 대한 명세
- **VE10.53.02**: 암호모듈이 제공하는 주기적 자가시험 수행 방법 및 절차 명세

## 3. 작성 예시 (Examples)

### 3.1. 주기적 자가시험 API 및 수행 방법
"KISACrypto V1.0은 운영자가 원하는 시점에 모듈의 상태를 점검할 수 있도록 온디맨드(On-demand) 방식의 주기적 자가시험 API를 제공한다."

- **제공 API**: `KISA_Crypto_selftest()`
- **수행 주체**: 암호모듈을 사용하는 응용 프로그램 또는 관리자 권한을 가진 운영자
- **수행 방법**: 암호모듈이 정상 동작 중인 상태에서 `KISA_Crypto_selftest()` 함수를 호출하여 자가시험을 강제로 실행함.

### 3.2. 주기적 자가시험 포함 항목
"주기적 자가시험은 모듈 초기화 시 수행되는 모든 '동작 전 자가시험' 항목을 포함하며, 알고리즘의 유효성을 재확인한다."

1.  **소프트웨어 무결성 시험**: 현재 로드된 바이너리의 해시값을 계산하여 참조값과 비교 수행.
2.  **핵심기능시험 (KAT)**: 탑재된 모든 검증대상 암호알고리즘(LEA, SEED, SHA-256 등)에 대해 KAT 형태의 자가시험 수행.
3.  **조건부 알고리즘 시험**: 난수발생기(DRBG)의 엔트로피 건전성 시험 등 조건부 요건을 포함하여 수행.

## 4. 구조도 및 시각 자료 (Visuals)
> **알림**: 본 항목은 운영 중인 모듈의 상태 재검증 및 API 호출 제어에 집중함.
> **논리 흐름**: [운영 중인 상태] → [운영자의 `selftest()` 호출] → [암호 서비스 일시 중단] → [무결성 및 KAT 전수 재수행] → [성공 시 서비스 재개 / 실패 시 심각한 오류 상태 전이]

## 5. 해설 및 증빙 가이드 (Guide)
- **시험 범위의 포괄성**: 주기적 자가시험은 반드시 모든 동작 전 자가시험 항목을 포함해야 하며, 적어도 조건부 암호알고리즘 시험 항목이 누락되지 않도록 설계해야 함.
- **서비스 가용성 고려**: 자가시험 수행 중에는 외부로부터의 암호 서비스 요청 및 데이터 출력이 차단되어야 하며, 시험 완료 후 결과 코드(Return Value)를 통해 운영자에게 성공/실패 여부를 명확히 알려야 함.
- **알고리즘 확장**: 연구 중인 **LEA**나 **HAETAE(양자내성암호)** 모듈의 경우, 장시간 구동되는 환경에서 알고리즘의 논리적 무결성을 보장하기 위해 이 주기적 자가시험 API가 핵심적인 역할을 수행함을 기술할 것.
- **수행 시점의 유연성**: 서비스 요청 시마다 수행하거나, 모듈 재시작을 유도하는 등 운영 환경에 적합한 주기적 자가시험 정책을 수립하고 이를 설계서에 명시해야 함.
