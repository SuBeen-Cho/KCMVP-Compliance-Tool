# [AS03.09/10] 제어 출력 명세 및 특정 상태에서의 제어 출력 금지

## 1. 보안요구사항 개요
암호모듈의 동작 상태를 제어하거나 표시하는 모든 출력 명령, 신호 및 제어 데이터는 지정된 제어 출력 인터페이스를 통해서만 출력되어야 하며, 특히 오류 상태나 자가시험 상태에서는 이러한 제어 출력이 엄격히 금지되어야 함.

## 2. 상세 요구사항 (Requirements)
- **VE03.09.01**: 암호모듈의 모든 출력 명령, 신호, 제어 데이터의 출력 명세
- **VE03.10.01**: 암호모듈의 오류상태에서의 제어 출력 금지 명세
- **VE03.10.02**: 암호모듈의 자가시험 상태에서의 제어 출력 금지 명세

## 3. 작성 예시 (Examples)

### 3.1. 제어 출력 명세 개요
"KISACrypto V1.0은 소프트웨어 암호모듈로서 물리적인 제어 신호를 직접 출력하지 않으며, API 함수의 반환값(상태 코드)을 통해 논리적인 제어 정보를 제공한다. 모든 오류 코드는 암호운영 오류와 심각한 오류로 구분하여 정의한다."

### 3.2. 제어 출력 금지 메커니즘
| 상태 | 제어 출력 금지 방법 |
| :--- | :--- |
| **오류 상태** | 심각한 오류(Hard Error) 발생 시, 모듈은 즉시 모든 제어 출력 API의 동작을 중단하고 정의된 고유 오류 코드만을 반환하며 추가적인 제어 데이터 송출을 차단함. |
| **자가시험 상태** | 자가시험 수행 중에는 외부 인터페이스를 통한 제어 데이터 출력이 활성화되지 않으며, 시험이 완료된 후 성공/실패 여부만 제어 출력 인터페이스를 통해 전달됨. |

## 4. 구조도 및 시각 자료 (Visuals)
> **알림**: 본 항목은 별도의 아키텍처 다이어그램을 포함하지 않음. 
> **논리 흐름**: [상태 모니터링] → [오류/자가시험 감지] → [제어 출력 게이트 차단] → [제한된 상태 코드만 반환]


## 5. 해설 및 증빙 가이드 (Guide)
- **제어 출력 정의**: 소프트웨어 모듈의 경우 '제어 데이터'가 무엇인지(예: 상태 코드, 오류 코드 등)를 명확히 정의하고, 이것이 '제어 출력 인터페이스'로 분류된 경로로만 나가는지 확인해야 함.
- **상태별 차단 로직**: 암호모듈이 오류 상태에 있을 때마다 제어 출력 인터페이스를 통한 모든 출력이 금지되는 구체적인 방법(예: 전역 에러 플래그 확인 후 API 즉시 리턴)을 상세설계서에 명세해야 함.
- **물리적 출력 지원 여부**: 예시와 같이 물리적 제어 출력을 지원하지 않는 소프트웨어 모듈은 그 논리적 근거를 명확히 제시하여 보안 요구사항을 충족함을 입증할 것.
