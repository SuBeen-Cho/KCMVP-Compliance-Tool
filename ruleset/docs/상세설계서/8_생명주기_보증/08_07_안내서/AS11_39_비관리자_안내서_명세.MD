# [AS11.39] 비관리자 안내서 제공

## 1. 보안요구사항 개요
암호모듈의 일반 사용자(응용 프로그램 개발자 등)가 모듈에서 제공하는 보안 서비스를 안전하게 호출하고 사용할 수 있도록 API 사용 방법 및 사용자 책임 사항을 명세한 비관리자 안내서를 제작하여 제공해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE11.39.01**: 비관리자 안내서 제공
- **VE11.39.02**: 비관리자 안내서 제공

## 3. 작성 예시 (Examples)
"KISACrypto V1.0 암호모듈은 일반 사용자가 암호 서비스를 오용하지 않고 안전하게 활용할 수 있도록 상세한 **'비관리자 안내서(사용자 매뉴얼)'**를 제공한다. 본 안내서는 API의 기능, 매개변수 설정 및 사용자가 준수해야 할 보안 수칙을 포함한다."

## 4. 상세 명세 항목 (Specification)
표준 요구사항 및 해설에 따라 비관리자 안내서에는 다음과 같은 핵심 항목들이 포함되어야 함.

| 주요 명세 항목 | 세부 내용 |
| :--- | :--- |
| **사용 가능 알고리즘 목록** | 사용자가 호출할 수 있는 검증대상 및 비검증대상 암호알고리즘의 종류와 특징 |
| **논리적 인터페이스 명세** | API 함수명, 입력/출력 매개변수의 타입 및 의미, 리턴 코드 정의 |
| **물리적 포트 안내** | 소프트웨어 모듈이 실행되는 환경에서의 논리적 포트와 물리적 포트의 매핑 관계 |
| **검증대상 동작모드 책임** | 모듈을 '검증대상 동작모드(Approved Mode)'로 유지하기 위해 사용자가 지켜야 할 구성 및 호출 방법 |
| **사용자 보안 책임** | 키 관리 주의사항, 세션 종료 절차 등 안전한 운영을 위한 사용자의 의무 사항 |

## 5. 해설 및 증빙 가이드 (Guide)
- **API 참조 문서의 역할**: 비관리자 안내서는 실질적으로 '개발자 가이드'의 역할을 수행함. 따라서 각 API가 설계서의 서비스(AS09)와 어떻게 대응되는지 명확히 알 수 있어야 함.
- **알고리즘 구분**: 사용자가 실수로 비검증 알고리즘을 사용하여 보안 수준이 낮아지는 것을 방지하기 위해, 검증필 알고리즘과 그 외의 알고리즘을 엄격히 구분하여 안내해야 함.
- **오류 처리 안내**: API 호출 실패 시 반환되는 오류 코드에 따른 적절한 대응 방법(예: 파라미터 재확인, 모듈 재초기화 등)을 상세히 기술할 것.
- **설계 반영**: 현재 진행 중인 **LEA**나 **PQC(양자내성암호)** 구현물의 경우, 각 알고리즘의 특성(예: 키 사이즈 선택, 서명 검증 절차 등)이 비관리자 안내서의 API 사용 예시에 정확히 반영되어 있는지 확인할 것.
