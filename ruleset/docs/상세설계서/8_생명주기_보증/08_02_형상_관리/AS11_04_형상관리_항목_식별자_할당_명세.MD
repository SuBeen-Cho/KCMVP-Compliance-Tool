# [AS11.04] 형상관리 항목에 대한 유일한 식별자 할당 명세

## 1. 보안요구사항 개요
형상관리 시스템으로 관리되는 모든 항목(문서, 코드, 바이너리 등)에 대하여 고유한 식별자를 부여하고, 변경 사항을 관리하기 위한 체계적인 버전 부여 방법론을 명세해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE11.04.01**: 형상관리 시스템으로 관리되는 항목 및 버전 부여 방법 명세
- **VE11.04.02**: 형상항목의 버전을 식별하는 방법 서술

## 3. 작성 예시 (Examples)

### 3.1. 형상관리 대상 항목 목록
"KISACrypto V1.0 암호모듈은 다음과 같은 항목들을 형상관리 시스템에 등록하여 고유한 이름으로 관리한다."

| 분류 | 항목명 (식별자) | 설명 |
| :--- | :--- | :--- |
| **개발문서** | 기본 및 상세 설계서 | 암호모듈의 설계를 증빙하는 문서 (KS X ISO/IEC 19790 준수) |
| | 형상관리문서 | 형상관리 대상, 방법, 정책 및 절차 기술서 |
| | 보안정책서 | 암호모듈의 특징, 설정, 사용방법에 대한 명세서 |
| | 시험서 | 보안서비스 시험 수행 결과 보고서 (목적, 절차, 결과 포함) |
| | 관리자 안내서 | 암호모듈 운영 및 관리를 위한 지침서 |
| **소스코드** | 암호모듈 원천소스코드 | `*.c`, `*.h`로 이루어진 실제 구현 소스코드 |
| **암호모듈** | KISACrypto32/64.dll | 빌드 완료된 플랫폼별 암호모듈 라이브러리 파일 |
| **무결성 검증기** | VerificationKey | 무결성 확인을 위한 바이너리 형태의 검증 키 파일 |
| **무결성 생성기** | IntegrityGenSoftware.exe | 무결성 검증값을 생성하는 전용 소프트웨어 |
| **테스트 프로그램** | KISACryptoTester.exe | 암호모듈의 보안서비스를 검증하는 테스트 도구 |

### 3.2. 버전 식별 및 부여 방법
"모든 형상항목은 유일한 버전을 식별하기 위해 다음과 같은 명명 규칙을 적용한다."

> **규칙**: `{항목명} V{Major Version}.{Minor Version}`

- **Major Version (주 버전)**: 
    - 암호모듈의 메인 알고리즘 추가나 구조적 변경 등 주요 기능 변화 시 '형상관리위원회'를 통해 1씩 증가시킴.
    - 1자리 숫자로 구성되며 최초 '1'부터 시작함.
- **Minor Version (부 버전)**: 
    - 단순 오류 수정이나 일부 기능의 미세 변경 시 1씩 증가시킴.
    - 1자리 숫자로 구성되며 최초 '0'부터 시작함.

## 4. 구조도 및 시각 자료 (Visuals)
> **설계 핵심**: 모든 형상 항목은 중앙 저장소에서 관리되며, 체크인(Check-in) 시점에 해당 규칙에 따라 버전이 자동으로 기록되거나 관리자에 의해 할당되어 중복 식별을 방지함.

## 5. 해설 및 증빙 가이드 (Guide)
- **추적성 확보**: 식별자 할당의 목적은 특정 버전의 암호모듈이 어떤 소스코드와 어떤 설계서에 기반하여 만들어졌는지 역추적(Traceability)할 수 있게 하기 위함임.
- **문서 인용**: 본 항목의 세부 이행 내용은 '형상관리문서'에 작성된 공식 절차를 인용하여 기술하며, 실제 형상관리 시스템(Git/SVN)의 로그 화면을 증빙 자료로 첨부할 수 있음.
- **PQC 알고리즘 관리**: 수빈님이 연구 중인 **LEA**나 **HAETAE** 모듈의 경우, 알고리즘 구현 코드와 테스트 벡터 파일에 각각 독립적인 식별자를 부여하여 관리되고 있는지 확인할 것.
