# [AS11.30] 자동화 보안 진단 도구 이용 명세

## 1. 보안요구사항 개요
암호모듈의 소프트웨어/펌웨어 구성요소에 대하여 자동화된 소스코드 취약점 진단 도구를 적용하고, 이를 통해 발견된 보안 취약점(버퍼 오버플로우 등)에 대한 대응 결과를 명세해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE11.30.01**: 자동화 보안 진단 도구를 이용하여, 소프트웨어/펌웨어의 취약점 점검

## 3. 작성 예시 (Examples)

### 3.1. 보안 진단 도구 및 적용 환경
"KISACrypto V1.0 암호모듈은 소스코드 레벨의 잠재적 결함을 제거하기 위해 공개 취약점 진단 도구인 **Yasca V2.1**을 적용하여 정적 분석을 수행하였다."

* **진단 도구**: Yasca V2.1 (및 기타 정적 분석 도구)
* **진단 대상**: 암호모듈 전체 소스코드 (`*.c`, `*.h`)
* **주요 점검 항목**: 버퍼 오버플로우, 메모리 누수, 포인터 오용, 보안에 취약한 함수 사용 등

### 3.2. 취약점 제거 및 개선 결과
"진단 도구를 통해 식별된 보안 취약점에 대해 다음과 같이 코드를 개선하여 안전성을 확보하였다."

| 취약 유형 | 개선 전 (위험 요소) | 개선 후 (조치 내용) |
| :--- | :--- | :--- |
| **취약 함수 제거** | `strlen`, `strcmp`, `strcpy` 등 버퍼 길이를 명시하지 않는 함수 사용 | `strncpy`, `strncmp` 등 버퍼 길이를 명시적으로 체크하는 안전한 함수로 교체 |
| **버퍼 관리** | 특정 버퍼로 데이터 복사 시 경계 검사 미흡 | 데이터 복사 및 메모리 비교 시 반드시 대상 버퍼의 유효 길이를 체크하는 로직 추가 |
| **메모리 보호** | 연산 종료 후 민감 정보 잔류 가능성 | 임시 버퍼 사용 후 즉시 제로화(Zeroization) 로직 적용 확인 |

## 4. 구조도 및 시각 자료 (Visuals)
> **설계 핵심**: 자동화 도구를 빌드 파이프라인에 통합하여, 새로운 코드가 커밋될 때마다 취약점을 상시 점검하는 체계를 구축함.

## 5. 해설 및 증빙 가이드 (Guide)
- **도구 선정 및 명세**: 실제 암호모듈 개발에 사용된 취약점 진단 도구의 명칭과 버전을 정확히 명시해야 함.
- **수정 이력의 구체성**: 단순히 "도구를 썼다"는 설명보다는, 기존에 발생했던 취약점을 어떻게 소스코드 레벨에서 수정했는지에 대한 전/후 비교 설명을 포함하는 것이 바람직함.
- **LEA 및 PQC 알고리즘 적용**: **LEA**나 **HAETAE**, **SMAUG-T**와 같이 고성능 연산이 필요한 알고리즘은 복잡한 루프와 포인터 연산을 포함하므로, 자동화 도구를 통해 경계 검사(Boundary Check)가 완벽히 이루어졌음을 증빙하는 것이 중요함.
- **KCMVP 대응**: 심사 시 진단 도구의 실행 결과 보고서(Report)를 별첨하여, 알려진 보안 취약점에 대해 모두 대응 완료했음을 입증할 것.
