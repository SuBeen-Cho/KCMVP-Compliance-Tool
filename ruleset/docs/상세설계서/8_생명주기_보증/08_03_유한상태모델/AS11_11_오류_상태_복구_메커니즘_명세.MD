# [AS11.11] 오류 상태에 대한 복구 명세

## 1. 보안요구사항 개요
암호모듈이 유지보수 상태나 심각한 오류 상태가 아닌 경우, 즉 운영자의 실수 등으로 인한 단순한 오류 발생 시 모듈 스스로 정상 동작 모드로 복구될 수 있는 절차와 방법을 명세해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE11.11.01**: 심각한 오류 상태가 아닐 경우, 복구가 가능하다는 명세

## 3. 작성 예시 (Examples)

### 3.1. 오류 상태 분류 및 복구 정책
"KISACrypto V1.0 암호모듈은 하드웨어적 결함이나 자가시험 실패가 아닌, API 호출 과정에서의 사용자 실수로 발생하는 오류를 '단순한 오류'로 정의하고 다음과 같이 처리한다."

- **복구 가능 조건**: 잘못된 키 사이즈 입력, 지원하지 않는 알고리즘 식별자(ID) 사용, 잘못된 패딩(Padding) 옵션 선택 등.
- **복구 절차**: 
    1. 내부 상태 체크 로직에 의해 오류 발생을 감지함.
    2. 해당 오류에 매핑되는 특정 **오류 코드(Status Indicator)**를 반환함.
    3. 내부 전역 상태 변수를 '오류' 상태로 일시 변경한 후, 즉시 **자동으로 '검증대상 동작 모드'로 천이**시킴.
- **유지보수 기능**: 본 암호모듈은 소프트웨어 라이브러리 형태로, 별도의 유지보수 상태나 유지보수 기능을 제공하지 않으므로 관련 보안 위협에서 제외됨.

### 3.2. 복구 메커니즘의 구현
"모든 공개 API는 예외 처리(Exception Handling) 루틴을 포함하고 있으며, 단순 오류 발생 시 연산 중인 임시 자원만 정리(Clear)하고 서비스 가용성을 유지하도록 설계됨."

## 4. 구조도 및 시각 자료 (Visuals)
> **설계 핵심**: 본 항목은 '가용성(Availability)'과 '안전한 복구'의 균형에 집중함.
> **논리 흐름**: [API 호출] → [입력값 검증 실패] → [오류 코드 반환] → [임시 자원 정리] → [자동 상태 복구(State 7 → 5)] → [다음 서비스 대기]

## 5. 해설 및 증빙 가이드 (Guide)
- **FSM과의 일관성**: AS11.08 유한상태모델에서 정의한 '오류(State 7)' 상태의 동작 설명과 본 항목의 내용이 반드시 일치해야 함.
- **자동 천이의 강조**: 소프트웨어 라이브러리에서 복구가 가능하다는 것은 "프로그램이 죽지 않고 다음 API 호출을 정상적으로 받을 준비가 된다"는 뜻임. 이를 소스코드의 `return` 문과 에러 처리 로직으로 증빙할 것.
- **심각한 오류와의 차별점**: 무결성 파괴와 같은 '심각한 오류'는 절대 자동 복구되어서는 안 됨을 대조하여 기술하여, 단순 오류 복구 로직의 안전성을 강조할 것.
- **PQC/LEA 적용**: 수빈님이 구현 중인 **LEA**나 **HAETAE** 알고리즘 API에서 파라미터 체크(예: LEA의 경우 키 길이가 128, 192, 256이 아닌 경우) 단계가 이 복구 메커니즘의 첫 번째 관문이 됨을 명시할 것.
