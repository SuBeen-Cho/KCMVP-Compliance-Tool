# [AS06.08] 암호모듈에 의해 생성된 프로세스에 대한 제한

## 1. 보안요구사항 개요
암호모듈이 동작 중 추가적인 프로세스를 생성하는 경우, 해당 자식 프로세스의 소유권과 제어권을 생성 주체인 암호모듈(부모 프로세스)로 국한시켜 외부로부터의 비인가 접근이나 가로채기를 방지해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE06.08.01**: 생성된 프로세스의 소유가 생성한 암호모듈로 국한시키는 방법 명세

## 3. 작성 예시 (Examples)

### 3.1. 서술형 예시 (프로세스를 생성하지 않는 경우)
"KISACrypto V1.0 암호모듈은 범용 소프트웨어 라이브러리형 암호모듈로서 응용 프로그램에 링크되어 동일한 프로세스 컨텍스트 내에서 동작하며, 동작 중에 별도의 추가적인 자식 프로세스를 생성하지 않는다."

### 3.2. 시스템 API 활용에 대한 명세
"난수발생기(DRBG)의 잡음원 수집 등을 위해 호출되는 시스템 API(예: Windows의 `CryptGenRandom`, Linux의 `/dev/urandom` 등)는 운영체제 커널에서 제공하는 기능을 호출하는 것이며, 암호모듈이 직접 프로세스를 생성하거나 소멸 과정에 관여하지 않는다. 따라서 프로세스 소유권 전이에 따른 보안 위협이 존재하지 않는다."

## 4. 구조도 및 시각 자료 (Visuals)
> **알림**: 본 항목은 별도의 아키텍처 다이어그램을 포함하지 않음. 
> **논리 흐름**: [암호 서비스 호출] → [응용 프로그램 프로세스 내 실행] → [자식 프로세스 생성 여부 확인(생성 안 함)] → [단일 프로세스 컨텍스트 유지] → [프로세스 소유권 보호]

## 5. 해설 및 증빙 가이드 (Guide)
- **프로세스 미생성 명세**: 소프트웨어 라이브러리 형태의 모듈은 대부분 독립된 프로세스를 생성하지 않으므로, 작성 예시와 같이 "프로세스를 생성하지 않는다"고 명세하는 것으로 요건 충족이 가능함.
- **자식 프로세스 생성 시**: 만약 성능 향상이나 병렬 처리를 위해 자식 프로세스를 생성한다면, 운영체제의 프로세스 관리 기능을 사용하여 자식 프로세스의 핸들이나 소유권이 부모 프로세스에 종속되도록 설계된 근거를 제시해야 함.
- **범위 명확화**: 암호모듈이 직접 `fork()`나 `CreateProcess()` 등을 호출하여 관리하는 영역과, 단순히 OS 시스템 콜을 사용하는 영역을 구분하여 기술할 것.
