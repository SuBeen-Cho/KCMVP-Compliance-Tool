# [AS06.06] 운영환경의 암호모듈 프로세스 보호기능

## 1. 보안요구사항 개요
암호모듈이 동작하는 운영환경(OS)이 인가되지 않은 프로세스로부터 암호모듈의 중요보안매개변수(CSP) 접근을 차단하고, 제어되지 않은 보안매개변수의 수정을 방지하는 구체적인 메커니즘을 명세해야 함.

## 2. 상세 요구사항 (Requirements)
- **VE06.06.01**: 운영환경이 인가되지 않은 CSP 접근과 제어되지 않은 보안매개변수의 변경을 방지하는 방법 명세

## 3. 작성 예시 (Examples)

### 3.1. 운영체제 커널 기반 프로세스 보호
"본 암호모듈은 윈도우 및 리눅스 커널에서 제공하는 가상 메모리 관리 시스템(Paging/Segmentation)을 활용한다. 각 응용 프로그램 프로세스는 고유한 가상 주소 공간을 할당받으며, 하드웨어 수준(MMU)에서 타 프로세스의 메모리 영역 침범이 원천적으로 차단된다."
"본 시험항목은 AS06.05에서 요구하는 VE 항목과 함께 명세될 수 있다."

### 3.2. 보안 기술 적용 명세
| 보호 대상 | 보호 방법 및 기술 |
| :--- | :--- |
| **CSP 접근 차단** | - **메모리 격리**: 운영체제의 프로세스 간 메모리 보호 기능을 통해 비인가 프로세스의 `Read/Write` 접근을 거부함.<br>- **DEP (데이터 실행 방지)**: 데이터 영역에서의 코드 실행을 차단하여 스택/힙 오버플로우를 통한 CSP 유출을 방지함. |
| **보안매개변수 변경 방지** | - **ASLR (주소 공간 배치 난수화)**: 모듈이 로드되는 주소를 매번 변경하여 공격자가 특정 보안매개변수의 위치를 예측하여 수정하는 것을 방해함.<br>- **Access Control**: 파일 시스템 및 객체 접근 제어 권한을 통해 인가된 운영자 외의 매개변수 파일 수정을 차단함. |

## 5. 해설 및 증빙 가이드 (Guide)
- **항목 통합 권고**: 본 항목은 **AS06.05(독립적 SSP 제어)**와 밀접하게 연관되어 있으므로, 상세설계서 작성 시 두 항목의 기술적 근거를 통합하여 하나의 '프로세스 보호 체계' 섹션으로 구성하는 것이 효율적임.
- **OS 의존성 강조**: 소프트웨어 암호모듈은 OS 보안 기능에 전적으로 의존하므로, 사용하는 운영체제의 버전(예: Windows 10, Ubuntu 24.04)이 제공하는 구체적인 보안 라이브러리나 커널 기능을 명시하는 것이 중요함.
- **예외 처리 증빙**: 다른 프로세스가 암호모듈의 주소 공간에 접근을 시도할 때 발생하는 시스템 예외(Segmentation Fault, Access Violation) 처리 결과 등을 증빙 자료로 활용할 수 있음.
