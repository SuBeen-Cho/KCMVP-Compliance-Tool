## 개요

KCMVP 검증 시 제출 문서 간 추적성(Traceability)이 확보되어야 한다.
기본 및 상세설계서, 소스코드, 시험결과보고서 사이의 인터페이스/에러코드/함수 커버리지 일치성이 검증된다.

---

## TRC-001: 설계서 인터페이스 명세 vs 헤더 파일 시그니처 일치성

**근거**: KS X ISO/IEC 24759 AS04.03 (기본 및 상세설계서 제출 요구사항)

**요구사항**:
- 설계서(기본설계서/상세설계서)의 인터페이스 명세표에 기재된 함수는 헤더 파일(.h)에 선언되어야 한다
- 헤더 파일에 선언된 공개 함수(public API)는 설계서의 인터페이스 명세에 반드시 포함되어야 한다
- 함수명, 파라미터 타입, 반환 타입이 일치해야 한다

**검사 대상**:
- 헤더 파일의 공개 함수 선언 (예: `void lea_encrypt(...)`, `void lea_key_setup(...)`)
- 설계서의 인터페이스 명세표 또는 본문의 함수 언급

**위반 예시**:
- 헤더에 `lea_get_version(void)` 선언되어 있으나 설계서에 언급 없음
- 설계서에 `lea_key_setup` 명세되어 있으나 헤더에 선언 없음

## TRC-002: 설계서 오류 코드 정의 vs 코드 상수 일치성

**근거**: KS X ISO/IEC 19790:2015 §7.9 (SSP 관리), 시험기준

**요구사항**:
- 설계서의 오류 코드 정의표에 기재된 에러 코드 상수는 소스코드에 `#define` 또는 `enum`으로 정의되어야 한다
- 소스코드에 정의된 에러 코드는 설계서에도 명세되어야 한다
- 에러 코드의 심볼명과 값이 일치해야 한다

**검사 대상**:
- 소스코드의 `#define` 에러 상수 (예: `#define LEA_ERROR_INVALID_KEY -1`)
- 설계서의 오류 코드 정의표 또는 본문의 에러 코드 언급

**위반 예시**:
- 설계서에 `LEA_ERROR_INVALID_KEY(-1)` 정의되어 있으나 소스코드에 `#define` 없음
- 소스코드에 `#define LEA_ERROR_BAD_PARAM -2` 정의되어 있으나 설계서에 언급 없음

## TRC-003: 공개 함수 시험 커버리지

**근거**: KS X ISO/IEC 24759 (시험 요구사항), GVI Part 1 부속서A

**요구사항**:
- 헤더 파일(.h)에 선언된 공개 함수는 시험결과보고서에서 시험 항목으로 언급되어야 한다
- 공개 함수의 최소 50% 이상이 시험서에서 테스트 항목으로 언급되어야 함 (기본 기준)
- KCMVP 시험에서는 암호화/복호화 함수의 KAT(Known Answer Test) 수행이 필수

**검사 대상**:
- 헤더 파일의 공개 함수 목록
- 시험결과보고서의 시험 항목명 및 시험 내용

**위반 예시**:
- 공개 함수 4개 중 1개만 시험서에서 언급됨 (25% < 50%)
- `lea_gcm_encrypt` 함수가 시험서에 전혀 언급되지 않음

## 문서 제출 요구사항 (GVI Part 1 부속서A)

KCMVP 검증 시 제출해야 하는 문서 목록:
- **기본설계서**: 암호모듈 경계, 인터페이스 명세, 운영 환경 등
- **상세설계서**: 함수 시그니처, SSP 관리 표, 알고리즘 구현 상세
- **소스코드**: 전체 암호모듈 구성 요소 소스코드
- **시험결과보고서**: 암호알고리즘 KAT, 조건부 자가시험, 기능 시험 결과
- **보안정책서**: 암호모듈 보안 정책 및 사용 지침
- **사용자 가이드**: 설치/운용 방법

---

## 자가시험(Self-Test) 요구사항 (GVI Part 1 §10)

- **동작 전 자가시험(Power-On Self-Test)**: 모듈 초기화 시 KAT 수행 필수
- **조건부 알고리즘 시험(KAT)**: 각 검증대상 알고리즘에 대한 알려진 정답 시험
- **소프트웨어/펌웨어 무결성 검사**: 코드 무결성 검증 수행
- **조건부 키 쌍 일치 시험**: 키 생성 시 암·복호화 또는 서명·검증 일치 확인

---

## 추적성 확인 방법 (소스코드 검토)

KS X ISO/IEC 24759에 따라 시험기관은 다음을 소스코드로 확인한다:
1. 설계서의 인터페이스 명세와 실제 구현 함수 시그니처 일치 여부
2. 설계서의 SSP 관리 표에 명세된 제로화 코드 구현 여부
3. 설계서의 자가시험 절차와 코드 내 자가시험 로직 일치 여부
4. 설계서에 명세된 오류 코드가 소스코드에 동일하게 정의되어 있는지 여부
