## 개요

KCMVP 검증대상 블록암호 및 운영모드:

| 블록암호 | 키 길이 | 블록 크기 |
|---------|--------|---------|
| ARIA    | 128/192/256비트 | 128비트 |
| SEED    | 128비트 | 128비트 |
| LEA     | 128/192/256비트 | 128비트 |
| HIGHT   | 128비트 | 64비트 |

지원 운영모드: ECB, CBC, CFB, OFB, CTR (일반 암·복호화), GCM, CCM (인증 암호화)

---

## 공통 구현 요구사항

### ① 비밀키 길이 확인
- ARIA, LEA: 128/192/256비트 지원
- SEED, HIGHT: 128비트만 지원

### ② 안전한 비밀키 생성
블록암호 비밀키는 **검증대상 난수발생기(DRBG)**를 이용하여 생성해야 한다.
(SSP 생성 방법 준수)

### ③ 평문/암호문 길이 확인
- ARIA, SEED, LEA: 128비트(16바이트) 블록 단위
- HIGHT: 64비트(8바이트) 블록 단위

### ④ 패딩 알고리즘
- 평문 길이가 블록 크기의 배수가 아닌 경우 권고된 패딩 적용
- 복호화 후 패딩 유효성 검증 후 제거
- Zero-padding(덧붙이기 방법 1)은 검증대상 모드에서 사용 불가 (GVI Part 1 §C.2)
- 스트림 암호화 모드(CFB, OFB, CTR)에 패딩 적용 시 소스코드 검토 필요

### [공통] 제로화(Zeroization)
사용이 끝난 모든 SSP(비밀키, IV, 라운드키, 중간 연산 데이터)는 즉시 제로화해야 한다.

---

## ECB (Electronic CodeBook)

**특징**
- 동일한 평문 블록 → 동일한 암호문 블록 생성
- 암호화/복호화 모두 병렬 처리 가능
- 패딩 필요: 평문 길이가 1블록 이하인 경우

**추가 요구사항**
- 블록암호가 처리 가능한 1블록 길이를 초과하는 평문 직접 입력 금지

**검증 항목**: ①비밀키길이, ②안전한키생성, ③평문길이, ④패딩알고리즘, 제로화

---

## CBC (Cipher Block Chaining)

**특징**
- 이전 암호문 블록이 다음 평문 블록과 XOR된 후 암호화
- 첫 번째 평문 블록은 IV와 XOR
- 복호화만 병렬 처리 가능

**IV 생성 요구사항** (GVI Part 2 §2나④)
암호화 단계마다 새로운 IV를 생성해야 하며, **예측 불가능한** 값이어야 한다:
1. 미사용(Unique) 값을 비밀키로 암호화한 결과값을 IV로 사용
2. 검증대상 난수발생기를 이용하여 생성

**검증 항목**: ①비밀키길이, ②안전한키생성, ③패딩알고리즘, ④안전한IV생성, 제로화

---

## CFB (Cipher Feedback)

**특징**
- 자가 동기화된 스트림 암호 형태
- 블록암호 암호화 알고리즘만 구현하면 됨 (복호화에도 암호화 사용)
- 복호화만 병렬 처리 가능
- 피드백 길이(r비트): ARIA/SEED/LEA는 1≤r≤128, HIGHT는 1≤r≤64

**IV 요구사항**: 예측 불가능한 값이어야 함

**검증 항목**: ①비밀키길이, ②안전한키생성, ③안전한IV생성, ④피드백길이확인, 제로화

---

## OFB (Output Feedback)

**특징**
- 동기화된 스트림 암호와 유사
- 블록암호 암호화 알고리즘만 구현하면 됨
- 병렬 처리 불가능
- 암호화와 복호화의 구조가 동일

**IV 요구사항**: 암호 연산의 각 실행에 대해 **유일(Unique)**해야 한다

**검증 항목**: ①비밀키길이, ②안전한키생성, ③안전한IV생성, 제로화

---

## CTR (Counter)

**특징**
- 카운터를 암호화한 후 평문 블록과 XOR
- 암호화와 복호화의 구조가 동일
- 암호화/복호화 모두 병렬 처리 가능
- 카운터가 최대값 도달 시 적절한 처리 필요

**카운터 요구사항**: 동일한 비밀키로 암호화되는 모든 평문 블록에 대해 **유일(Unique)**해야 한다

**검증 항목**: ①비밀키길이, ②안전한키생성, ③안전한CTR생성, 제로화

---

## GCM (Galois/Counter Mode) — 인증 암호화

**특징**
- CTR 모드에 GF(2¹²⁸) 곱 연산 기반 인증 추가
- 기밀성 + 인증을 동시에 제공
- 입력 메시지 인증만 필요한 경우: GMAC
- ARIA, SEED, LEA와 함께 사용 가능 (HIGHT 제외)

**IV(Nonce) 생성 요구사항** (GVI Part 1 §C.1)
1. **난수 생성 방법**: 검증대상 난수발생기로 최소 96비트 이상 생성
2. **결정론적 생성 방법**:
   - 최소 32비트 고정 필드 + 최소 32비트 반복되지 않는 결정론적 가변 필드 결합
   - IV 길이 64비트 이상
   - 가변 필드 최대값 도달 시 세션 중단 구현 필요

**인증값(Tag) 길이 요구사항** (GVI Part 1 §C.3)
- 최소 112비트(14바이트) 이상이어야 함
- 단, KISA LEA 구현체의 `lea_gcm_final`은 tag_len ≥ 4 (최소 4바이트)
- KCMVP 제출 시 인증값 112비트 이상 사용 권고

**GCM 암호화 호출 횟수 제한**
- 동일한 키에 대한 GCM 암호화 호출은 2³² 번을 초과하지 않아야 함
- 초과 전에 비밀키를 반드시 변경(갱신)해야 함

**구현 순서**:
```
lea_gcm_init → lea_gcm_set_ctr → [lea_gcm_set_aad] → lea_gcm_encrypt/decrypt (1회+) → lea_gcm_final
```

## CCM (Counter with CBC-MAC) — 인증 암호화

**특징**
- CTR 모드 암호화 + CBC-MAC 인증을 결합
- 기밀성 + 인증을 동시에 제공
- ARIA, SEED, LEA와 함께 사용 가능 (HIGHT 제외)

**Nonce 요구사항**
- Nonce 길이: 7~13바이트

**인증값(Tag) 길이**
- 4, 6, 8, 10, 12, 14, 16바이트 중 하나이어야 함
- KCMVP 제출 시 최소 112비트(14바이트) 이상 사용 권고
