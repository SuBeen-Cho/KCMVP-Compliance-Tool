## 요구사항

KCMVP 검증 신청 시 기본 및 상세설계서에 반드시 포함되어야 하는 핵심 항목들입니다.
누락 시 검증 신청이 반려됩니다.

**DOC-001 (AS02.03): 암호모듈 유형 명세**
- 반드시 명시: 하드웨어, 소프트웨어, 펌웨어, 하이브리드 중 해당 유형
- 소프트웨어 암호모듈의 경우: 동적 라이브러리(.dll/.so/.dylib) 형태 명시
- 유형 선택 근거도 서술 필요

**DOC-002 (AS02.07): 암호모듈 경계 명세**
- 암호경계(Cryptographic Boundary) 내 모든 구성요소 명세 필수
- 구현물 경계와 암호 경계를 구분하여 서술
- 구성요소 다이어그램 첨부 권고

**DOC-003 (AS02.09): 검증대상 암호알고리즘 및 CSP 명세**
- 경계 내 검증대상 암호알고리즘 목록 필수 (LEA, ARIA, SEED, HIGHT 등)
- 각 알고리즘에 연관된 핵심보안매개변수(CSP: Critical Security Parameter) 명세
- CSP 예시: 비밀키, 라운드키, IV, 난수 시드, 세션키
- CSP 생명주기(생성 → 사용 → 소멸/제로화) 서술 필요

**DOC-004 (AS02.11): 암호모듈 명칭 및 버전 정보**
- 정식 명칭(국/영문)과 버전 번호 필수
- 내부 구성요소별 버전도 포함

**DOC-005 (AS02.16): 소프트웨어 운영환경 명세**
- 지원 운영체제 목록 (Windows, Linux, macOS 등)
- 지원 CPU 아키텍처 (x86-64, ARM64 등)
- 컴파일러 및 빌드 환경 명세

**DOC-006 (AS02.19): 검증대상 동작모드 실행 방법**
- 검증대상 동작모드 목록 (예: 일반 동작 모드, FIPS 모드)
- 각 모드 진입/전환 방법

**DOC-010 (AS03.xx): 승인된 보안서비스 목록**
- 승인된 암호 서비스 목록 (암호화, 복호화, 해시, MAC, 키생성, 난수생성 등)
- 각 서비스 제공 API 함수명 및 파라미터

**DOC-012 (AS03.05): 데이터 입출력 명세**
- 각 서비스의 입력 데이터: 유형, 크기, 형식
- 각 서비스의 출력 데이터: 유형, 크기, 형식

**DOC-022 (AS09.29): 제로화(Zeroization) 서비스 API**
- 제로화 수행 API 함수명 필수 명시
- 제로화 대상 CSP 목록 (비밀키, 라운드키 등)
- 제로화 방법: 0으로 덮어쓰기, 특수 패턴 등

**DOC-030 (AS06.01): 암호 담당자 역할 정의**
- Crypto Officer(암호 담당자) 역할 및 권한
- User(사용자) 역할 및 권한

**DOC-040 (AS09.29): 운영 상황별 제로화 방법**
- 정상 종료 시 제로화 절차
- 비정상 종료(오류, 전원 차단) 시 제로화 처리 명세

**DOC-045 (AS08.01): 전원 투입 자가시험 명세**
- 전원 투입 시 수행되는 Known Answer Test(KAT) 목록
- 자가시험 실패 시 처리 방법

**DOC-048 (AS02.25): 유한상태모델(FSM) 명세**
- 암호모듈의 전체 상태 다이어그램 필수
- 각 상태: 전원 투입, 자가시험, 일반 동작, 오류, 제로화 등
- 상태 전이 조건 및 동작 명세

## 위반 패턴

설계서에서 자주 발생하는 위반 유형:
- CSP(핵심보안매개변수) 목록 없이 알고리즘만 나열
- 제로화 API 이름 명시 없이 "제로화 수행" 만 기술
- FSM(유한상태모델) 다이어그램 누락, 텍스트만으로 대체
- 운영환경을 "Windows 10" 만 기재, CPU 아키텍처 누락
- 서비스별 입출력 크기/형식 미명시

## 올바른 구현

올바른 설계서 예시 — CSP 명세 테이블:

| CSP 이름 | 유형 | 크기 | 접근 역할 | 생성 방법 | 소멸 방법 |
|---------|-----|-----|---------|---------|---------|
| 비밀키(K) | 비밀 | 128/192/256 비트 | CO | DRBG | lea_zeroize() |
| 라운드키(RK) | 비밀 | 알고리즘별 | 없음 | 키 스케줄 | lea_zeroize() |
| IV | 비밀 | 128 비트 | CO | CSPRNG | 사용 후 즉시 |

올바른 FSM 기술 예시:
- 상태: POWER_ON → SELF_TEST → OPERATIONAL / ERROR
- 전이 조건: SELF_TEST 통과 시 OPERATIONAL, 실패 시 ERROR
- ERROR 상태에서는 암호 서비스 불가, 제로화 수행 후 POWER_ON으로만 복귀
