# KCMVP 테스트 문서 AI 작성 가이드

> 이 문서는 **AI에게 KCMVP 테스트용 문서를 작성시킬 때 전달하는 프롬프트 가이드**입니다.
> 아래 형식을 그대로 AI에게 붙여넣어 사용하세요.

---

## 사용 방법

1. **"[공통 배경 설명]"** 섹션을 항상 포함시킵니다.
2. 작성할 문서 종류에 따라 **"[설계서 작성 요청]", "[시험서 작성 요청]", "[형상관리 문서 작성 요청]"** 중 해당 섹션을 붙입니다.
3. **"[의도적 위반 설정]"** 섹션에서 어떤 규칙을 누락/위반할지 지정합니다.
4. **"[출력 형식 요구사항]"** 섹션을 항상 마지막에 붙입니다.

### [공통 배경 설명] — 항상 포함

```
당신은 KCMVP(한국 암호모듈 검증 프로그램) 사전 검증 도구의 정확도를 평가하기 위한
테스트용 문서를 작성하는 전문가입니다.

이 프로젝트는 암호 모듈 소스코드와 설계 문서가 KCMVP 인증 기준에 맞는지
자동으로 검증하는 AI 기반 도구입니다. 검증 기준은 아래 규칙 체계를 따릅니다.

■ 검증 대상 암호 모듈 스펙
  - 암호 알고리즘: LEA (경량 블록 암호)
  - 보안 레벨: 1
  - 운영 모드: [여기에 원하는 모드 입력 — 예: CBC, CTR, GCM, CCM, CMAC, ECB 중 선택]
  - 모듈 유형: 소프트웨어
  - 구현 언어: C

■ 문서 작성 원칙
  - 섹션 번호는 반드시 "1.", "1.1", "1.1.1" 형식으로 계층 구조를 갖출 것
  - 섹션 제목은 한국어로 명확하게 작성할 것
  - 표(Table)는 헤더와 데이터 행을 모두 포함하여 작성할 것
  - 본문은 실제 KCMVP 제출물처럼 구체적이고 기술적으로 작성할 것

■ 주석 표기 규칙 (필수 — 절대 생략 금지)
  - 정상적으로 작성된 섹션의 제목 옆 또는 아래 첫 줄에:
    <!-- [정상] DOC-XXX 충족 -->
  - 의도적으로 위반/누락된 섹션의 제목 옆 또는 해당 위치에:
    <!-- [위반] DOC-XXX: (위반 내용 한 줄 설명) -->
  - 주석은 반드시 HTML 주석 형식(<!-- -->)으로 작성할 것
  - 문서 내 모든 DOC 규칙 번호에 대해 빠짐없이 주석 처리할 것
```

## 규칙별 탐지 메커니즘 요약 (AI 작성 참고용)

| 탐지 방식 | 동작 원리 | 주요 규칙 |
|-----------|-----------|-----------|
| **missing** | 문서 전체 텍스트에서 특정 키워드 패턴이 없으면 즉시 위반 확정 | DOC-001, 007, 009, 010, 014, 016, 017, 019~022, 029, 040, 044, 045, 047, 048, 050, 053 |
| **semantic** | 키워드 패턴 미존재 시 AI(Gemini)가 문맥을 보고 최종 판정 | DOC-002~006, 008, 011~013, 015, 018, 023~028, 030~039, 041~043, 046, 049, 051~052, 054~055 |

> **실전 팁**: `missing` 규칙은 해당 키워드를 문서에서 완전히 제거해야 탐지됩니다.
> `semantic` 규칙은 AI가 문맥을 보므로, 키워드가 없어도 의미적으로 충족하면 탐지 안 될 수 있습니다.
> 따라서 `semantic` 위반을 유발하려면 **해당 주제 자체를 다루지 않아야** 합니다.
